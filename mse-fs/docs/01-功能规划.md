# 01 功能规划 —— 能力模块与功能点

> mse-fs 功能总纲。配套文档：[02-权限规划](02-权限规划.md)（每个功能点的权限码）、[03-角色规划](03-角色规划.md)（谁能用）。
> 标记说明：「使用者」取建议角色口径（工程未种角色，见 03 册）——**租户用户** = 日常上传下载的业务人员；**文件管理员** = 租户侧存储管理；**平台运维** = 存储/迁移/后端治理。
> 工程主 README 为功能权威描述，本册按产品视角重组，语义一致。

## 一、模块总览

| # | 模块 | 页面/入口（menu_id） | 一句话定位 |
| --- | --- | --- | --- |
| 1 | 统一存储抽象与双实现 | 后端能力（无页面） | `FileStorage` 一套接口，local 缺省 / rustfs 按配置互斥装配，可整体替换 |
| 2 | 文件管理 | 文件管理（471） | 上传、秒传、检索、下载、缩略图、直链、分片直传、删除——最终用户主页面 |
| 3 | 公开素材通道 | 免登录端点 | `/fs/asset/{tenantId}/{fileId}.{后缀}`：登录页 Logo / 品牌素材等匿名可读场景专用 |
| 4 | 存储迁移运维 | 文件管理（471）内按钮 | 历史对象在 local ↔ rustfs 间一键搬移，切换存储模式不丢旧文件 |
| 5 | RPC 契约 | 框架区 api-fs | `RemoteFileService` 四方法，业务服务 `@RpcReference` 即用，形态无关 |
| 6 | 开放 API（mse-open） | 开放平台目录 | 四条文件能力自注册开放，第三方经 `/open/api/fs/**` 受控调用 |
| 7 | 业务接入标准 | 本册第九节（附则） | 「mse-fs 优先、无 mse-fs 自动降级本地」的模块接入范式与样板 |

**核心链路**：

```
上传（页面/业务模块/开放API）
  → MD5 秒传判定（同租户同 MD5 同大小 → 复用物理对象，新元数据行指向同一键）
  → 物理对象落 {tenantId}/{yyyyMM}/{fileId}.{ext}（local 目录或 rustfs 桶内）
  → 元数据 fs_file 落库（行级租户隔离，记录 storage_type / access_level / biz 归属）
下载（页面下载 / 代理流式 / 预签名直链 / 公开素材匿名读 / RPC base64）
删除（逻辑删元数据 + 尽力删物理对象；秒传共享对象仍有引用时保留）
```

## 二、统一存储抽象与双实现（后端能力）

### 2.1 FileStorage 接口

| 功能点 | 说明 |
| --- | --- |
| 统一抽象 | `FileStorage` 接口：store / open / delete / presign（+ 分片直传 init/complete/abort），上层 Service 与 Controller 对实现零感知 |
| 存储键规范 | `{tenantId}/{yyyyMM}/{fileId}.{ext}`——首段恒为租户 ID（物理层租户隔离），fileId 即元数据雪花主键（物理对象同名） |
| 双实现互斥装配 | `mse.fs.storage.type=local`（缺省，`matchIfMissing=true`）装配 `LocalFileStorage`；`=rustfs` 且 classpath 有 AWS SDK 时装配 `RustFsFileStorage`——两侧条件互斥，恒只有一个实现 |
| 缺 SDK 护栏 | `type=rustfs` 但 classpath 缺 `software.amazon.awssdk:s3` 时**启动即失败**，报错给出明确修复指引（避免拖到首次上传才报错） |
| 可整体替换 | 三个装配分支均带 `@ConditionalOnMissingBean(FileStorage.class)`——声明同类型 Bean（如自研 OSS 实现）即整体替换，全程不改积木代码 |
| 依赖语义 | fs-service 的 S3 SDK 为 `<optional>`（嵌入方只引 fs-service 自动纯本地）；fs-boot 显式引入 SDK（微服务部署两模式可经 Nacos 随时切换，无需重打包） |

### 2.2 两种后端

| 后端 | 取值 | 说明 |
| --- | --- | --- |
| 本地文件系统 | `local`（缺省） | 目录 `{baseDir}/{tenantId}/{yyyyMM}/{fileId}.{ext}`，零外部依赖；生产挂载持久卷 |
| RustFS 1.x 对象存储 | `rustfs` | 经 AWS SDK v2 走 S3 兼容协议（同样适用于 MinIO 等）；桶 `mse-fs` 启动自动创建，桶内按 `{tenantId}/` 前缀隔离；path-style 寻址 |

## 三、文件管理（页面 471，最终用户主页面）

| 功能点 | 权限点 | 说明 | 使用者 |
| --- | --- | --- | --- |
| 文件上传 | `fs:file:upload` | multipart 上传（默认单文件上限 100MB 可配），可选携带业务分类 bizType / 业务关联 bizId | 租户用户 |
| MD5 秒传 | 随上传 | 服务端流式计算内容 MD5（`fs_file.content_md5`），同租户同 MD5 同大小直接复用已有物理对象（新元数据行指向同一键）；删除按引用计数保留共享对象 | 租户用户 |
| 大文件分片直传 | `fs:file:upload` | 仅 rustfs 模式：init 一次签发全部分片 PUT URL（8MB 起、≤1000 片自动放大）→ 浏览器并发直传对象存储 → complete 凭 ETag 组装 / abort 放弃清理；进行中元数据行 `upload_id` 非空，列表显示「直传中」 | 租户用户 |
| 文件检索 | `fs:file:list` | 分页列表：文件名模糊、业务分类、上传时间范围；列展示文件名（图片带缩略图）/ 大小 / MIME 类型 / 业务分类 / 存储后端 / 上传时间 | 租户用户 |
| 存储信息 | `fs:file:list` | 当前存储模式 / 预签名是否可用 / 分片直传是否可用——页面顶部标签与按钮显隐的数据来源 | 租户用户 |
| 代理下载 | `fs:file:download` | 服务端流式透传（先经元数据校验，租户插件过滤，跨租户 fileId 直接 404），保留鉴权与审计 | 租户用户 |
| 图片缩略图 | `fs:file:download` | `GET /fs/file/{id}/thumbnail?width=`：JDK ImageIO 惰性生成（jpeg 白底 / png 保透明），产物按 `{storageKey}.th{width}` 派生键缓存（档位 128/256/512），永久强缓存；svg/webp 与 >20MB 源图返回 400，前端降级纯文件名 | 租户用户 |
| 预签名直链 | `fs:file:download` | 仅 rustfs 模式且 `presign.enabled=true`：按单键限时签发（默认 3600 秒），复制后供外部直接下载，减轻服务流量；默认关闭，下载统一走服务端代理 | 租户用户 |
| 文件删除 | `fs:file:delete` | 逻辑删元数据 + 尽力删物理对象（物理删除失败仅告警不阻塞）；秒传共享对象仍有引用时保留 | 租户用户 / 文件管理员 |

**安全模型**：文件端点全部 `@SaCheckPermission`（租户端登录会话）；下载 / 预签名 / 缩略图先经元数据校验（租户插件过滤）；预签名与分片直传 URL 按对象 key 限时签发，泄露面限于单文件且默认关闭。

## 四、公开素材通道（免登录）

| 功能点 | 说明 |
| --- | --- |
| 上传时声明公开 | 上传请求携带 `accessLevel=public`（默认 `tenant` 租户私有）——该行即可经免登录端点匿名读取 |
| 免登录读取端点 | `GET /fs/asset/{tenantId}/{fileId}.{后缀}`：无注解即匿名可达；inline + 永久强缓存 + nosniff/CSP 响应头；尾段后缀仅可读性（无后缀同语义） |
| URL 规范拼法 | `FsAssetUrls.publicAssetUrl(tenantId, fileId, fileName)`（框架区 api-fs，唯一合法拼法，格式变更只改此处）；首段租户号即素材所属世界（**0=平台世界**，其余为租户编号） |
| 寻址语义 | 服务端按首段租户号做语句级路由（runAs），精确复用上传时的落库决策（平台世界落平台库 / 租户世界落共享主库或租户独立库）；**租户段与行 tenant_id 不符即 404**；非 public 行与不存在同语义 404（不泄露存在性） |
| 网关放行 | `mse.gateway.ignore-urls` 已放行 `/fs/asset/**`；前端经 /api 代理加载 |
| 适用场景 | 登录页 Logo / 背景图、租户品牌个性化素材、免登录页面图片等 img 标签带不了 token 的场景；oa 附件 / 用户头像 / ai 知识库等登录态场景不走此通道 |

## 五、租户双层隔离与平台世界

| 层 | 机制 | 说明 |
| --- | --- | --- |
| 元数据层 | `fs_file.tenant_id` 行级隔离 | 继承 BaseEntity，租户插件自动填充/改写；跨租户 fileId 直接 404 |
| 物理层 | 存储键首段恒为租户 ID | 本地目录 `{baseDir}/{tenantId}/` 与桶内对象 `{tenantId}/` 前缀互不可见 |
| 平台世界 | tenant_id=0 | 平台会话（平台头像 /platform/avatar、域名个性化素材等）的全部 fs_file 语句经路由拦截器落平台库（双库形态）；平台库自持 fs_file 副本脚本（`V20261001_03`，mse-base-scope: platform） |
| 独立租户库 | 随租户库路由 | 共享主库与各独立租户库各持 fs_file 表（master 通道脚本随租户库克隆/懒初始化就绪） |
| 公开素材 | 首段租户号路由 | 免登录端点按 URL 租户段定位素材所属世界寻址（见第四节） |

## 六、存储迁移运维（local ↔ rustfs）

| 功能点 | 权限点 | 说明 |
| --- | --- | --- |
| 迁移历史文件 | `fs:storage:migrate` | `POST /fs/storage/migrate?from=local\|rustfs`：把源存储的历史对象按原键搬移到**当前装配**的存储实现并改写 `storage_type`；游标分页逐条容错，返回成功/失败/跳过统计 |
| 会话范围收口 | 同上（双端） | `@SaCheckOr` 租户端 + 平台端两类会话均可持该权限码：**租户会话仅迁移本租户文件，平台会话全库迁移**（迁移是全局运维动作，不留给租户会话跨租户触发） |
| 边界 | — | 同步执行，文件量大建议低峰操作；分片进行中的行（upload_id 非空）不参与迁移；切换存储模式后历史文件仍按原 `storage_type` 寻址，迁移后统一 |

## 七、RPC 契约（框架区 api-fs）

契约放 `mse-framework/mse-api/api-fs`（接口 + Serializable DTO，跨服务唯一合法依赖），本工程为实现方：

| 契约方法 | 说明 |
| --- | --- |
| `uploadFile(requestJson)` | FileUploadRequest（fileName / contentBase64 必填，bizType / bizId / accessLevel 可选）→ FileMetaResult；同租户同 MD5 秒传复用对象 |
| `getFileMeta(requestJson)` | 按 fileId 查元数据；跨租户 fileId 查不到抛 404 语义错误 |
| `downloadFile(requestJson)` | 返回 contentBase64（base64 膨胀约 1.33 倍，适合 ≤20MB 小文件；更大走 HTTP 端点） |
| `deleteFile(requestJson)` | 逻辑删元数据 + 尽力删物理对象 |

调用语义：消费方 `@RpcReference` 注入即用——单体 local 模式本地直调、微服务 dubbo 模式远程调用，消费方零改动；租户上下文经 RPC 隐式透传（文件归属租户 = 调用方上下文租户）；DTO 日期字段以 `@JsonFormat` 钉死载荷格式（`yyyy-MM-dd HH:mm:ss`），消费端无需自行适配。实现类 `@RpcService` 由装配类 `@Bean + @ConditionalOnMissingBean(RemoteFileService.class)` 注册，可整体替换。

## 八、开放 API（mse-open 自注册）

`FsOpenApiContributor` 声明四条描述，应用就绪后由 open-api 推送器自动推送 mse-open 目录（幂等 upsert + 周期重推自愈），**零 SQL 种子**；mse-open 按目录 target 泛化分发，不依赖本工程 jar：

| code | 名称 | 方法与路径 | 说明 |
| --- | --- | --- | --- |
| `open:fs:file-upload` | 上传文件 | POST `/open/api/fs/file/upload` | body 含 fileName/contentType/contentBase64（必填）、bizType/bizId/accessLevel（可选）；开放场景带 accessLevel=public 可匿名读 |
| `open:fs:file-get` | 查询文件元数据 | GET `/open/api/fs/file/{fileId}` | 跨租户 fileId 不可见（404 语义） |
| `open:fs:file-download` | 下载文件内容 | POST `/open/api/fs/file/{fileId}/download` | 返回 contentBase64（小文件场景；大文件走服务代理下载端点） |
| `open:fs:file-delete` | 删除文件 | DELETE `/open/api/fs/file/{fileId}` | 逻辑删元数据并尽力删物理对象 |

管理端「API 目录」可启停（即时生效）；RPC 契约 base64 适合小文件（建议 < 5MB）。

## 九、附则：业务文件存储接入标准（mse-fs 优先、无 mse-fs 自动降级本地）

业务模块需要文件存储时**不要自造落盘逻辑**，按以下模式接入。现成样板：oa-form `OaFileStorage`（附件）、service-platform `DomainAssetStorage`（品牌素材）、service-system `AvatarStorage`（用户头像，公开素材通道优先）、ai-service `KbStorageService`（知识库归档 `fs:{fileId}` 串）。

### 9.1 接入五步

1. **依赖**：模块引框架契约 `api-fs`（BOM 仲裁版本，仅接口 + DTO，无实现依赖）；
2. **存储契约接口化**：模块内定义自己的存储接口（如 `OaFileStorage`），先实现本地磁盘兜底版；
3. **条件装配（自动降级语义）**：自动装配类标 `@AutoConfiguration(afterName = "vip.mseapp.fs.autoconfigure.FsServiceAutoConfiguration")`，内放**两个嵌套配置，两侧条件必须互斥**——
   - Fs 实现 Bean：`@Conditional(FsAvailableCondition.class)` + `@ConditionalOnMissingBean(存储接口)`，内部 `@RpcReference(dubbo = @RpcReference.Dubbo(timeout = 60000))` 注入 `RemoteFileService`（条件语义：classpath 有契约 且（dubbo 模式 或 local 模式容器已有契约实现）；模块显式开关可强制 `local`）；
   - Local 实现 Bean：`@Conditional(FsUnavailableCondition.class)`（上一条件取反）+ `@ConditionalOnMissingBean(存储接口)`；
   - **勿依赖嵌套类声明顺序兜底**：javac 编译 InnerClasses 顺序不保序，Local 若只写 `@ConditionalOnMissingBean` 而先注册，Fs 会整体让位、文件静默落本地磁盘。
4. **元数据约定**：业务侧行留存自己的元数据并记录 `fsFileId`（或 `fs:{fileId}` 归档串）；历史本地行下载时按行分流，切换存储模式后旧文件不丢；
5. **公开素材规范拼法**：需要免登录 URL 的场景（登录页素材等），上传时声明 `accessLevel=public`，URL 一律用 `FsAssetUrls.publicAssetUrl(tenantId, fileId, fileName)` 构造（`/fs/asset/{tenantId}/{fileId}.{后缀}`），禁止手拼。

### 9.2 降级语义与显式开关

- **引入/部署 mse-fs 即统一存储，未引入自动回落本地磁盘**——Maven 与配置两层同时成立（不引 fs-service 时无 FsAvailableCondition 成立的前提）；
- 已接入模块的显式开关（默认 `auto`，取值 `auto|fs|local`）：`mse.oa.storage-mode`（oa 附件）/ `mse.tenant.branding-storage`（品牌素材）/ `mse.ai.kb.storage-mode`（知识库归档）/ `mse.system.avatar-storage`（用户头像）；
- **RPC 边界**：base64 内容适合小文件（≤20MB，dubbo payload 已提至 32MB）；更大文件走 mse-fs HTTP 端点或分片直传。

## 十、演进路线（规划，未落地）

| 方向 | 说明 |

| 分片断点续传 | 前端持久化已传分片 ETag，续传时仅补传缺失片；分片直传进度秒级回写（当前一次性签发全部分片 URL，失败即 abort 重传） |
