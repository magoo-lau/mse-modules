# 05 配置手册（零基础版）—— 从零把文件存储服务跑起来

> **这本手册是给谁的**：没接触过本系统、甚至没怎么接触过服务器软件的同事——实施工程师、现场 IT、接手部署的新人。你不需要看懂代码，照着做、每步核对「✅ 成功的标志」即可。
> 配套文档：跑起来之后怎么用，看 [04-操作说明书](04-操作说明书/README.md)；功能与架构细节，看工程 [README](../README.md) 与 [docs/01-功能规划](01-功能规划.md)。

## 一、先认识几个名词（2 分钟）

| 名词 | 是什么 | 打个比方 |
| --- | --- | --- |
| **Docker** | 容器软件，把 MySQL 等软件"打包"成一键安装 | 免安装的"绿色软件"运行器 |
| **MySQL** | 数据库，文件清单（元数据）存在这里 | 大仓库的账本 |
| **Redis** | 缓存，存登录会话等临时数据 | 门卫的登记本 |
| **JDK 21** | Java 运行环境，后端 jar 包需要它 | 播放器（jar 是影碟） |
| **Maven** | Java 的打包工具，把源码编译成 jar | 印刷厂 |
| **Node.js** | 前端页面的构建运行环境 | 网页的发动机 |
| **Nacos** | 微服务模式下的"配置中心 + 通讯录" | 公司前台（单体模式用不到） |
| **对象存储 / RustFS** | 专门存文件的服务，容量大、可扩展（S3 兼容协议，MinIO 同类） | 立体仓库（本地磁盘=平房库房） |
| **桶（bucket）** | 对象存储里的"顶层文件夹"，mse-fs 自动创建，名叫 `mse-fs` | 仓库里划出的专属库区 |
| **预签名直链** | 带时效的文件直接下载地址 | 限时通行证 |
| **微服务** | mse-fs 的标准形态：独立进程，经网关接入 | 专营门店 |

> **存储模式二选一**：不装 RustFS 就用本地磁盘（零依赖，开箱即用）；生产建议 RustFS（容量弹性 + 大文件直传）。随时可切换，历史文件一键迁移不丢。

## 二、你需要准备什么

| 项 | 要求 | 说明 |
| --- | --- | --- |
| 服务器/电脑 | 2 核 4G 起步（启用 RustFS 建议 4 核 8G），硬盘按文件量预估 ≥40G | Windows / Linux 均可 |
| 软件 | Docker（推荐）或：JDK 21 + MySQL 8 + Redis + Nacos + Maven 3.9+ + Node.js 20+ | 路线 A 只需 Docker |
| 软件包 | 本仓库源码（git clone 或拿到压缩包） | jar 也可以直接找开发要成品 |
| 基座就绪 | **前置**：框架区已构建（仓库根 `mvn install -DskipTests`）、基座平台可登录（MySQL/Redis/Nacos 已起，网关已起） | mse-fs 依赖基座的登录/租户/菜单能力 |

## 三、路线 A：容器部署（推荐，约 30 分钟）

### 第 1 步：安装 Docker

- Windows：安装 Docker Desktop 并启动；Linux：安装 docker + docker compose 插件。
- ✅ 成功标志：命令行执行 `docker --version` 能输出版本号。

### 第 2 步：确认基座中间件已起

进入仓库 `mse-framework/docker` 目录，确认 `docker ps` 里有 `mse-mysql`、`mse-redis`（以及微服务形态的 Nacos）：

```bash
docker compose up -d mysql redis nacos
```

- ✅ 成功标志：三个容器状态 Up；Nacos 控制台 `http://localhost:18080` 能打开。
- 说明：基座平台的建库建表由基座自己完成，**不用你手工执行任何 SQL**。

### 第 3 步：（可选）启动 RustFS 对象存储

不装就跳过本步（自动走本地磁盘模式）。在本工程 `mse-modules/mse-fs` 目录执行：

```bash
docker compose -f docker/rustfs/compose.yaml up -d
```

- ✅ 成功标志：`docker ps` 出现 `mse-rustfs`；浏览器打开控制台 `http://localhost:9001`，用 rustfsadmin/rustfsadmin 能登录。
- **生产必须改凭据**：用环境变量 `RUSTFS_ACCESS_KEY` / `RUSTFS_SECRET_KEY` 覆盖默认值（与第 4 步的服务配置保持一致）；并建议把镜像钉住确定的 1.x 版本 tag。

### 第 4 步：把 mse-fs 专属配置导入 Nacos

在本工程 `mse-modules/mse-fs` 目录执行：

```bash
CONFIG_DIR="$PWD/docker/nacos/config" sh ../../mse-framework/docker/nacos/init-configs.sh
```

- ✅ 成功标志：Nacos 控制台「配置管理 → 配置列表」出现 Data ID `mse-fs.yaml`。
- 想用 RustFS：此时顺手在 Nacos 控制台编辑 `mse-fs.yaml`，把 `mse.fs.storage.type` 改为 `rustfs`（本地模式则保持 `local` 不动）。

### 第 5 步：构建并启动 mse-fs 服务

```bash
# 构建本工程（基座未构建时先在仓库根 mvn install -DskipTests）
mvn install -DskipTests
java -jar fs-boot/target/fs-boot-1.0.0-SNAPSHOT.jar
```

- ✅ 成功标志：日志出现 `Started FsBootApplication in xx seconds`；`fs_file` 业务表自动建好（首次启动自动迁移，失败会阻断启动并给原因）。
- 端口 8095；Nacos 地址默认 localhost:8848（环境变量 `MSE_NACOS_ADDR` 可改）。

### 第 6 步：启动前端子应用

```bash
cd mse-modules/mse-fs/fs-ui
npm install
npm run dev
```

- ✅ 成功标志：`http://localhost:3900` 有响应（独立调试地址）。子应用注册（`//localhost:3900`）已随服务自动写入基座，无需手工登记。
- 正式部署：`npm run build`，产物按 `/sub-apps/fs/` 路径发布到静态服务器（构建已内置该前缀）。

### 第 7 步：给租户"点亮"文件存储（关键！）

1. 用**平台账号**登录基座门户 →「**套餐管理**」→ 编辑租户所用套餐 → 勾选「**文件存储**」分组下的「文件管理」页面 → 保存。
2. ✅ 成功标志：用**租户管理员**重新登录后，左侧出现「文件存储 → 文件管理」。
3. 原理：页面菜单默认"封存"，套餐勾选是租户可见的总开关。

### 第 8 步：初始化角色（按需）

mse-fs **没有预置角色**（能力面小）。租户管理员在「组织管理 → 角色管理」按需自建（建议编码与授权见 [03-角色规划](03-角色规划.md) 第二节）：

- `fs_user` 文件用户：勾「文件查询 / 文件上传 / 文件下载」；
- `fs_admin` 文件管理员：五个权限点全勾（含删除与存储迁移）。

把角色授予用户；租户超管不建角色也能用全部能力。

### 第 9 步：验收主流程

登录租户账号 → 文件管理页：上传一个文件 → 列表出现且可下载 → 删除后消失。本地模式看服务器工作目录出现 `fs-files/{租户号}/...` 文件；RustFS 模式在控制台桶 `mse-fs` 内看到 `{租户号}/` 前缀对象。走通即部署成功。

## 四、两种存储模式配置速查

> 配置在 Nacos 的 `mse-fs.yaml`（本工程 `docker/nacos/config/mse-fs.yaml` 留档），全部支持同名环境变量覆盖。**修改后重启 mse-fs 服务生效**。

| 想改什么 | 配置项（环境变量） | 默认值 | 说明 |
| --- | --- | --- | --- |
| 存储模式 | `mse.fs.storage.type`（`MSE_FS_STORAGE_TYPE`） | `local` | `local` 本地磁盘 / `rustfs` 对象存储 |
| 本地存储目录 | `mse.fs.storage.local.base-dir`（`MSE_FS_BASE_DIR`） | `./fs-files` | **生产挂载持久卷**；按 `{租户号}/` 分目录 |
| RustFS 端点 | `mse.fs.storage.rustfs.endpoint`（`MSE_FS_ENDPOINT`） | `http://localhost:9000` | 对应 compose 的 9000 端口 |
| 访问密钥/私有密钥 | `...rustfs.access-key / secret-key`（`MSE_FS_ACCESS_KEY / MSE_FS_SECRET_KEY`） | `rustfsadmin` | 与 RUSTFS_ACCESS_KEY/SECRET_KEY 一致，**生产必须改** |
| 桶名 | `mse.fs.storage.rustfs.bucket`（`MSE_FS_BUCKET`） | `mse-fs` | 不存在时启动自动创建 |
| 预签名直链 | `mse.fs.storage.presign.enabled`（`MSE_FS_PRESIGN_ENABLED`） | `false` | 开启后页面出现「直链」按钮（仅 rustfs 模式） |
| 直链有效期 | `mse.fs.storage.presign.ttl-seconds`（`MSE_FS_PRESIGN_TTL`） | `3600` 秒 | 分片直传的 PUT URL 有效期同源（不看开关，下限 300 秒） |
| 上传大小上限 | `spring.servlet.multipart.max-file-size`（`MSE_FS_MAX_FILE_SIZE`） | `100MB` | 普通上传上限；更大走分片直传 |
| Nacos 地址 | `MSE_NACOS_ADDR` | `localhost:8848` | 多机部署改实际地址 |

> 寻址细节无需关心但别改错：`region` 固定 `us-east-1`、`path-style-access` 固定 `true`（RustFS/MinIO 类单机部署必须）。

## 五、Nacos 配置要点

1. **专属配置只有一份**：`mse-fs.yaml`（端口 8095、存储、预签名、上传上限都在这）；数据源/Redis/Sa-Token/Dubbo 等共享项在 `mse-micro-common.yaml` / `mse-micro-db-biz.yaml` / `mse-micro-dubbo.yaml`，由基座统一维护，不要在专属配置里重复。
2. **生效优先级**：环境变量 > Nacos 配置——容器部署用环境变量注入差异项（如存储模式、密钥）最省事。
3. **改完重启**：存储模式与存储参数在启动时读取，改完 Nacos 需重启 mse-fs 进程。
4. **Seata**：默认关停（配置已显式关闭数据源代理），文件服务无跨库全局事务需求，保持默认即可。

## 六、单体形态（更简单的跑法）

不做微服务时，把 `fs-service` 引入聚合单体（`mse-sample/mse-monolith` **已引入**，本地存储模式）：基座单体起来即带文件能力（RPC 本地直调），无独立进程、不占 8095 端口。注意：

- 单体只引 `fs-service` 时 classpath 无对象存储 SDK，**只能本地模式**（想用 RustFS 需在单体补 S3 依赖或改用微服务形态）；
- 前端照常经基座门户访问「文件存储」菜单。

## 七、业务模块接入（给开发的一句话）

业务模块要存文件时**不自建落盘逻辑**：引框架契约 `api-fs` + 双嵌套互斥条件装配——部署了 mse-fs 就统一存储，没部署自动回落本地磁盘，oa 附件 / 用户头像 / 品牌素材 / 知识库四个现成样板。完整五步与红线见 [01-功能规划](01-功能规划.md) 第九节附则。

## 八、微服务进阶

1. **网关路由**：确认 `mse-gateway.yaml` 里有 `/fs/** → lb://mse-fs`（已留档）；免登录白名单含 `/fs/asset/**`（公开素材，已留档；自行收紧白名单时勿删）。
2. **信创数据库**：启动加 `--spring.profiles.active=dm` 或 `kingbase`，数据源与方言由共享配置 profile 提供，专属配置无需重复。
3. **多实例**：脚本自动迁移带 Redis 锁按库互斥，多实例直接横向启动即可；本地模式的多实例**必须共享同一存储卷**（否则 A 实例上传 B 实例下载不到）。

## 九、常见问题排查（按现象查）

| 现象 | 先检查什么 |
| --- | --- |
| 启动失败，日志报数据库连接错误 | MySQL 没起/地址密码错——`docker ps` 看容器；数据源在共享 Nacos 配置里改 |
| 启动失败并报「classpath 缺少对象存储客户端 SDK」 | 配置了 `type=rustfs` 但部署包没带 S3 依赖——用标准 fs-boot 部署包，或临时改回 `local` |
| 启动失败报「脚本执行失败」并退出 | 数据库迁移是启动强校验：按日志提示修复后重启，不要跳过 |
| 启动连不上 Nacos | Nacos 没起或地址不对（`MSE_NACOS_ADDR`）；控制台 `http://localhost:18080` |
| 登录后左侧没有「文件存储」菜单 | 套餐没勾选（第 7 步），或该用户角色没授权 |
| 菜单在但页面空白/404 | fs-ui 没启动（dev 3900）或子应用地址不对；生产部署核对 `/sub-apps/fs/` 前缀 |
| 看得到菜单但上传报 403 | 该角色没授「文件上传」权限（第 8 步） |
| 上传成功但下载 404 | 多实例+本地模式未共享存储卷（第八节第 3 条）；或文件所在后端与当前模式不符（先「迁移历史文件」） |
| 「大文件直传」报「未读到分片 ETag」 | RustFS 侧 CORS 未放行门户来源/未暴露 ETag 头——按部署留档开启跨域配置 |
| RustFS 控制台登不进 | 凭据被环境变量覆盖过：用部署时注入的 RUSTFS_ACCESS_KEY/SECRET_KEY |
| 公开素材（登录页图片）打不开 | 网关免登录白名单缺 `/fs/asset/**`；或素材不是公开级别 |
| 切了存储模式后旧文件下载 404 | 旧文件在原后端且原后端不可达——恢复原后端可达后执行「迁移历史文件」 |
| 界面/数据库中文乱码 | 建库与连接必须 utf8mb4（脚本已内置；自建库时确认字符集） |

## 十、上线前检查清单

- [ ] RustFS（如启用）已改默认凭据，且与 mse-fs 配置两侧一致
- [ ] 本地模式：存储目录已挂载持久卷（非容器临时层）；多实例共享同一卷
- [ ] 数据库与对象存储数据卷均已纳入每日备份（元数据在库、内容在存储，两份都要）
- [ ] 上传大小上限按业务复核（默认 100MB）；预签名直链默认关闭，如开启确认时效可接受
- [ ] 网关免登录白名单最小化：仅 `/fs/asset/**`（公开素材通道）
- [ ] 租户套餐已勾选「文件存储」，角色按最小授权发放（删除/迁移只给管理员）
- [ ] 公开素材抽查：登录页 Logo/背景图未登录可加载，非公开文件匿名访问返回不存在
- [ ] 验收主流程走通：上传 → 列表 → 下载 → 删除（第三节第 9 步）
- [ ] 记录本次部署的版本号、存储模式与日期，便于后续切换/升级追查
