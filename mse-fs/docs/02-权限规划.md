# 02 权限规划 —— 子应用注册、页面菜单与权限点

> mse-fs 的菜单与权限点设计。功能点含义见 [01-功能规划](01-功能规划.md)，角色授权见 [03-角色规划](03-角色规划.md)。
> **本文所有 id / 值均为工程实际落库值**，转录自 `fs-service/src/main/resources/db/mysql/V20261001_01_fs__fs_base.sql`（头指令 `-- mse-target: base`），号段登记见 `zcode-plugin/plugins/mse-dev/references/alloc-tables.md`。

## 一、规划原则（基座 RBAC 模型）

1. **三张全局表，一条链路**：`sys_micro_app`（子应用注册）→ `sys_menu`（导航菜单）→ `sys_permission`（权限点）；授权链 `sys_user → sys_user_role → sys_role → sys_role_menu / sys_role_permission`。
2. **sys_menu.type**：1=目录（本工程仅 470 一个分组目录）、3=子应用页面菜单（`micro_name` 关联子应用、`path` 为子应用内部路由）。`menu_scope=2` 租户端（fs 是租户端子应用，side=1）。
3. **权限点必须挂靠页面菜单**：`sys_permission.menu_id` 指向本工程 type=3 页面菜单（全部挂 471），才参与角色授权分组与**租户套餐裁剪**（`sys_tenant_package.menu_ids` 圈定菜单 → 隐含圈定挂靠的权限点）；fs 无 `menu_id=NULL` 的通用权限。
4. **权限码格式**：`fs:<域>:<动作>`，动作小写动词（`fs:file:list` / `fs:storage:migrate`），与仓库 `mes:` / `oa:form:list` 等风格一致；唯一键 `uk_code`。
5. **前端按钮控制**：子应用内用 `v-permission` 指令按权限码显隐按钮（上传 / 直传 / 下载 / 直链 / 删除 / 迁移按钮均按码显隐）。
6. **落库方式**：随 jar 的幂等版本化脚本自动推送 mse-system 应用（分册账本 `mse_fs_schema_history`），**免手工执行、不把 SQL 种子写进框架区**；已应用脚本不再修改，变更一律新增版本文件。
7. **控制器开关**：默认控制器随 `mse.service.fs.controller.enabled`（默认 true）装配，false 时由接入方自有控制器替代——权限码语义不变。

## 三、页面菜单（sys_menu，实际值）

470 为 type=1 分组目录（parent_id=0、path=`/sub/fs`、icon=FolderOpened、sort=26），471 为 type=3 页面菜单（parent_id=470、micro_name=`fs`、menu_scope=2），`path` 为子应用内部路由：

| menu_id | type | 名称 | path（内部路由） | 对应能力 |
| --- | --- | --- | --- | --- |
| 470 | 1 | 文件存储 | `/sub/fs` | 分组目录 |
| 471 | 3 | 文件管理 | `/file` | 上传 / 直传 / 检索 / 下载 / 直链 / 删除 / 存储迁移（fs-ui 唯一页面） |

> 页面内无二级页签菜单——fs-ui 仅一个文件管理页，按钮粒度用权限点控制；存储迁移是同页内的运维按钮（4105），不单独建菜单。

## 五、开放 API 目录码（mse-open，非 sys_permission）

`FsOpenApiContributor` 自注册到 mse-open 目录的四条描述码——**不是** `sys_permission` 权限点，不参与菜单/套餐/角色授权，走开放平台的凭证/授权/限流体系（管理端「API 目录」启停）：

| code | 名称 | 方法与路径 |
| --- | --- | --- |
| `open:fs:file-upload` | 上传文件 | POST `/open/api/fs/file/upload` |
| `open:fs:file-get` | 查询文件元数据 | GET `/open/api/fs/file/{fileId}` |
| `open:fs:file-download` | 下载文件内容 | POST `/open/api/fs/file/{fileId}/download` |
| `open:fs:file-delete` | 删除文件 | DELETE `/open/api/fs/file/{fileId}` |

## 七、套餐裁剪与登记纪律

1. **租户套餐**：fs 页面菜单（471）需在平台端「套餐管理」勾选后才对租户可见；未配置页面菜单的中间状态子应用在侧边栏渲染为单个菜单项。租户管理员拿到的是「套餐域内全量权限码」。
2. **平台侧权限**：4105 的平台会话校验复用同一权限码 `fs:storage:migrate`——平台侧不另建菜单/权限种子，平台角色需要全库迁移能力时在基座平台角色管理中挂载该码（或由平台超管执行）。
3. **alloc-tables.md 登记（已完成）**：后端端口 8095、前端 dev 3900、micro_app id=8、菜单段 470-479（用 470-471）、权限段 41xx（用 4101-4105，基点 4100）、网关前缀 `/fs`。
4. **脚本纪律**：全部幂等写法（子应用按 name 判重、菜单按 id 判重、权限点按 id 判重）；**升级兼容**——早期安装的权限点未挂菜单（menu_id=NULL 按通用权限登录即授予），脚本以条件 UPDATE 幂等补挂到 471。
