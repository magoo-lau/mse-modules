# 01 平台管理员操作手册（存储后端与运维视角）

> 使用者：平台管理员 / 实施运维｜视角：全平台｜定位：负责**存储后端的选型、切换与迁移**，RustFS 对象存储的部署巡检，公开素材（登录页素材 / 品牌素材）的治理。**不负责**租户内日常文件上传下载（那是租户用户的事，见 [02-租户用户](02-租户用户.md)）。
> 部署层面的安装与配置步骤见 [05-配置手册-零基础版](../05-配置手册-零基础版.md)，本手册只讲运行期运维。

## 一、职责与操作入口

| 职责 | 入口 |
| --- | --- |
| 查看当前存储模式、各能力可用状态 | 基座门户 → 文件存储 → 文件管理（页面顶部标签与按钮显隐） |
| 切换存储后端（local ↔ RustFS） | Nacos 控制台 → Data ID `mse-fs.yaml`（见第三节） |
| 历史文件迁移（全库） | 文件管理页 →「迁移历史文件」按钮（平台会话执行即全库范围） |
| RustFS 运行巡检 | RustFS 管理控制台（默认 `http://localhost:9001`） |
| 公开素材治理（登录页素材 / 品牌素材 / 头像） | 各业务模块页面 + 公开素材地址口径（见第五节） |

## 二、认清两种存储模式

文件管理页顶部的存储标签即当前生效模式：

| 模式 | 适用 | 特点 |
| --- | --- | --- |
| **本地文件存储**（缺省） | 试点、小规模、无对象存储运维能力 | 零外部依赖，文件落服务器磁盘（按租户分目录）；受单盘容量与备份能力限制 |
| **RustFS 对象存储** | 生产、文件量大、需要容量弹性 | S3 兼容协议（RustFS 1.x，同样适用于 MinIO 等）；支持大文件分片直传、预签名直链；桶自动创建 |

两种模式**互斥生效**（同一时刻只用一个），但可随时切换——历史文件不会丢，仍按上传当时的后端寻址，用「迁移历史文件」统一搬到新后端。

## 三、切换存储模式（低峰操作）

1. **前置**：确认目标后端已就绪（RustFS 未部署时先用 `docker/rustfs/compose.yaml` 起栈，见 05 册第三节；生产环境务必改默认凭据）。
2. 登录 **Nacos 控制台**（默认 `http://localhost:18080`）→ 配置管理 → `mse-fs.yaml`（Group DEFAULT_GROUP）→ 编辑：
   - 把存储类型改为目标模式：`mse.fs.storage.type` = `rustfs`（切对象存储）或 `local`（切回本地）；
   - 切 rustfs 时核对：端点、访问密钥/私有密钥（与 RustFS 侧一致）、桶名（不存在会自动创建）。
3. **保存后重启 mse-fs 服务生效**（运行期修改不热生效）。
4. ✅ 成功标志：文件管理页顶部标签变为新模式；「大文件直传」按钮出现（rustfs 模式）。
5. 若启动失败并明确提示「classpath 缺少对象存储客户端 SDK」：说明部署包不完整，联系开发补充依赖（微服务标准部署包已内置，勿自行改配置绕过）。

## 四、迁移历史文件（切换后端后必做）

切换存储模式后，**旧文件仍留在原后端**（列表可正常下载，存储列显示原后端标签）。把历史文件统一搬到当前后端：

1. 用**平台管理员账号**登录门户（平台会话），进入文件管理页。
2. 点「**迁移历史文件**」→ 确认弹窗（会说明迁移方向与耗时提示）。
3. 等待完成提示：「迁移完成：成功 N，失败 X，跳过 Y」。同步执行，文件量大时耗时较长，**务必低峰操作**。
4. ✅ 成功标志：刷新后列表所有文件的存储列统一为当前后端标签，抽查下载内容正常。
5. 失败明细会在结果中给出；失败文件可修复原因（如原后端不可达）后再次执行——已成功的文件自动跳过（幂等）。
6. 「直传中」状态的文件不参与迁移，等直传完成后再迁。
7. 用**租户账号**执行同一按钮只迁移**本租户**的文件——范围随登录身份自动收口，租户管理员可自行迁移自己的数据，无需平台代劳。

## 五、公开素材治理（免登录可读的文件）

**哪些文件是公开的**：上传时被业务模块声明为「公开访问级别」的文件——典型为登录页 Logo / 背景图、租户品牌个性化素材。这类文件**无需登录即可通过固定地址访问**（浏览器图片标签场景），服务端只放行公开级别的行，非公开文件按不存在处理（404），不会泄露。

运维要点：

1. **地址口径固定**：公开素材地址形如 `/fs/asset/{租户号}/{文件id}.{后缀}`——首段租户号即素材所属世界（0=平台世界）。各业务模块（登录页配置、品牌设置）会自动生成并保存该地址，运维无需手拼。
2. **网关白名单**：微服务形态需保证网关免登录白名单含 `/fs/asset/**`（标准部署已内置；若自行收紧白名单导致登录页图片 404，把该路径加回）。
3. **永久缓存**：公开素材响应带永久强缓存头——**替换素材后请上传新文件并更新引用地址**，不要指望覆盖同名文件生效（文件 id 变了，地址随之变，客户端会自动拉新）。
4. **治理建议**：公开 = 任何能拿到地址的人可读。仅把确定无敏感内容的素材（Logo、背景图、公开宣传图）设为公开；业务附件、个人信息文件一律走默认私有级别。

## 六、RustFS 日常巡检（rustfs 模式）

1. **控制台**：浏览器打开 RustFS 管理控制台（默认 `http://localhost:9001`，账号见部署时的凭据配置）。
2. **桶巡检**：确认桶 `mse-fs` 存在（服务启动自动创建）；桶内顶层目录即各租户号——这是物理层租户隔离，**不要在存储侧手工改动对象**。
3. **容量**：关注卷容量水位（容器数据卷 `rustfs-data`），提前扩容。
4. **备份**：对象存储的数据卷纳入每日备份策略（与数据库备份同等级别——元数据在库、内容在存储，两者都不可丢）。
5. **跨域配置**：如需使用「大文件直传」，存储侧 CORS 需允许门户来源并暴露 ETag 响应头（部署手册有留档说明）；未配置时直传会报「未读到分片 ETag」。

## 七、注意事项

1. **先切后端、再迁文件、后下线旧存储**：顺序错了旧文件会临时不可下载；迁移完成确认前不要清理旧后端数据。
2. **默认凭据必须改**：RustFS 出厂凭据（rustfsadmin/rustfsadmin）生产环境必须更换，且与 mse-fs 配置两侧同步。
3. **元数据与物理对象是两份资产**：文件元数据在数据库、内容在存储后端，备份策略要同时覆盖。
4. **上传上限**：普通上传默认 100MB（配置可调）；更大文件引导用户走「大文件直传」（rustfs 模式）。
5. **可整体替换**：如需接入自研对象存储（其他 S3 兼容产品按 rustfs 模式配置即可；非 S3 协议需开发定制存储实现），联系开发按替换语义扩展，不要直接改库改对象。
