# 05 配置手册（零基础版）—— 从零把 mse-im 跑起来

> **这本手册是给谁的**：没接触过本系统、甚至没怎么接触过服务器软件的同事——实施工程师、现场 IT、接手部署的新人。你不需要看懂代码，照着做、每步核对「✅ 成功的标志」即可。
> 配套文档：跑起来之后怎么用，看 [04-操作说明书](04-操作说明书/README.md)；技术架构与设计权衡，看仓库根 [docs/tech/openim-integration.md](../../../docs/tech/openim-integration.md)。

## 一、先认识几个名词（3 分钟）

| 名词 | 是什么 | 打个比方 |
| --- | --- | --- |
| **OpenIM** | 开源聊天服务端（本产品的"发动机"，Go 语言全家桶） | 邮局本身 |
| **mse-im** | 我们的业务积木：负责账号桥、会话签发、工作台免登——**用户账号只有一个来源（ai-mse 基座）** | 邮局门口的传达室 |
| **聊天客户端** | 员工用的聊天网页（`clients/web/`） | 你手里的信纸 |
| **IM 实例** | 一整套独立运行的 OpenIM（含它私有的数据库等）；**每个租户一套，互不相通** | 每家公司自己的邮局 |
| **MongoDB / Redis / Kafka / MinIO / etcd** | 实例私有的配套件：消息库 / 缓存 / 内部队列 / 附件仓 / 通讯录——随实例一起启动，**不用单独装** | 邮局的档案柜、电话线、包裹架 |
| **LiveKit** | 开源音视频服务：1v1 通话的画面声音走它 | 电话交换机 |
| **平台托管 / 租户自助** | 实例两种来源：平台代建（推荐）/ 租户自己的服务器或第三方 | 自建邮局 vs 租用邮政服务 |
| **webhook 回调** | 实例把"谁上线了、谁发了消息"反向通知给 mse-im（机器人、停用踢线依赖它） | 邮局的回执电话 |
| **Docker / Nacos / 单体 / 微服务** | 见 [mse-mes 同款手册](../../mse-mes/docs/05-配置手册-零基础版.md) 第一节，含义完全一致 | — |

## 二、你需要准备什么

| 项 | 要求 | 说明 |
| --- | --- | --- |
| 服务器 | **每实例预留 2~4G 内存**（OpenIM 全家桶 + LiveKit）；基座本体 4 核 8G 起步 | Windows / Linux 均可；生产建议 Linux |
| 软件 | Docker（推荐）；基座侧 JDK 21 / MySQL 8 / Redis / Node.js 20+ 需求与基座部署一致 | 路线 A 只需 Docker |
| 端口 | 见第三节端口表；**Windows 部署须避开系统保留端口段（见 3.3 的坑）** | — |
| 软件包 | 本仓库源码（git clone 或压缩包）；OpenIM 镜像约 1~2GB 首次拉取 | — |

## 三、路线 A：容器一键部署（推荐，约 60 分钟）

### 第 1 步：启动基座（MySQL / Redis）

进入仓库 `mse-framework/docker`，执行 `docker compose up -d mysql redis`。
✅ 成功标志：`docker ps` 出现 `mse-mysql`、`mse-redis` 且状态 Up。

### 第 2 步：启动 OpenIM 实例（租户 1 的手动 PoC 栈）

```bash
cd mse-modules/mse-im/docker/openim
# 先改 .env 两个密码再启动（见下）
docker compose up -d
docker exec im-openim-server mage check     # 健康检查
```

✅ 成功标志：`docker ps` 出现 `im-` 前缀的一组容器（openim-server、mongo、redis、kafka、minio、etcd、livekit）。

启动前必须核对 `.env` 三处：

| 变量 | 要求 |
| --- | --- |
| `OPENIM_SECRET` | 改强随机值；**必须与 mse 侧 `MSE_IM_SECRET` 同值**（两边对不上暗号就握不了手） |
| `MINIO_EXTERNAL_ADDRESS` | 必须是**员工浏览器可达**的地址（聊天图片/文件浏览器直传落这里）；本机联调用默认 `http://127.0.0.1:10005` 即可 |
| `LIVEKIT_API_KEY / SECRET` | 必须与 mse 侧一致（mse-im 负责发"进房门票"）；生产把 `LIVEKIT_NODE_IP` 改为服务器公网 IP |

该栈占用端口（与基座零冲突）：**10001**（聊天长连接）、**10002**（聊天接口，媒体上传也走它）、**10004/10005**（MinIO 控制台/对象存储）、**12379/12380**（etcd，生产可去掉映射）、**7880/7881 + UDP 7880-7889**（音视频）。Mongo/Redis/Kafka 不占宿主端口。数据都在目录 `./data/` 里——整目录删除即重置。

### 第 3 步：启动应用（单体，含聊天管理页与聊天接口）

进入 `mse-framework/docker`，执行：

```bash
docker compose --profile apps up -d --build mse-monolith
```

✅ 成功标志：`docker logs -f mse-monolith` 出现 `Started ...`；`curl http://localhost:8080` 有应答。
说明：单体聚合工程已内置 mse-im 业务积木——业务表（实例台账/机器人/审计/工作台/部门群/用户资料）与页面菜单、权限点**全部随启动自动写入数据库**，无需执行任何 SQL。

### 第 4 步：把两边"暗号"对上（关键！）

给单体配置 `mse.im.*`（编辑 `mse-sample/mse-monolith/src/main/resources/application.yaml` 的 `mse.im` 段，或用环境变量覆盖）：

| 配置 | 值 | 对应 OpenIM 侧 |
| --- | --- | --- |
| `MSE_IM_SECRET` | 与 `.env` 的 `OPENIM_SECRET` **同值** | `OPENIM_SECRET` |
| `MSE_IM_API_URL` / `MSE_IM_WS_URL` | 默认 `http://127.0.0.1:10002` / `ws://127.0.0.1:10001` | 实例端口 |
| `MSE_IM_CRYPT_KEY` | **生产必改**（实例密钥落库加密钥匙；更换后需重录实例密钥） | — |
| LiveKit `api-key` / `api-secret` | 与 `.env` 的 `LIVEKIT_API_KEY / SECRET` 一致 | `LIVEKIT_*` |
| `MSE_IM_PROVISION_ENABLED` | 要用「平台一键开通」时设 `true`（默认 false） | — |

改完重启单体。✅ 成功标志：登录后调「IM 设置 → 测试连接」显示成功。

### 第 5 步：启动前端与聊天客户端

```bash
cd mse-framework/mse-ui && npm install && npm run dev          # 基座门户（含「即时通讯」管理菜单），:3000
cd mse-modules/mse-im/clients/web && npm install && npm run dev    # 聊天客户端，:4100
```

✅ 成功标志：浏览器打开 `http://localhost:4100` 见聊天登录页（代理目标默认单体 8080，微服务形态用 `MSE_API_TARGET` 指向网关 48080）。

### 第 6 步：开通租户并"点亮"聊天

1. `http://localhost:3000` 用平台超管（`platform/admin123`，正式环境务必改密）登录 →「租户管理」新建租户。
2. **套餐管理** → 编辑该租户套餐 → 勾选「**即时通讯**」分组下的页面菜单（IM 设置 / 机器人 / 工作台配置）→ 保存。不勾，租户侧看不到任何 IM 管理页。
3. 租户管理员登录 →「即时通讯 → IM 设置」：平台托管实例此时已可见（仅可启停与测试）；租户 1 的手动栈在本手册属"默认实例配置段"形态，无需录入。

### 第 7 步：验收主流程

1. 员工账号（租户内）打开 `http://localhost:4100` 用基座账号密码登录 → 能进聊天主界面。
2. 双开浏览器用两个员工账号互发消息、发图片 → 收发正常。
3. 租户管理员在「IM 设置 → 部门群」点「立即同步」→ 部门群出现在双方会话列表。
4. 「机器人」页绑一个 AI 智能体 → 聊天里给机器人发消息收到回复（需 mse-ai 已部署，可选）。
5. 聊天客户端「工作台」页签点宫格 → 免登直达基座页面。走通即部署成功。

## 四、两种开通方式（生产怎么选）

| | **手动 PoC 栈**（本手册第三节） | **平台编排托管**（推荐生产） |
| --- | --- | --- |
| 谁来做 | 实施/IT 手工起 compose | 平台管理员在「即时通讯管理 → IM 开通」页一键开通 |
| 适合 | 单租户试点、PoC、standalone 交付 | 多租户正式环境：每租户一套、独立端口块与随机凭据 |
| 台账形态 | 无台账行，走 `mse.im.server` 默认配置段 | 开通即写"平台托管"台账（租户侧仅可启停与测试） |
| 前提 | 手工执行 compose | `MSE_IM_PROVISION_ENABLED=true` 且部署机可用 docker 命令 |
| 运维 | 手工 down/up | 页面完成探活/停启/备份/升级/销毁，并生成接入反代配置段 |

### 4.1 平台编排的端口规则（与 Windows 大坑）

- 每开通一个租户分配**一块连续端口**（默认 10 个一组：聊天接口=块基址、长连接+1、对象存储+2、控制台+3），从 **11000** 起自动顺延，无需人工规划。
- ⚠️ **Windows 陷阱**：Windows 会动态保留一些端口段（如 `10588-11287`），被保留的端口**起不来且报错隐晦**。检查命令：

```bash
netsh interface ipv4 show excludedportrange protocol=tcp
```

若默认起始段 11000 落在保留区间，把 `mse.im.provision.port-base` 改到保留段之后（本仓库回归实测用 **11500**）；生产 Linux 无此问题。

- 手动栈与编排托管混部时：手动栈端口（10001/10002 等）与自动分配块不重叠，可共存。

## 五、微服务形态要点（进阶）

1. Nacos 配置：`CONFIG_DIR=<仓库根>/mse-modules/mse-im/docker/nacos/config sh mse-framework/docker/nacos/init-configs.sh` 导入 `mse-im.yaml`（端口 8099、`mse.im.*` 全量留档在此，参数含义见文件内注释）。
2. 构建顺序：框架区 `mvn install -DskipTests` → `mvn install -DskipTests -f mse-modules/mse-im/pom.xml` → `java -jar im-boot/target/im-boot-1.0.0-SNAPSHOT.jar`。
3. 网关：确认 `mse-gateway.yaml` 有 `/im/** → lb://mse-im` 与白名单（`/im/sso/exchange`、`/im/oauth/token`、`/im/oauth/userinfo`、`/im/workbench/asset/*`、`/im/client/asset/*`、`/im/callback/**`）——已随仓库基线登记。
4. 每个租户的实例坐标仍走「IM 设置」（租户自助）或「IM 开通」（平台托管）；多实例不靠改代码。
5. 信创库：启动加 `--spring.profiles.active=dm` 或 `kingbase`（基线自带三方言能力，im 表结构随方言脚本；当前 im 仅提供 mysql 脚本，信创环境先与研发确认）。

## 六、生产反代与回调（必读）

1. **同域名反代**：聊天页面是 HTTPS 时聊天连接必须 wss——用一张域名证书把 `https://im.xxx.com/api` → 实例 10002、`/msg_gateway` → 10001、`/rtc` → LiveKit 7880 反代（「IM 开通」页可一键生成该配置段）；平台托管实例开通时选配子域模板即自动落好公网坐标。
2. **webhook 回调**：平台托管实例已自动反连；自建实例须把「IM 设置」页展示的回调地址填进实例回调配置——不配则机器人、停用踢线、在线状态、消息审计均不工作（「测试连接」会明示）。
3. **防火墙放通**：音视频需 UDP 7880-7889 与 TCP 7881；Docker Desktop 下 UDP 直通异常时客户端自动走兜底通道（质量降级不中断）。

## 七、常见问题排查（按现象查）

| 现象 | 先检查什么 |
| --- | --- |
| 客户端登录报「IM 功能未开通」 | 该租户台账停用 / 无台账且默认段未配 secret——「IM 设置」或 `MSE_IM_SECRET` 逐查 |
| 登录报密钥类错误 | 两侧暗号不一致：`OPENIM_SECRET` ≠ `MSE_IM_SECRET`（最常见） |
| 消息能发、图片/文件发不出 | `MINIO_EXTERNAL_ADDRESS` 不是浏览器可达地址（写成内网地址了） |
| 部署机起编排实例失败、日志端口类报错 | Windows 保留端口段（见 4.1 的 netsh 命令）；或与手动栈端口冲突 |
| 机器人不回复 | 回调没配/不可达（测试连接看探测结果）；机器人未启用；AI 平台侧智能体不可用 |
| 停用账号后还能聊 | 该实例回调不可达（踢线依赖上线复核）+ 7 天票据未到期——修回调通道后即恢复即时踢线 |
| 「测试连接」提示回调不可达 | 实例在 NAT/内网后反连不到平台；平台托管实例不应出现，出现则报平台管理员 |
| 通话接通但无声音/画面 | 防火墙未放通音视频端口段；或两侧 `LIVEKIT_*` 密钥不一致 |
| 管理页菜单看不到 | 套餐没勾「即时通讯」菜单，或角色未授权（见第 6 步与 03-角色规划） |
| 单体启动报脚本失败并退出 | 数据库迁移是强校验：按日志修复后重启，不要跳过 |
| 界面中文乱码 | 自建库须 utf8mb4；用 SQL 直插中文加 `--default-character-set=utf8mb4` |

## 八、上线前检查清单

- [ ] 修改所有默认密码：`.env` 的 `OPENIM_SECRET`、`MINIO_*`、`LIVEKIT_API_SECRET`、mse 侧 `MSE_IM_SECRET` / `MSE_IM_CRYPT_KEY`（两侧一致的保持一致）
- [ ] 生产使用 Linux 部署机（规避 Windows 保留端口段）；端口块规划留好增长空间（每租户 10 个）
- [ ] 域名 + TLS 同域反代就位（`/api`、`/msg_gateway`、`/rtc`），聊天页面与基座同源或可跨域
- [ ] 防火墙放通：10001/10002（或反代后仅 443）、MinIO 10005、LiveKit UDP 7880-7889 / TCP 7881
- [ ] 平台托管模式：`MSE_IM_PROVISION_ENABLED=true` 且已在「IM 开通」页为每个租户完成开通与首次探活
- [ ] 租户套餐已勾选「即时通讯」菜单；建议角色已建并授权（03-角色规划）
- [ ] 首个实例完成验收主流程（第 7 步五项）；实例备份策略已定（低峰期定期备份）
- [ ] 数据库开启每日备份；记录部署版本与日期（OpenIM 锁定 v3.8.3-patch.x，升级走独立租户灰度）
