# 02 权限规划 —— 子应用注册、页面菜单与权限点

> mse-open 的菜单与权限点设计。**本文所有 id / 号段均为实际落库值**，转录自工程内版本化脚本（`open-service/src/main/resources/db/mysql/V20261001_01_open__open_base.sql`），与 `zcode-plugin/plugins/mse-dev/references/alloc-tables.md` 登记一致。
> 功能点含义见 [01-功能规划](01-功能规划.md)，角色授权见 [03-角色规划](03-角色规划.md)。

## 一、设计原则（基座 RBAC 模型）

1. **三张全局表，一条链路**：`sys_micro_app`（子应用注册）→ `sys_menu`（导航菜单）→ `sys_permission`（权限点）；授权链 `sys_user → sys_user_role → sys_role → sys_role_menu / sys_role_permission`。
2. **sys_menu.type**：450=目录（type=1 分组目录、parent_id=0），其余为 type=3 子应用页面菜单（`micro_name=open`、`path` 为子应用内部路由）。`menu_scope=2` 租户端。
3. **权限点必须挂靠页面菜单**：`sys_permission.menu_id` 指向本工程 type=3 页面菜单，参与角色授权分组与**租户套餐裁剪**；本工程无 `menu_id=NULL` 通用权限。454「接入指南」为纯展示页，无按钮级权限点。
4. **双端会话语义（本工程特有）**：管理端接口 `@SaCheckPermission` 同时接受**租户端与平台端**两种登录类型（`LOGIN_TYPE_TENANT` / `LOGIN_TYPE_PLATFORM`）——租户管理员自管本租户的开放应用/API/凭证；平台管理员治理平台域应用（tenantId=0 凭证）并可为应用绑定任意租户；平台超管域内全量权限码。
5. **权限码格式**：`open:<模块>:<动作>`，动作小写动词（如 `open:app:reset-secret`），唯一键 `uk_code`；前端按钮用 `v-permission` 按权限码显隐（open-ui 已内置 directives/permission.ts）。
6. **开放 API 标识是另一维编码**：`open:<biz>:<资源>[-<动作>]`（如 `open:oa:process-start`），落在 `open_api.code`（世界内唯一），是**应用授权与调用审计的锚点**——与上面的管理端权限点（`open:app:*` 等人机权限）完全两个体系，勿混淆。
7. **落库方式**：随 jar 的幂等版本化脚本（当前仅 MySQL），免手工执行——`base` 通道脚本由 starter-bridge 自动推送 mse-system 应用（分册账本 `mse_open_schema_history`）；已应用脚本不再修改，变更一律新增版本文件。

## 六、开放 API 标识编码规范（open_api.code）

应用授权、调用审计、目录治理共用这一维编码，纪律如下：

1. **格式** `open:<biz>:<资源>[-<动作>]`：biz 段为业务积木标识（`oa`/`mp`/`data`/`ai`/`fs`…），资源小写；如 `open:oa:process-start`、`open:user:page`、`open:fs:file-upload`。
2. **内置段** `open:user:*` / `open:dept:*` / `open:role:*` / `open:bind:*` 为 mse-open 内置端点保留前缀（种子 8001-8022），业务积木不得占用；业务 path 必须带业务前缀段（`/open/api/<biz>/...`），勿与内置路径冲突。
3. **唯一性**：`(tenant_id, code)` 世界内唯一（`uk_tenant_code`）——两家业务撞 code 时后注册者更新前者的定义字段，命名规范是防冲突的第一道闸。
4. **与权限点的关系**：开放 API 标识**不进** `sys_permission`，不参与角色/菜单授权；它经管理端「API 授权」勾选落到 `open_app_api`（应用×API 授权关系），参与租户套餐裁剪的是管理端页面菜单（450-455）而非 API 本身。

## 七、套餐裁剪与登记纪律

1. **租户套餐**：开放能力页面菜单（451-455）需在套餐中勾选后对租户管理员可见；租户管理员拿到的是「套餐域内全量权限码」，再经角色管理细分到岗位（见 [03-角色规划](03-角色规划.md)）。租户未开通开放能力时，不勾 451-455 即整体封存。
2. **网关白名单**：`/open/oauth/token`（公开换凭证端点）与 `/open/api/**`（应用凭证在 open-service 下游校验，纵深防御）已放行于 `mse.gateway.ignore-urls`；注意 Spring list 属性整体替换，调整白名单须全量列出。
3. **alloc-tables.md 登记**（已占用）：后端端口 8092、前端 dev 3600、micro_app id=5、菜单段 450-455、权限段 7xxx（7001-7012）、网关前缀 `/open /openapp`、操作日志字典 id=41。后续新增权限点在 7xxx 段顺延，先查表再占用、用后回写。
4. **脚本纪律**：全部幂等写法（子应用按 name 判重、菜单按 id 判重、权限点按 id 判重、字典按 id 判重）；已应用脚本不再修改，新增权限点/菜单一律新增版本文件（`V{yyyyMMdd}_{NN}_open__<描述>.sql`，头指令 `-- mse-target: base`）。
