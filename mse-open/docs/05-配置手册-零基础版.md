# 05 配置手册（零基础版）—— 从零把开放平台跑起来

> **这本手册是给谁的**：没接触过本系统、甚至没怎么接触过服务器软件的同事——实施工程师、现场 IT、接手部署的新人。你不需要看懂代码，照着做、每步核对「✅ 成功的标志」即可。
> 配套文档：跑起来之后怎么用，看 [04-操作说明书](04-操作说明书/README.md)；业务接入与第三方调用的技术细节，看 [open-api-guide.md](open-api-guide.md)。

## 一、先认识几个名词（2 分钟）

| 名词 | 是什么 | 打个比方 |
| --- | --- | --- |
| **Docker** | 容器软件，把 MySQL 等软件"打包"成一键安装 | 免安装的"绿色软件"运行器 |
| **MySQL / Redis** | 数据库 / 缓存；业务数据存前者，令牌与会话存后者 | 账本 / 门卫的登记本 |
| **JDK 21 / Maven / Node.js** | Java 运行环境 / Java 打包工具 / 前端构建运行环境 | 播放器 / 印刷厂 / 网页的发动机 |
| **Nacos** | 微服务模式下的"配置中心 + 通讯录" | 公司前台（单体模式用不到） |
| **单体 / 微服务** | 两种安装形态：单体=所有功能装在一个程序里；微服务=拆成多个程序各司其职 | 便利店 vs 购物中心 |
| **AppKey / AppSecret** | 发给接入系统的"账号 + 密钥"对；密钥加密存放、只在发放那一刻展示一次 | 门禁卡 + 卡片密码 |
| **access_token** | 接入系统用凭证换来的"临时通行证"（默认 2 小时），调用接口时随身携带 | 临时出入证 |
| **开放 API 目录** | 平台维护的"可调用接口清单"，接入应用只能调被授权的条目 | 菜单，点了才能上菜 |
| **限流 QPS** | 每个应用每秒最多允许的调用次数，超了返回 429 | 柜台每秒接待上限 |

> **新人建议选「单体」**：一个程序 + MySQL + Redis 就能跑全部功能（含开放平台与各业务系统）。微服务是给有运维团队的正式生产环境用的（见第六节）。

## 二、你需要准备什么

| 项 | 要求 | 说明 |
| --- | --- | --- |
| 服务器/电脑 | 4 核 8G 起步，硬盘 ≥40G | Windows / Linux 均可 |
| 软件 | Docker（推荐）或：JDK 21 + MySQL 8 + Redis + Maven 3.9+ + Node.js 20+ | 路线 A 只需 Docker |
| 软件包 | 本仓库源码（git clone 或压缩包），或向开发要成品 jar | jar 也可以直接用 |

## 三、路线 A：容器一键部署（推荐，约 30 分钟）

### 第 1 步：安装 Docker 并启动数据库和缓存

- Windows 装 Docker Desktop 并启动；Linux 装 docker + docker compose 插件。✅ `docker --version` 能输出版本号。
- 进入仓库 `mse-framework/docker` 目录执行：

```bash
docker compose up -d mysql redis
```

- ✅ 成功标志：`docker ps` 里出现 `mse-mysql`、`mse-redis`，状态 Up（首次初始化约 1 分钟）。会自动创建 `mse_platform` 与 `mse_tenant` 两个库，**不用手工建表**。

### 第 2 步：启动应用（单体，已含开放平台）

单体示例 mse-monolith 已聚合开放平台业务积木（open-service）与各业务积木，启动即自带：

```bash
docker compose --profile apps up -d --build mse-monolith
```

- ✅ 成功标志：浏览器打开 `http://localhost:8080` 有应答；`docker logs -f mse-monolith` 出现 `Started ...`。
- 开放平台的业务表、内置接口清单种子、页面菜单与权限点，都会在启动时**自动写入数据库**，无需执行任何 SQL。

### 第 3 步：启动网页前端

```bash
cd mse-framework/mse-ui      # 基座门户（含「开放能力」页面）
npm install && npm run dev
```

- ✅ 成功标志：浏览器打开 `http://localhost:3000` 看到登录页。
- 开放平台自己的管理页面是子应用，开发调试另起：`cd mse-modules/mse-open/open-ui && npm install && npm run dev`（端口 3600，本地免配置即可被门户加载）。

### 第 4 步：登录并初始化租户

1. `http://localhost:3000` 用**平台超管**登录：账号 `platform`，密码 `admin123`（正式环境务必改密码）。
2. 「租户管理」新建租户（自动生成租户管理员账号）。
3. 「**套餐管理**」→ 编辑租户所用套餐 → 勾选「**开放能力**」分组下的页面菜单（应用管理 / 调用日志 / 身份绑定 / 接入指南 / API 目录）→ 保存。**不勾菜单，租户侧看不到开放平台**。
4. 用租户管理员登录 →「角色管理」按 [03-角色规划](03-角色规划.md) 第二节创建建议角色（如 `open_admin`）并勾选「开放能力」分组权限点 → 授予管理员工账号。

### 第 5 步：验收第一条链路（接入方视角）

1. 开放能力 → 应用管理 → 接入应用（绑一个租户）→ **当场保存弹窗里的 AppKey/AppSecret**；
2. 「授权」至少勾选 `open:user:page`；给接入方交付凭证与 [open-api-guide.md](open-api-guide.md)；
3. 让接入方（或用接口工具代替）换 token → 调用户分页查询 → 只能看到所绑租户的用户；
4. 故意用未授权接口试一次（应 403）、用错误密钥换 token（应 401）→ 「调用日志」里能看到这几次调用即审计链路正常。

## 四、关键参数速查

> 单体形态在 `mse-sample/mse-monolith` 的配置文件里加 `mse.open.*` 段即可覆盖；微服务形态改 Nacos 的 `mse-open.yaml`（见第六节）。所有参数都可用**环境变量**注入，不用改文件。

| 想改什么 | 参数（环境变量） | 默认值 | 说明 |
| --- | --- | --- | --- |
| 密钥落库加密密钥 | `mse.open.crypt-key`（`MSE_OPEN_CRYPT_KEY`） | 内置演示值 | **生产必须改**！更换后历史密文不可解，需逐应用重置密钥 |
| 访问令牌有效期（分钟） | `mse.open.token-ttl-minutes`（`MSE_OPEN_TOKEN_TTL`） | 120 | 接入方按返回的 expiresIn 提前刷新 |
| 默认限流 QPS | `mse.open.default-rate-limit`（`MSE_OPEN_RATE_LIMIT`） | 50 | 应用未单独配置时限流值 |
| 签名时间戳窗口（秒） | `mse.open.sign-timestamp-window-seconds` | 300 | 与接入方服务器时钟偏差容忍度 |
| 自注册推送开关 | `mse.open.registry.enabled` | true | 只消费契约不参与自注册的部署可关 |
| 自注册重推周期（分钟） | `mse.open.registry.interval-minutes` | 5 | 周期重推自愈，调小收敛更快 |
| 泛化分发接口包白名单 | `mse.open.rpc.allowed-packages` | `vip.mseapp.` | 开放新业务包前缀时追加 |
| 泛化调用超时（毫秒） | `mse.open.rpc-timeout-millis` | 30000 | 慢业务接口按需调大 |

> 应用级的限流 QPS、凭证过期时间、请求签名、IP/域名白名单**不在配置文件里改**——管理员在「应用管理」页按应用设置（见 04 号手册 01 册）。

## 五、租户 / 套餐 / 角色初始化小结

| 事项 | 在哪做 | 要点 |
| --- | --- | --- |
| 套餐勾选 | 平台端「套餐管理」 | 勾「开放能力」分组菜单（451-455），租户侧才可见 |
| 角色创建 | 租户端「角色管理」 | 建议角色与权限点勾法见 [03-角色规划](03-角色规划.md)；超管可不建角色直接用 |
| 平台侧管理员 | 平台端「角色管理」 | 平台超管天然全量；其他平台账号勾选 `open:app:*` 等权限点 |
| 首个接入应用 | 开放能力 → 应用管理 | 绑定租户决定数据边界；凭证仅展示一次 |

## 六、路线 B：微服务形态（进阶，正式环境）

> 什么时候需要：用户量大、需要独立扩缩容、有运维团队。试点环境用第三节单体即可。

1. 启动 Nacos（基座 compose 已含）：`docker compose up -d nacos`，控制台 `http://localhost:18080`。
2. 把开放平台专属配置写入 Nacos：
   ```bash
   CONFIG_DIR=<仓库根>/mse-modules/mse-open/docker/nacos/config sh mse-framework/docker/nacos/init-configs.sh
   ```
   即导入 Data ID `mse-open.yaml`（端口 8092 与第四节全部参数都在这里改）；数据源/Redis/Sa-Token/Dubbo 等公共项在共享 Data ID（`mse-micro-common.yaml`、`mse-micro-db-biz.yaml`、`mse-micro-dubbo.yaml`）统一管理。
3. 构建：先仓库根 `mvn install -DskipTests`（框架）→ `mvn install -DskipTests -f mse-modules/mse-open/pom.xml`；启动 `java -jar open-boot/target/open-boot-*.jar`（注册进 Nacos，服务名 `mse-open`）。
4. 网关：`mse-gateway.yaml` 已留档路由 `Path=/open/**,/openapp/** → lb://mse-open`，白名单已放行 `/open/oauth/token`（公开换凭证端点）与 `/open/api/**`（凭证在 open-service 内校验，纵深防御）——一般无需改动；调整白名单注意该配置是**全量替换**，须完整列出。
5. 前端开发代理：`open-ui/vite.config.ts` 的 `/api` 代理默认指向单体 8080，微服务模式改为网关 `http://localhost:48080`（或 open-boot 直连 8092）。
6. 业务服务（如 oa-boot）启动后，其开放能力经自注册自动出现在「API 目录」（启动即推 + 每 5 分钟重推自愈），无需任何手工登记。

## 七、常见问题排查（按现象查）

| 现象 | 先检查什么 |
| --- | --- |
| 接入方换 token 返回 401 | AppKey/AppSecret 抄错（注意复制时带空格）、应用被停用/删除、改绑了租户、凭证过期时间已过——「应用管理」核对状态与「调用日志」看失败原因 |
| 接入方调用返回 403 | 该应用未被授权此 API——「应用管理 → 授权」勾选保存 |
| 接入方调用返回 404 | API 被目录停用（「API 目录」查状态）或路径/方法不在清单 |
| 接入方调用返回 429 | 触发限流：调高该应用限流 QPS 或让接入方退避重试 |
| 接入方调用返回 503 | 目标业务系统未部署/未启动；恢复后自动可用，无需重启开放平台 |
| 签名校验一直失败 | 核对三点：签名原文拼接顺序、密钥必须用 AppSecret **明文**、服务器时钟偏差是否超窗口（先校 NTP）；随机串不能复用 |
| 「API 目录」看不到业务系统条目 | 自注册未生效：业务工程是否依赖 open-api 契约并声明了 Contributor Bean；`mse.open.registry.enabled` 是否被关；等一个重推周期或重启业务服务（目录接收在开放平台侧日志可见） |
| 登录后左侧没有「开放能力」菜单 | 套餐没勾选（第 4 节第 3 步），或该用户角色没授权菜单 |
| 菜单在但页面空白/404 | open-ui 子应用没启动（3600）或生产地址没在「子应用管理」登记为 `/sub-apps/open/` |
| 换了 `mse.open.crypt-key` 后所有应用 401 | 预期行为：旧密文不可解——逐应用「重置密钥」并把新密钥同步接入方 |
| 微服务下接口报 404（网关层） | open-boot 没注册进 Nacos，或网关路由缺 `/open/**` |
| 管理端操作报 403（人机） | 当前账号未授予对应权限点（如 `open:app:grant`）——按 03 号手册补授权 |
| 应用启动失败报数据库错误 | MySQL 没起/地址密码错/账号无建库权限；启动日志报脚本执行失败会阻断启动，按提示修复后重启 |

## 八、上线前检查清单

- [ ] **更换 `mse.open.crypt-key` 为强随机值**（如 `openssl rand -hex 32`），并记录保管位置
- [ ] 修改所有默认密码（platform/admin123、数据库 root、Redis 密码）
- [ ] 对外暴露的接入应用：开启**请求签名**并配置 IP / 域名白名单，设置限流 QPS 与凭证过期时间
- [ ] 接入方授权遵循最小化：只勾选业务需要的 API
- [ ] 数据库开启每日备份；「调用日志」表容量与归档策略已评估
- [ ] 微服务形态：Nacos 开鉴权、网关白名单保持最小（仅两条 /open 放行项）
- [ ] 用 04 号手册 02 册的「上线前自查清单」与首个接入方完成一次端到端联调
- [ ] 记录本次部署的版本号与日期，便于后续升级追查
