# 02 接入方开发者操作手册

> 使用者：第三方系统 / 内网系统的开发与联调人员。**不使用管理端**，全程只与两样东西打交道：管理员发给你的一对应用凭证（AppKey/AppSecret），以及开放接口地址。
> 本文只讲流程与判断；命令级示例（curl 全样例、签名算法细节、六步接入）见 [open-api-guide.md](../open-api-guide.md)——请勿重复提问，照抄即可。

## 一、接入全流程（从申请到上线）

| 步骤 | 谁做 | 你要做什么 / 拿到什么 |
| --- | --- | --- |
| 1. 提交接入申请 | 你 → 管理员 | 说明接入系统名称、用途、需要调用哪些能力（如用户同步、发起 OA 流程）、预期调用量 |
| 2. 领取凭证 | 管理员 | 管理员在「应用管理」建应用并发凭证：**AppKey + AppSecret（仅展示一次）**；请存入你们的密钥管理系统，不要进代码仓库 |
| 3. 确认可调清单 | 管理员 + 你 | 管理员给应用勾选授权；你在「API 目录」或对接文档核对自己被授权的 API 标识、方法与路径 |
| 4. 换取访问令牌 | 你 | 用凭证换取 access_token（默认 2 小时有效）；**缓存复用、到期前刷新**，不要每次调用都换 |
| 5. 联调 | 你 | 携带令牌调用开放接口，按第五节核对错误语义；有签名/IP 白名单要求的先向管理员确认应用配置 |
| 6. 上线 | 你 | 固化 token 刷新、错误重试与监控告警；关键写操作带业务幂等键；正式环境地址与网关入口找实施确认 |

## 二、调用模型（一分钟理解）

- **一个令牌入口**：`POST /open/oauth/token`，提交 AppKey + AppSecret，返回 accessToken 与有效期（秒）。
- **一个业务入口**：所有开放接口都在 `/open/api/**` 下，请求头带 `Authorization: Bearer {accessToken}`。
- **一个数据边界**：应用绑定了某个租户，你能读写的全部数据都在该租户范围内——**不需要也无法传租户参数**。
- **两类接口**：内置端点（用户/部门/角色/身份绑定，`open:user:*` 等）+ 业务能力端点（OA 流程、AI 对话、文件等，`open:<业务>:*`），鉴权与调用方式完全一致。
- **机器身份**：接口没有"登录人"，需要操作者的请求请显式携带操作者字段（如 `operatorUserId`，取中台账号编号）。

## 三、身份绑定（做单点登录/消息归人必读）

- 你的系统用户与中台账号的映射关系由你经开放接口建立：提交「来源系统标识 + 外部用户标识 + 中台用户编号」创建绑定（同一外部标识重复创建会被拒绝）。
- 登录态映射：拿你系统的用户标识反查中台账号，命中即完成身份归一。
- 也可解绑与反查某账号的全部绑定。字段级示例见 open-api-guide.md 第三节。

## 四、可安全增强项（与管理员对齐）

应用开启以下配置后**强制生效**，联调前先确认你的应用开了哪些：

| 配置 | 开启后你需要做什么 |
| --- | --- |
| 请求签名 | 每个请求附加三个头：毫秒时间戳（±300 秒内）、一次性随机串、HMAC-SHA256 签名（密钥 = AppSecret；签名原文拼接规则见 open-api-guide.md） |
| IP 白名单 | 你的出口 IP 必须在管理员配置的名单内（支持网段），出口 IP 变更需提前报备 |
| 域名白名单 | 纯浏览器侧调用时，你的页面域名需在名单内（支持 `*.域名` 通配） |
| 限流 / 有效期 | 超过每秒配额会收到 429；凭证到期需重新换 token |

## 五、错误语义（联调排错速查）

**先看 HTTP 状态码**（鉴权链拒绝，开放平台直写）：

| 状态码 | 含义 | 你该做什么 |
| --- | --- | --- |
| 401 | 凭证缺失/无效/过期，或应用被停用/删除/过期 | 重新换 token；持续 401 找管理员查应用状态 |
| 403 | 应用未授权调用该 API | 找管理员在「应用管理 → 授权」勾选 |
| 404 | API 未开放或已停用，或路径不存在 | 与管理员核对 API 标识、方法与路径 |
| 429 | 超出应用限流 | 退避重试；持续触发找管理员评估配额 |

**再看响应体 code**（业务层结果，HTTP 200）：

| body code | 含义 | 你该做什么 |
| --- | --- | --- |
| 400 | 业务参数不合法 | 按 message 修正参数（含扩展属性超 4KB、重复绑定等） |
| 404 | 业务资源不存在 | 核对资源编号（如流程实例） |
| 500 / 503 | 业务执行失败 / 目标业务系统未部署 | 503 稍后重试；持续失败把 TraceId 报给管理员查「调用日志」 |

**判定成功以 `HTTP 200 且响应体 code=0` 为准。**

## 六、上线前自查清单

- [ ] AppSecret 存入密钥管理系统，代码与配置仓库中无明文
- [ ] access_token 缓存复用并按有效期提前刷新（不是每次调用都换）
- [ ] 关键写操作携带业务幂等键，失败重试前先查询防重复
- [ ] 分页查询遵守页大小上限（全量同步翻页拉取）
- [ ] 若启用请求签名：签名算法对齐原文拼接规则，服务器时钟已校准（NTP）
- [ ] 监控告警覆盖 401/403/429/503 四类信号，TraceId 已接入排障流程
- [ ] 联系人机制：凭证泄露、IP 变更、扩容申请的管理员联系渠道已建立
