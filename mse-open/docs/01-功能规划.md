## 一、模块总览与核心链路

| # | 模块 | 管理页面（menu_id） | 分期 | 一句话定位 |
| --- | --- | --- | --- | --- |
| 1 | 接入应用管理 | 应用管理（451） | 一期 | 接入应用档案、凭证（appKey/appSecret）、绑定租户、授权、启停 |
| 2 | OAuth 凭证 | 无页面（token 端点） | 一期 | `POST /open/oauth/token` 换取 access_token（机器凭证入口） |
| 3 | 开放 API 目录 | API 目录（455） | 一期/二期 | API 清单治理：SQL 种子内置条目 + 业务自注册条目，启停即时生效 |
| 4 | 开放 API（基座能力） | 无页面（内置端点） | 一期 | 用户/部门/角色/身份绑定 22 条内置端点（种子 8001-8022） |
| 5 | 泛化分发引擎 | 无页面（分发端点） | 一期 | 按目录 target 分发到业务契约：dubbo 泛化 / 单体反射 |
| 6 | 统一身份绑定 | 身份绑定（453） | 一期 | 外部系统用户标识 ↔ 中台账号映射（SSO/会话映射基础） |
| 7 | 用户扩展属性 | 无页面（开放 API） | 一期 | 接入系统差异化画像：JSON 对象整体读写（≤4KB） |
| 8 | 安全加固 | 应用管理（451）内 | 二期 | 请求签名验签、IP 白名单、域名白名单（应用级开关） |
| 9 | 调用日志与审计 | 调用日志（452） | 一期 | 全量调用审计（含 401/403/429），耗时/IP/TraceId |
| 10 | 限流 | 应用管理（451）内 | 一期 | 应用级 Redis 固定窗口限流，超限 429 |

**核心业务链路**（一条机器凭证链路贯穿）：

```
业务积木自注册目录（OpenApiContributor 推送，幂等 upsert + 周期重推自愈）
  → 平台/租户管理员在「API 目录」查看与治理（启停即时生效）
  → 接入方申请接入：管理员「应用管理」建应用（appKey + AppSecret 仅展示一次）
  → 管理员「授权」勾选该应用可调用的 API（含自注册条目）
  → 接入方 POST /open/oauth/token 换 access_token（默认 2h，Redis 承载）
  → 接入方持 Bearer token 调 /open/api/**
     鉴权链：token → 应用实时状态 → IP 白名单 → 域名白名单 → 签名验签
             → 目录匹配 → 应用授权 → 限流 → 注入租户上下文
  → 泛化分发：内置端点本服务承接 / 目录 target 分发业务契约（dubbo 泛化 / 反射）
  → 异步审计落库 → 管理端「调用日志」可查全部调用（含拒绝）
```

## 二、接入应用管理（一期）

一个外部系统一条记录；**应用必绑一个租户（0=平台域）**，绑定租户即数据边界。功能点均落在「应用管理」页（451）。

| 功能点 | 说明 | 主要角色 |
| --- | --- | --- |
| 接入应用 | 录入应用名称与备注；appKey 自动生成（全局唯一）；AppSecret **AES-GCM 加密落库，明文仅创建/重置时弹窗展示一次** | 开放平台管理员 |
| 业务绑定租户 | 应用绑定一个租户（平台端会话可选全部租户与平台域；租户端会话自动填充本租户）；应用调用开放 API 时数据被约束在该租户域内 | 开放平台管理员 |
| API 授权 | 授权弹窗按业务域分类勾选可调用 API（含业务自注册条目）；授权关系不被目录重推覆盖 | 开放平台管理员 |
| 限流 QPS | 按应用设置每秒调用上限（空 = 用平台默认 `mse.open.default-rate-limit`，当前 50）；超限返回 429 | 开放平台管理员 |
| 凭证过期时间 | 应用级凭证有效期上限（空 = 长期）；过期后 token 校验即 401 | 开放平台管理员 |
| 应用启停 | 停用即时生效——**每次调用回查应用状态**，停用/删除/改绑租户的存量 token 立即失效 | 开放平台管理员 |
| 重置密钥 | AppSecret 泄露时一键重置（新密文落库，旧密钥立即作废） | 开放平台管理员 |
| 应用删除 | 逻辑删除；授权关系与有效凭证一并失效（弹窗二次确认） | 开放平台管理员 |

## 三、OAuth 凭证（一期）

| 功能点 | 说明 | 主要角色 |
| --- | --- | --- |
| token 端点 | `POST /open/oauth/token`（网关白名单端点），client credentials 语义：appKey + appSecret 换 `accessToken`，返回 `expiresIn`（默认 7200 秒） | 接入方 |
| token 承载 | Redis 存储，平台可调 `mse.open.token-ttl-minutes`（默认 120 分钟）；接入方应缓存复用、到期前刷新 | 实施管理员 |
| 即时失效 | 应用停用/删除/改绑租户**即时失效**——token 校验每次回查应用实时状态，不依赖 token 剩余时长 | —（机制） |
| 会话隔离 | 机器凭证链路与基座 Sa-Token 人机会话完全独立，互不可冒充 | —（机制） |

## 四、开放 API 目录（一期 + 二期目录真租户化）

平台维护的 API 清单，应用只能调用**被授权**的 API。管理页面「API 目录」（455）。

| 功能点 | 说明 | 主要角色 |
| --- | --- | --- |
| 目录双来源 | `seed`=SQL 种子内置端点（8001-8022）；`rpc`=业务积木自注册（幂等 upsert：按 code 新增或更新定义字段，**管理端启停状态与授权关系永不被覆盖**） | —（机制） |
| 目录清单查看 | 标识/名称/方法/路径/来源/分发目标/状态一目了然；定义字段由业务重推维护，管理端只做治理 | 开放平台管理员 |
| 目录启停 | `open:api:status`，**本世界行级**：停用即时全平台（本世界）所有应用 404；租户端停用只影响本租户，平台端治理平台域凭证的目录 | 开放平台管理员 |
| 目录真租户化（二期） | **每会话世界一份目录**：平台目录行（tenant_id=0）经 per-tenant 播种脚本复制为各租户自有副本；rpc 条目经租户清单扇出播种持续维护；业务库驻留数据 `runIgnore` + 显式 tenant 条件读写 | —（机制） |
| 内置端点承接 | `open_api.target` 为空 = open-service 内置精确 Controller 承接（用户/部门/角色/绑定） | —（机制） |

## 五、开放 API：基座能力开放（一期，内置端点 22 条）

把基座用户/部门/角色/租户能力安全开放（种子 id 8001-8022，全部 `target` 为空的内置端点）。请求/响应示例见 [open-api-guide.md](open-api-guide.md) 第三节。

| 域 | API 标识 | 方法 路径 | 说明 |
| --- | --- | --- | --- |
| 用户 | `open:user:page` | GET `/open/api/user/page` | 分页查询（自动按绑定租户过滤） |
| 用户 | `open:user:get` / `get-by-username` | GET `/open/api/user/{id}`、`/by-username` | 单用户查询 |
| 用户 | `open:user:create` | POST `/open/api/user` | 创建用户（全量纳管；开放链路禁止创建超管） |
| 用户 | `open:user:update` / `status` / `reset-password` / `delete` | PUT/DELETE `/open/api/user…` | 全生命周期维护 |
| 用户 | `open:user:role-ids`（GET） / `open:user:assign-roles`（PUT） | `/open/api/user/{id}/role-ids` | 查询 / 覆盖式分配角色 |
| 用户 | `open:user:extend-get` / `extend-put` | `/open/api/user/{id}/extend` | 用户扩展属性（见第七节） |
| 部门 | `open:dept:tree` / `create` / `update` / `delete` | `/open/api/dept…` | 组织架构同步 |
| 角色 | `open:role:list` / `create` | `/open/api/role…` | 角色查询 / 基础创建（授权矩阵仍由管理端维护） |
| 绑定 | `open:bind:create` / `resolve` / `by-user` / `delete` | `/open/api/bind…` | 统一身份绑定（见第六节） |

## 六、统一身份绑定（一期）

外部系统用户标识 ↔ 中台账号的映射表（`open_user_bind`，租户表自动隔离），SSO 与会话映射的基础。

| 功能点 | 说明 | 主要角色 |
| --- | --- | --- |
| 创建绑定 | `open:bind:create`：中台用户 + 来源系统标识 + 外部用户标识；同租户同来源同外部标识唯一（重复 400） | 接入方（经开放 API） |
| 外部标识反查 | `open:bind:resolve`：sourceSystem + externalUserId → 中台账号（登录态映射基础） | 接入方（经开放 API） |
| 按用户查绑定 | `open:bind:by-user` / `open:bind:delete`：某账号全部绑定关系与解绑 | 接入方（经开放 API） |
| 管理端只读视图 | 「身份绑定」页（453）：绑定关系分页检索、按用户/来源系统筛选；`open:bind:list`（开放 API 增删走机器凭证，管理端只做审计查询） | 开放平台管理员 |

## 七、用户扩展属性（一期）

接入系统差异化画像：`open_user_extend`（租户表），每用户一条 JSON 对象，**整体读写、≤4KB**（超限 400）。

| 功能点 | 说明 | 主要角色 |
| --- | --- | --- |
| 读扩展属性 | `open:user:extend-get`：GET `/open/api/user/{id}/extend` | 接入方（经开放 API） |
| 写扩展属性 | `open:user:extend-put`：PUT 同路径，JSON 对象整体覆盖 | 接入方（经开放 API） |

## 八、安全加固（二期）

应用级开关，均在「应用管理」页维护；全部拒绝均记审计日志。

| 功能点 | 说明 | 主要角色 |
| --- | --- | --- |
| 请求签名验签 | `sign_required` 开启后，`/open/api/**` 全部请求附加三个头：`X-Open-Timestamp`（毫秒时间戳，±300s 窗口可调）、`X-Open-Nonce`（一次性随机串，Redis 去重防重放）、`X-Open-Signature`（HMAC-SHA256，密钥=AppSecret 明文；签名原文=appKey/方法/路径[?query]/时间戳/nonce/body 摘要）；服务端常量时间比对 | 开放平台管理员 |
| IP 白名单 | `ip_whitelist`：精确 IP / IPv4 CIDR，逗号/分号/换行分隔；空 = 不限制 | 开放平台管理员 |
| 域名白名单 | `domain_whitelist`：裸域名或 `*.example.com` 子域通配；约束浏览器侧 Origin/Referer 来源（防页面侧滥用） | 开放平台管理员 |
| 密钥加密存储 | AppSecret AES-GCM 落库；`mse.open.crypt-key` 为加密密钥，生产必须更换（更换后历史密文不可解，需重置各应用密钥） | 实施管理员 |

## 十一、业务自注册接入专节（业务工程视角三步）

> 开放平台是统一对外窗口：凭证/目录/授权/限流/审计全部在 mse-open，业务积木只"声明我开放什么"——**业务新增开放能力 mse-open 零改动**。操作级六步（含代码）见 [open-api-guide.md](open-api-guide.md) 第二节。

| 步骤 | 业务工程做什么 | 说明 |
| --- | --- | --- |
| ① 契约 + 实现 | 自有 `xxx-api` 契约（接口 + Serializable DTO，方法签名统一 `String 方法名(String requestJson)`，操作者显式携带、不依赖 UserContext、契约不带 tenantId）+ `@RpcService` 实现（`@Bean + @ConditionalOnMissingBean` 注册） | 机器语义约定是泛化分发的前提 |
| ② Contributor Bean | 依赖 mse-open 的 `open-api` 契约 jar，声明一个 `OpenApiContributor` Bean（code/name/path/httpMethod/target 描述清单；**按 Bean 名判重**防多积木互相让位） | 描述清单即目录条目 |
| ③ 自动推送 | 应用就绪后 open-api 装配自动推送 mse-open 目录：启动即注册 + 每 `mse.open.registry.interval-minutes`（默认 5 分钟）重推自愈；多实例重推按条目业务段窗口收敛 | 可 `mse.open.registry.enabled=false` 关闭 |

**mse-open 侧接收与分发**（业务零感知）：

- 目录接收：幂等 upsert（按 code），每租户一份目录扇出播种，单世界失败等下轮推送自愈；
- 泛化分发：按目录 target（`契约接口全名#方法名`）dubbo 模式 `GenericService` 泛化调用 / 单体反射调用——**mse-open 不依赖任何业务 jar**；target 接口须落在 `mse.open.rpc.allowed-packages`（默认 `vip.mseapp.`）白名单内；
- 业务积木未部署时调用返回 503/500（目录仍在，便于感知），服务恢复自动可用，无需 mse-open 重启。

**首批已接入**：mse-oa（流程全生命周期 + Webhook）、mse-mp（粉丝/消息查询）、mse-data（调用已发布数据 API）、mse-ai（AI 对话）、mse-fs（文件上传/查询/下载/删除）。参考实现：mse-oa（oa-api + OaOpenApiContributor，全量六步）与 mse-ai（仅 Contributor，契约复用）。

## 十二、分期范围汇总

| 分期 | 模块/功能点 | 交付闭环 |
| --- | --- | --- |
| 一期（已交付） | 应用/凭证/授权/限流/审计 + 管理端五页 + 22 条内置端点 + 业务积木自注册与泛化分发 + 身份绑定/扩展属性 | 基座与业务能力以应用凭证安全开放，第三方统一窗口调用 |
| 二期（已交付） | 请求签名验签（HMAC-SHA256 + 防重放 + nonce）、IP 白名单、域名白名单、目录真租户化 | 对外暴露应用具备金融级请求防伪；目录每租户自治 |
| 三期（规划） | SSO 授权码模式（需基座登录页支持回跳参数，单独评审）、Webhook 事件订阅推送（事件边界 = 经开放 API 的变更）、`open-sdk` Java 客户端 | 免凭证化单点登录、事件反向通知、接入成本再降低 |
