## 一、规划原则（基座 RBAC 模型）

1. **三张全局表，一条链路**：`sys_micro_app`（子应用注册）→ `sys_menu`（导航菜单）→ `sys_permission`（权限点）；授权链 `sys_user → sys_user_role → sys_role → sys_role_menu / sys_role_permission`。
2. **sys_menu.type**：1=目录（本工程仅 440 一个分组目录）、3=子应用页面菜单（`micro_name` 关联子应用、`path` 为子应用内部路由）。`menu_scope=2` 租户端。
3. **权限点必须挂靠页面菜单**：`sys_permission.menu_id` 指向本工程 type=3 页面菜单，才参与角色授权分组与**租户套餐裁剪**；`menu_id=NULL` 即通用权限（登录即授予）——本工程全部权限点均挂菜单，早期安装的 NULL 权限点由脚本末段条件 UPDATE 幂等补挂。
4. **权限码格式**：`data:<模块>:<动作>`，动作小写动词（`:list` 查询 / `:save` 编辑 / `:delete` 删除 / `:run` 执行），与仓库现有 `oa:form:list` / `mes:qc:scheme:save` 等风格一致；唯一键 `uk_code`。
5. **前端按钮控制**：子应用内用 `v-permission` 指令按权限码显隐按钮（`data-ui/src/directives/permission.ts`）；选项类下拉（源表/水位列）无 `data:meta:list` 权限时静默降级为手输。
6. **落库方式**：随 jar 的幂等版本化脚本（头指令 `-- mse-target: base`，当前随仓库惯例仅 MySQL），由 starter-bridge 就绪即推 mse-system 按账本应用（周期重推自愈）——免手工执行；已应用脚本不再修改，变更一律新增版本文件。

## 五、编码规范

1. **权限码**：`data:<模块>:<动作>`——模块取 `source`（数据源）/ `sync`（集成）/ `meta`（地图）/ `service`（数据服务）/ `overview`（概览）/ `quality`（质量）/ `allow`（白名单）；动作 `list/save/delete/run/collect/export/approve/app`。新增权限点从 **9524** 顺延（alloc-tables.md 已登记 data 段 9501+）。
2. **免登录通道不走权限点**：`/openapi/data/**`（自持签名）与 `POST /open/api/data/api/invoke`（mse-open 窗口，开放目录权限码 `open:data:api-invoke` 归 mse-open 侧）均为机器调用，不经 `sys_permission`。
3. **前端 v-permission**：按钮一律挂权限码（如 `data:sync:run`）；有页面权限但缺按钮权限的角色只见列表与查询。
4. **接口侧双保险**：Controller 全量 `@SaCheckPermission(type = LOGIN_TYPE_TENANT)`；cron 预览接口接受 `data:sync:list` 或 `data:quality:list`（OR 语义，同步与质量两个表单共用）。

## 六、套餐裁剪与登记纪律

1. **租户套餐**：data 页面菜单（441-447）需在平台端「套餐管理」勾选后才对租户可见；租户管理员拿到的是「套餐域内全量权限码」，裁剪对管理员同样生效。建议七页一次配齐。
2. **网关白名单**：`/openapi/data/**` 已在 `mse-gateway.yaml` 白名单（签名调用免登录）；追加其他免登录地址时注意 Spring list 属性整体替换，须全量列出。
3. **alloc-tables.md 登记**（已完成）：后端端口 8093、前端 dev 3700、micro_app id=6、菜单段 440-447、权限段 9501-9523、网关前缀 `/data /openapi/data`（白名单 `/openapi/data/**`）。
4. **脚本纪律**：全部幂等写法（子应用按 name 判重、菜单按 id 判重、权限点按 id 判重）；早期 NULL 挂靠由脚本末段 23 条条件 UPDATE 幂等补挂（历史安装升级自愈）；已应用脚本不再修改，变更一律新增版本文件。
5. **无角色种子**：本工程 base 脚本只含子应用注册 + 菜单 + 权限点，`sys_role` 系无种子——角色与授权由租户管理员在基座界面配置（建议方案见 [03-角色规划](03-角色规划.md)）。
