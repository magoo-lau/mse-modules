# 05 配置手册（零基础版）—— 从零把数据中台跑起来

> **这本手册是给谁的**：没接触过本系统、甚至没怎么接触过服务器软件的同事——实施工程师、现场 IT、接手部署的新人。你不需要看懂代码，照着做、每步核对「✅ 成功的标志」即可。
> 配套文档：跑起来之后怎么用，看 [04-操作说明书](04-操作说明书/README.md)；技术细节与架构，看工程 [README](../README.md) 与 [docs/01-功能规划](01-功能规划.md)。

## 一、先认识几个名词（2 分钟）

| 名词 | 是什么 | 打个比方 |
| --- | --- | --- |
| **Docker** | 容器软件，把 MySQL 等软件"打包"成一键安装 | 免安装的"绿色软件"运行器 |
| **MySQL** | 数据库，所有业务数据存在这里 | 大仓库的账本 |
| **Redis** | 缓存，存登录会话、API 限流计数 | 门卫的登记本 |
| **JDK 21** | Java 运行环境，后端 jar 包需要它 | 播放器（jar 是影碟） |
| **Maven** | Java 的打包工具，把源码编译成 jar | 印刷厂 |
| **Node.js** | 前端页面的构建运行环境 | 网页的发动机 |
| **Nacos** | 微服务模式下的"配置中心 + 通讯录" | 公司前台（单体模式用不到） |
| **ODS 贴源层** | 数据中台里"原样搬运"外部库数据的一层表（ods_ 开头） | 原料仓库（原样入库，再加工从这里取） |
| **单体 / 微服务** | 两种安装形态：单体=所有功能装在一个程序里；微服务=拆成多个程序各司其职 | 便利店 vs 购物中心 |

> **新人建议选「单体」**：一个程序 + MySQL + Redis 就能跑全部功能（含数据中台）。微服务是给有运维团队的正式生产环境用的（见第八节）。

## 二、你需要准备什么

| 项 | 要求 | 说明 |
| --- | --- | --- |
| 服务器/电脑 | 4 核 8G 起步，硬盘 ≥40G | Windows / Linux 均可 |
| 软件 | Docker（推荐）或：JDK 21 + MySQL 8 + Redis + Maven 3.9+ + Node.js 20+ | 路线 A 只需 Docker |
| 软件包 | 本仓库源码（git clone 或拿到压缩包） | jar 也可以直接找开发要成品 |
| （可选）要接入的外部业务库 | MySQL / 达梦 / 金仓 / PostgreSQL 的地址、账号、口令；与部署机**网络互通** | 没有也能跑：内置「中台库」来源开箱可用 |

## 三、路线 A：容器一键部署（推荐，约 30 分钟）

### 第 1 步：安装 Docker

- Windows：安装 Docker Desktop 并启动；Linux：安装 docker + docker compose 插件。
- ✅ 成功标志：命令行执行 `docker --version` 能输出版本号。

### 第 2 步：启动数据库和缓存

命令行进入仓库的 `mse-framework/docker` 目录，执行：

```bash
docker compose up -d mysql redis
```

- ✅ 成功标志：`docker ps` 里出现 `mse-mysql`、`mse-redis` 两个容器，状态 Up（首次要等 MySQL 初始化约 1 分钟）。
- 说明：这一步会创建两个空数据库——`mse_platform`（平台控制面）和 `mse_tenant`（租户业务库），**不用你手工建表**。

### 第 3 步：启动应用（单体，含数据中台全部功能）

仍在同一目录执行（首次会构建镜像，10~20 分钟属正常）：

```bash
docker compose --profile apps up -d --build mse-monolith
```

- ✅ 成功标志：浏览器打开 `http://localhost:8080` 能看到服务应答；`docker logs -f mse-monolith` 里出现 `Started ... in xx seconds`。
- 数据中台的十四张 `dat_*` 业务表、子应用注册、菜单与 23 个权限点，都会在启动时**自动写入数据库**（业务表随启动迁移；菜单权限由推送通道自动落库），无需执行任何 SQL。

### 第 4 步：启动网页前端

前端是独立的网页工程，需要 Node.js：

```bash
cd mse-framework/mse-ui      # 基座门户（含数据中台页面）
npm install
npm run dev
```

- ✅ 成功标志：浏览器打开 `http://localhost:3000` 看到登录页。

### 第 5 步：登录平台，开通租户

1. `http://localhost:3000` 用**平台超管**登录：账号 `platform`，密码 `admin123`（正式环境务必改密码）。
2. 「租户管理」→ 新建租户 → 按向导填写，系统会自动生成该租户的管理员账号。

### 第 6 步：给租户"点亮"数据中台（关键！不勾菜单看不到系统）

用平台账号进「**套餐管理**」→ 编辑租户所用套餐 → 勾选「**数据中台**」分组下的七个页面菜单（数据概览 / 数据源管理 / 数据集成 / 数据地图 / 数据服务 / 质量监控 / 查询白名单）→ 保存。

- ✅ 成功标志：用**租户管理员**重新登录后，左侧出现「数据中台」菜单组。
- 原理：数据中台的菜单默认是"封存"的，套餐勾选是租户可见的总开关。

### 第 7 步：给员工建角色、分配权限（与 MES 等工程不同！）

> ⚠️ 数据中台**没有预置角色**（种子只有菜单与权限点）。角色由租户管理员在基座界面手工创建。

1. 用**租户管理员**登录 → 「组织管理」→「角色管理」→ 新建角色，建议建（编码自定，建议值见 [03-角色规划](03-角色规划.md)）：
   - **数据管理员**：勾选「数据中台」全部权限点（含「API 审批」）；
   - **数据分析师**：勾选概览查询、同步任务查询、元数据查询、数据导出、质量规则查询；
   - **数据服务开发者**：勾选概览查询、数据源查询、元数据查询、API 查询/编辑/删除、调用方应用管理（**不勾**「API 审批」——审批与开发分离）。
2. 「用户管理」新建员工账号并勾选对应角色（可多选）。
3. 小团队偷懒法：直接用**租户管理员账号**（天然拥有套餐域内全部权限）试用全部功能。

### 第 8 步：验收数据中台主流程

按 [04-操作说明书](04-操作说明书/README.md) 的顺序走一遍：数据源管理登记/测试 → 数据集成建任务、执行、看日志 → 数据地图登记贴源层、看详情 → 数据服务建 API、提交审批、审批发布、建应用、授权、开放调用 → 质量监控建规则、执行。走通即部署成功。

## 四、中台库初始化说明

- **业务表**：`dat_datasource` / `dat_sync_job` / `dat_meta_table` / `dat_api` 等十四张表随服务启动**自动创建**（脚本在 data-service jar 内，重复启动不重复执行；迁移失败会阻断启动，按日志修好后重启）。
- **ODS 贴源表**：不用建——第一次执行同步任务时引擎**自动建表**（`ods_` 前缀，自带 tenant_id 列）。
- **菜单/权限点**：随 jar 自动推送基座库（幂等，重复推送无害）；升级新版本 = 换新 jar 再启动，增量脚本自动补齐。

## 五、常用配置项速查（Nacos Data ID：`mse-data.yaml`）

> 微服务形态在 Nacos 修改（本地留档 `mse-modules/mse-data/docker/nacos/config/mse-data.yaml`）；单体形态这些项一般不用动，需要时在 `mse-sample/mse-monolith/src/main/resources/application.yaml` 加同名配置。

| 想改什么 | 配置 | 默认值 | 说明 |
| --- | --- | --- | --- |
| 口令加密密钥 | `mse.data.crypt-key` | 内置默认（含"please-change"字样） | 数据源口令/appSecret 的 AES-GCM 加密种子，**生产必须改**；更换后历史密文无法解密，需重新录入凭据 |
| 数据源连接池上限 | `mse.data.pool.max-pool-size` | 8 | 每个注册数据源的独立 Hikari 池上限 |
| 连接池闲置回收 | `mse.data.pool.idle-timeout-seconds` | 300 | 秒 |
| 同步单批行数 | `mse.data.sync.batch-size` | 2000 | 大表同步可调大 |
| 同步并发线程 | `mse.data.sync.executor-parallelism` | 2 | 同时执行的同步任务数 |
| 签名时间戳窗口 | `mse.data.open.signature-timeout-seconds` | 300 | 秒；消费方时钟偏差过大时调大 |
| API 默认限流 | `mse.data.open.default-per-minute` | 60 | 次/分钟（API 未单独配置时生效） |
| API 审批流开关 | `mse.data.service.approval-enabled` | true | false = API 保存即发布（小团队可用，正式环境建议开） |

环境变量：数据源/Redis 用 `MSE_MYSQL_*` / `MSE_REDIS_*`；加密密钥可用 `MSE_DATA_CRYPT_KEY` 注入；信创切换 `--spring.profiles.active=dm|kingbase`（连接信息用 `MSE_DM_*` / `MSE_KB_*`）。

## 六、外部数据源接入注意事项（现场 IT 重点）

1. **网络连通优先**：部署机要能访问每个外部库的 host:port——跨网段/防火墙时先放行端口，再到「数据源管理」点「测试」验证。
2. **账号权限最小化**：给数据中台的外部库账号建议只读（SELECT）；同步需要建表写数据的是**中台库**而非外部库。
3. **中台库自己的坐标别当外部源**：把平台主库地址登记为外部数据源会被拒绝（防呆护栏）——中台库取数走任务来源里的内置「中台库」。
4. **口令安全**：口令加密落库、界面不可回显；生产务必改 `mse.data.crypt-key` 且妥善保管（丢失 = 历史凭据全部重录）。
5. **水位列准备**：要做增量同步的源表需有**时间戳或自增 ID** 列（如 update_time / id），且业务写入会更新该列。
6. **白名单纪律**：把业务表加入「查询白名单」前确认该表含 `tenant_id` 列，否则查询会被拒绝。

## 七、常见问题排查（按现象查）

| 现象 | 先检查什么 |
| --- | --- |
| 应用启动失败，日志报数据库连接错误 | MySQL 没起/地址密码错/账号无建库权限——`docker ps` 看容器，改环境变量后重启 |
| 启动日志报"脚本执行失败"并退出 | 业务表迁移是启动强校验：按日志提示修复后重启，不要跳过 |
| 登录后左侧没有「数据中台」菜单 | 套餐没勾选数据中台菜单（第 6 步），或该用户角色没授权菜单 |
| 登录后看得到菜单但页面空白/404 | 子应用没登记或地址不对（「子应用管理」登记 `//localhost:3700` 或 `/sub-apps/data/`）；前端代理 target 指错了后端 |
| 菜单在但看不到某些按钮 | 该用户角色无此权限（按第 7 步的勾选清单补授权） |
| 数据源「测试」一直失败 | 网络/防火墙不通、账号口令错、达梦/金仓的库名应填 schema（达梦默认大写 schema、金仓独立 database + 同名 schema） |
| 同步任务执行失败 | 点「日志」看错误列：常见为源库不可达、水位列类型不支持、自定义查询投影掉了 tenant_id |
| 同步任务到点没自动跑 | cron 写错（组件有预览可核对）、任务被停用、或服务刚重启错过时点（内存态调度只补跑一次） |
| API 调用 401/403 | 签名错 / 时间戳超窗 / 授权过期 / 应用被停用——按 03 号手册第五节排查 |
| 接口报 404（微服务） | data-boot 没注册到 Nacos，或网关路由没配 `/data/**`（白名单 `/openapi/data/**` 需保留） |
| 界面/数据库中文乱码 | 建库与连接必须 utf8mb4（脚本已内置；自建库时确认字符集） |
| 更换 crypt-key 后数据源报解密失败 | 预期行为：旧密文不可解。重新录入各数据源口令与应用 Secret |

## 八、微服务形态（进阶，多服务正式环境）

> 什么时候需要：用户量大、需要独立扩缩容、有多团队维护。门外汉/试点环境用第三节的单体即可。

1. 启动 Nacos（compose 已含）：`docker compose up -d nacos`，控制台 `http://localhost:18080`。
2. 把服务专属配置写入 Nacos：
   ```bash
   CONFIG_DIR=<仓库根>/mse-modules/mse-data/docker/nacos/config sh mse-framework/docker/nacos/init-configs.sh
   ```
3. 数据源等公共配置在共享 Data ID（`mse-micro-common.yaml`、`mse-micro-db-biz.yaml`、`mse-micro-dubbo.yaml`）里管理；数据中台专属项（端口 8093、`mse.data.*`、Seata 代理开关）在 `mse-data.yaml`。
4. 构建并启动服务：先在仓库根 `mvn install -DskipTests`（框架），再 `mvn install -DskipTests -f mse-modules/mse-data/pom.xml`，最后 `java -jar data-boot/target/data-boot-1.0.0-SNAPSHOT.jar`（注册进 Nacos，`http://localhost:8093`）。
5. 网关路由：确认 `mse-gateway.yaml` 里有 `/data/** → lb://mse-data`，且白名单含 `/openapi/data/**`（签名调用免登录，删了开放调用就 401）；前端开发代理 target 改为网关地址（默认 48080）。
6. 可选开关：RocketMQ（`mq-starter` + name-server 地址）、独立库租户（平台端「租户数据源」界面维护，免重启）、信创数据库（启动参数 `--spring.profiles.active=dm` 或 `kingbase`）。

## 九、前端（数据中台子应用）的两种跑法

数据中台网页不是独立网站，而是"挂"在基座门户里的子应用（微前端），基座前端已内置兜底注册：

1. **开发调试**：`cd mse-modules/mse-data/data-ui && npm install && npm run dev`，启动在 `http://localhost:3700`（dev 代理默认指向单体 8080；调 data-boot 时改 vite.config.ts 的 target 为 `http://localhost:8093`）；在基座「子应用管理」确认 data 的开发地址为 `//localhost:3700`，刷新门户即可嵌入使用。
2. **正式部署**：`npm run build`（已内置 `--base=/sub-apps/data/`），产物部署到基座 nginx 的 `/sub-apps/data/` 路径，子应用登记为生产地址 `/sub-apps/data/`。

> 前提：第 6 步的套餐勾选已完成，否则页面登记了也看不见菜单。

## 十、上线前检查清单

- [ ] 修改所有默认密码（platform/admin123、数据库 root、Redis 密码）
- [ ] **修改 `mse.data.crypt-key`**（口令加密密钥，内置默认值仅用于演示）并妥善保管
- [ ] `mse.data.service.approval-enabled` 保持 true（API 发布需审批）——除非明确接受免审批
- [ ] 数据库开启每日备份（mysqldump 或云快照）
- [ ] 前端走 HTTPS 与正式域名；子应用登记改为生产地址 `/sub-apps/data/`
- [ ] 微服务形态：Nacos 开鉴权、网关白名单仅保留必需项（`/openapi/data/**` 按需保留）
- [ ] 外部数据源账号最小权限（只读）、网络走内网/专线
- [ ] 建 3 个角色（管理员/分析师/开发者）并把「API 审批」与管理员/审批人绑定，验证审批流走通
- [ ] 用 [04-操作说明书](04-操作说明书/README.md) 主流程跑通一遍（登记→同步→地图→API→质量）
- [ ] 记录本次部署的版本号与日期，便于后续升级追查
