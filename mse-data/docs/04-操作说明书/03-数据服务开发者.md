# 03 数据服务开发者操作手册

> 角色：`data_developer`（建议编码）｜数据范围：本租户全部数据｜菜单：数据概览、数据源管理（只读）、数据地图（只读）、数据服务。
> 定位：**把数据变成 API**——定义查询 API 并试运行验证，走审批流发布，管理调用方应用与授权，并对接第三方消费方完成签名调用联调。API 审批由数据管理员或数据审批人执行。

## 一、职责与页面清单

| 职责 | 页面 |
| --- | --- |
| API 定义（SQL 模板、参数、分页、限流）、试运行、提交审批、下线 | 数据服务 → API 管理 |
| 调用方应用建管（AppKey/AppSecret、启停、重置密钥） | 数据服务 → 调用方应用 |
| API 授权（批量授权、过期时间、改期、收回） | 数据服务 → 调用方应用 |
| 调用日志排查 | 数据服务 → 调用日志 |
| 确认表/列名与数据样本（只读） | 数据地图 |
| 确认来源数据源可用（只读） | 数据源管理 |

> 你**没有**的操作：「审批」按钮不可见（`data:service:approve` 归审批角色）；数据源/任务/白名单的编辑归数据管理员。

## 二、API 开发全流程（典型五步）

### 第 1 步：确认数据与口径

1. **数据地图**确认目标表（优先 `ods_` 贴源表）的列名、类型、注释，必要时「采样」核对数据内容。
2. 写好查询 SQL 草稿：**仅 SELECT**；参数用 `:name` 占位（如 `WHERE status = :status`）；`:param` 不要出现在字符串字面量里；不支持 FROM 派生表/UNION/WITH——复杂加工请先在 ODS 层完成。

### 第 2 步：新建 API

> 路径：数据中台 → **数据服务 → API 管理** → 「新建 API」。

| 字段 | 填写要点 |
| --- | --- |
| 名称 | 业务语义命名（如：订单日汇总查询） |
| 开放路径 | 小写字母开头，如 `order-daily`；最终端点 `/openapi/data/order-daily`，**租户内唯一** |
| 数据源 | 「中台贴源层（仅 ods_ 表，自动隔离租户）」或某个外部源 |
| SQL 模板 | 仅 SELECT；`:name` 占位；示例：`SELECT code, cfg_value FROM ods_sys_config WHERE cfg_key = :key` |
| 参数定义 | JSON 数组，如 `[{"name":"key","type":"string","required":true,"remark":"配置键"}]` |
| 分页 | 开启后调用方可传 pageNum/pageSize，系统自动包裹分页 |
| 行数上限 | 单次返回行数上限（默认 1000，最大 100000） |
| 超时(ms) | 查询超时（默认 10000） |
| 次/分钟 | 限流；0 = 跟随全局默认（60 次/分钟） |

### 第 3 步：试运行

1. 列表行内点「**试运行**」，输入参数 JSON（如 `{"key":"mse.name"}`）→「执行」。
2. 弹窗返回行数、耗时与结果表格——发布前把典型参数、空参数、边界参数各试一遍。
3. 报错对照：语法/非 SELECT 会被 SQL 防护拒绝；缺必填参数按参数定义提示。

### 第 4 步：提交审批 → 发布

1. 草稿态点「**提交审批**」，状态变为「待审批」。
2. 由数据管理员/审批人在「审批」对话框选**通过并发布**或**驳回**（可填意见）；全过程在「记录」里留痕（提交/通过/驳回/下线 + 操作人 + 时间）。
3. **已发布 API 一旦编辑自动打回草稿并下线**——修改已上线 API 前先与消费方约定窗口，改完重新走审批。
4. 下线：已发布 API 点「下线」即停止对外服务（回到草稿，可再提交）。
5. 部署侧若关闭了审批流（`mse.data.service.approval-enabled=false`），保存即发布，无第 4 步。

### 第 5 步：授权与联调（见第三节、第四节）

## 三、调用方应用与授权

> 路径：数据服务 → **调用方应用**。

### 3.1 新建应用

1. 「**新建应用**」：应用名称 + 备注 → 保存。
2. 弹窗展示 **AppKey / AppSecret**——**仅显示一次，关闭后不可再看**；请当场交给消费方并各自妥善保管（Secret 加密落库，丢失只能重置）。
3. 「**重置密钥**」：旧密钥立即失效，重置后把新 Secret 同步给消费方。

### 3.2 授权 API

1. 行内点「**授权(N)**」打开授权管理。
2. 上部下拉**多选** API（可批量；已授权的带 [已授权] 标记），选**过期时间**（留空=永久）→ 点「授权」。
3. 已授权重复授权即**刷新过期时间**；列表内可单行「**改期**」（留空保存=恢复永久）与「**收回**」。
4. 过期授权带红色「已过期」标识——到期后开放调用即被拒绝（403「授权已过期」），提前与消费方续期。

### 3.3 调用排查

「调用日志」页签：API、应用、参数、返回行数、耗时、成功/失败、错误信息、来源 IP、时间。消费方报障时按 AppKey 时间段检索，失败原因（签名错/授权过期/限流/超时）在错误列可见。

## 四、消费方对接（开放调用规范）

把以下内容交给第三方系统即可完成对接（**免登录**，网关白名单 `/openapi/data/**`）：

1. **端点**：`POST /openapi/data/{path}`（单体 `http://<host>:8080`；微服务走网关 `http://<host>:48080`；直连 data-boot 亦可 `http://<host>:8093`）。
2. **请求头**：

| 头 | 值 |
| --- | --- |
| X-App-Key | 授权的 AppKey |
| X-Timestamp | 秒级时间戳（窗口默认 ±300 秒） |
| X-Nonce | 随机串（防重放，每次不同） |
| X-Sign | 签名（见下） |

3. **签名算法**：`HMAC-SHA256(appSecret, appKey + "\n" + timestamp + "\n" + nonce)`，十六进制小写。
4. **请求体**：`{"params":{"status":"0"},"pageNum":1,"pageSize":20}`（分页仅 API 开启分页时生效）。

```bash
# 签名与调用示例（bash）
TS=$(date +%s); NONCE=$(uuidgen)
SIGN=$(python3 -c "import hmac,hashlib;print(hmac.new(b'$SECRET',f'$APPKEY\n$TS\n$NONCE'.encode(),hashlib.sha256).hexdigest())")
curl -X POST "http://<host>/openapi/data/order-daily" \
  -H "X-App-Key: $APPKEY" -H "X-Timestamp: $TS" -H "X-Nonce: $NONCE" -H "X-Sign: $SIGN" \
  -H "Content-Type: application/json" \
  -d '{"params":{"status":"0"},"pageNum":1,"pageSize":20}'
# 返回：{"code":0,"message":"ok","data":{"columns":[...],"rows":[...],"hasMore":false,"costMs":12}}
```

5. **mse-open 统一窗口（新接入建议）**：消费方也可不经自持签名，走开放平台 `POST /open/api/data/api/invoke`（请求体 `{"apiPath":"...","params":{...}}`），凭证、限流、审计由开放平台统一管理。

## 五、常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 保存 API 报「仅允许 SELECT」 | SQL 模板含写操作或派生表/UNION/WITH。改成纯 SELECT，复杂加工先落 ODS。 |
| 调用返回签名错误 | 签名串拼接顺序错（必须是 `appKey\ntimestamp\nnonce`）、大小写/编码不一致、或两端时钟偏差超 300 秒。 |
| 调用返回 403 授权已过期 | 授权设了过期时间且已到。「调用方应用 → 授权」改期或重新授权。 |
| 调用返回 404 | API 未发布（草稿/待审批/被编辑打回）、开放路径拼写不符，或 API 已下线。 |
| 调用返回限流错误 | 超过「次/分钟」上限（未配置时为全局默认 60）。提高 API 限流值或让消费方退避重试。 |
| 编辑后调用方突然 404 | 编辑已发布 API 自动打回草稿。重新提交审批、发布后恢复。 |
| 中台贴源层 API 查不到数据 | 该表本租户无数据：确认同步任务已执行且日志成功（自动注入租户条件，只返回本租户行）。 |
| 想让 API 直查某张业务表 | 中台贴源层仅放行 `ods_` 表 + 白名单表。请数据管理员在「查询白名单」登记该表（须含 tenant_id 列）。 |
| 换了个租户账号建 API，互相看不到 | 数据按租户隔离，正常设计。每个租户独立维护自己的 API 与应用。 |
