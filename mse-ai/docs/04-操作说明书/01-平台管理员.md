# 01 平台管理员操作手册

> 身份：**平台账号**（平台运营方，tenant_id=0 平台世界）｜菜单：平台门户内的「AI 服务」全部页面。
> 定位：维护**出厂模板资产**——平台世界的模型行、平台公共智能体与工具行；签发归属各租户的开放 API 密钥；查看全局用量。
> 关键认知：平台世界的数据是「出厂模板」——**新租户开通时自动复制为该租户的自有副本**；租户开通后副本由租户自治，你在平台侧的后续修改**不会**自动同步到已开通的租户。

## 一、职责与页面清单

| 职责 | 页面 |
| --- | --- |
| 维护平台世界模型行（作为新租户的播种模板），核对模型通道可用 | 模型管理 |
| 维护平台公共智能体（通用助手、OA 系列助手、数据分析师等出厂模板） | 智能体管理 |
| 核对系统工具平台行（内置 / 本地 / RPC 自动登记）状态 | 工具中心 |
| 签发 / 管理开放 API 密钥（选择租户归属）、登记外部 MCP Server | 开放能力 |
| 查看全部租户的全局用量 | 用量统计（全局） |

## 二、模型管理（出厂模板源）

> 路径：AI 服务 → **模型管理**。平台账号登录看到的是平台世界的模型行。

### 2.1 典型流程：新增一个出厂对话模型

1. 点「**新增模型**」：先选**模型类型**——「对话模型」（供智能体绑定）。
2. 选**供应商**（DeepSeek / 智谱 GLM / Kimi / 通义千问 / OpenAI / Anthropic Claude / Ollama / 讯飞星火 / 自定义兼容）：端点与接口类型自动带出，可下拉改选或手改（如 DeepSeek 选 Anthropic 兼容端点则接口类型切为 Claude 原生协议）。
3. 填模型名（如 `deepseek-chat`）与 **API Key**（保存后加密存储，界面上不再明文回显）。
4. 点「**测试**」：真实调用一次，显示成功 / 失败与原因。**测试通过再保存启用**。
5. （可选）配「**备用模型**」：选另一个对话模型，主模型网络抖动 / 限流时自动切换，用户无感。

### 2.2 向量模型与重排模型（知识库用）

- 需要 RAG 的模板另建一行：模型类型选「**向量模型**」或「**重排模型**」（一行只表达一种能力）。
- 向量模型点「**设默认**」作为出厂默认（测试会回显向量维度）；注意 DeepSeek 无向量端点，向量模型常配智谱 `embedding-3` 或本地 Ollama（如 `nomic-embed-text`）。

### 2.3 模板与副本的关系（重要）

- 新租户开通时：平台世界全部启用中的模型行自动复制为该租户自有副本（含端点与密文），租户可自行改 Key、改配——此后**两边互不影响**。
- 存量租户想用你新配的模型：请租户管理员照同一参数在本租户「模型管理」自行新增（他们改自己的 Key 计费，这正是租户自管的设计意图）。

## 三、智能体管理（平台公共智能体维护）

> 路径：AI 服务 → **智能体管理**。平台视角的列表即平台公共智能体模板。

- 出厂已有 6 个模板：**通用助手**、**OA 审批助手**、**OA 流程生成器**、**OA 智能填单**、**OA 流程机器人**、**数据智能分析师**。它们会在每个新租户开通时复制为该租户可编辑的自有副本。
- 日常只做两类事：
  1. **修模板**：优化出厂智能体的提示词 / 绑定 / 开场白后保存并「发布」——只影响之后新开通的租户；已开通租户的副本不回灌。
  2. **新建平台级模板**：为即将批量推广的场景建好智能体模板并发布，随租户开通自动下发。
- 绑定模型时下拉里出现的是平台世界模型行；**出厂模板一般不绑定具体模型**（空 = 租户侧按其默认模型解析），这样各租户用自己的模型跑同一个模板。
- 想验证模板效果：新建一个**草稿智能体**绑上平台模型，在画布「试运行」或对话工作台实测（平台账号的对话走平台世界模型），验证通过再发布。

## 四、工具中心（平台行核对）

> 路径：AI 服务 → **工具中心**。平台视角看到内置 / 本地 / RPC 来源的系统工具平台行。

- 这些行由系统**自动登记**（业务服务上线后自动推送），**不要手工删除**——删除后会自动回来；要下线某工具用「**停用**」。
- 可以做：查看 / 检索、停用 / 启用、点「**测试**」验证某业务工具是否健康（按参数说明填入参或直接粘 JSON）、看「调用日志」排查智能体调用失败原因。
- 租户自建的外部工具（HTTP / Dify）属各租户自有，平台列表中不可见、互不干扰。

## 五、开放能力（API Key 归属签发 + MCP）

> 路径：AI 服务 → **开放能力**。上半「API Key」，下半「MCP Server」。

### 5.1 给第三方系统签发密钥

1. 点「**签发密钥**」：填写应用标识、**归属租户**（下拉选择——第三方以该 Key 调用时的数据与用量都记在该租户名下）、每分钟调用上限、备注。
2. **智能体白名单**：从目标租户的已发布智能体里多选（留空 = 放行全部已发布智能体）。
3. 保存后弹窗一次性显示 **App ID 与 API Key**——当场交给对方，关闭后不再显示；丢失只能停用重发。
4. 之后可随时「停用 / 删除」，立即生效。

### 5.2 外部 MCP Server 登记

- 点「新增」：填名称（唯一）、服务地址、SSE 路径（默认 /sse）、传输方式，保存后点「**测试**」验证连通。
- 连通后该 Server 的工具会以「MCP 工具」出现在各租户智能体的工具下拉里。

## 六、用量统计（全局）

> 路径：AI 服务 → **用量统计（全局）**。跨租户汇总视图，用于平台运营：

- 按时间 / 通道（页面对话 / 业务系统调用 / 开放接口）/ 智能体 / 模型筛选用量流水（tokens 与耗时）；
- 结合汇总核对各租户消耗，作为计费 / 配额 / 模型选型的依据；
- 本页只读，不影响任何租户数据。

## 七、平台管理员注意事项

1. **模板思维**：平台世界的模型 / 智能体改了只影响「新租户」，存量租户副本自治——重大模板升级需另通知各租户管理员。
2. **密钥纪律**：API Key 明文仅签发时可见，登记台账在平台侧保存 App ID 与用途；离职 / 换供应商立即停用旧 Key。
3. **测试先行**：任何模型行 / 工具改动先点「测试」，避免把不可用模板播种给新租户。
4. **不要在平台世界配置「给某租户专用」的东西**：租户专属模型 / 智能体应由该租户管理员在自己的「模型管理 / 智能体管理」里建。
