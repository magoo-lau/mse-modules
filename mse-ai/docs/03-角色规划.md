# 03 角色规划 —— 角色定义、授权矩阵与数据权限

> mse-ai 的角色与授权设计。权限点 id / code 见 [02-权限规划](02-权限规划.md) 第二节与第四节，功能点含义见 [01-功能规划](01-功能规划.md)。
> **本工程无角色种子**（`db/mysql/` 三个脚本均不含 `sys_role` 数据）——本文角色为**建议角色**，由实施 / 租户管理员在基座「角色管理」按需创建并授权，已逐条给出建议授权明细作为直接输入。

## 一、角色模型说明

1. **全部为租户级角色**：AI 服务 8 个页面菜单全部 `menu_scope=2` 租户端，不涉及租户端之外的角色分工；平台侧操作（平台世界模型 / 智能体 / 全局用量）以平台账号登录使用同组页面。
2. **租户超管不依赖角色**：`sys_user.super_admin=1` 的租户管理员天然拥有套餐域内全量权限码，可包办本清单全部角色；建议角色面向**分工治理**——把「建模型 / 编智能体」与「日常用 AI」分离，避免人人可改提示词、删知识库。
3. **角色受套餐裁剪约束**：即使授予 AI 管理员角色，其权限也以租户套餐勾选的 AI 服务菜单（461-468）为上界（见 [02-权限规划](02-权限规划.md) 第六节）。
4. **角色是授权集合不是数据边界**：ai_* 数据的可见范围由「会话世界」决定（见第五节），角色只决定能操作哪些功能；同一角色在不同租户互不可见数据。
5. **消费方映射**：业务工程（oa / mes 等）的「AI 能力开关 + 场景 → 智能体映射」由其自有页面与 sys_config 参数承载（如 `oa.ai.mode` / `mes.ai.mode`），与本清单角色互不干扰；mse-ai 侧只需保证被映射的智能体处于「已发布」状态。

## 二、角色清单（3 个建议角色）

| 角色（建议编码） | 建议名称 | 建议数据范围 | 定位 | 落库情况 |
| --- | --- | --- | --- | --- |
| `ai_admin` | AI 平台管理员 | 全部 | 模型 / 智能体 / 知识库 / 工具 / 开放能力全量管理，包办建设与治理 | **未落库，建议角色** |
| `ai_builder` | AI 应用建设者 | 全部 | 面向业务专家：编排智能体 / 维护知识库 / 自建外部工具，不动模型与 API Key | **未落库，建议角色** |
| `ai_user` | AI 普通用户 | 仅本人（会话私有） | 对话工作台问答、只读用量，不改任何配置 | **未落库，建议角色** |

> 建议 data_scope：管理员 / 建设者用「全部（1）」（其管理对象 ai_agent / ai_model 等本就世界内全量）；普通用户用「仅本人（5）」——对话会话 `ai_chat_session.user_id` 归属个人，列表天然按用户过滤，data_scope 仅作兜底语义。
> 角色创建路径：租户管理员 → 基座「组织管理 → 角色管理」→ 新建（按上表编码）→ 勾选菜单与权限点（明细见第四节）。

## 三、角色 × 模块授权矩阵

图例：**●** 完整操作　**◐** 受限操作（见第四节明细）　**▲** 只读　**—** 无权限

| 模块（menu_id） | AI 平台管理员 | AI 应用建设者 | AI 普通用户 |
| --- | --- | --- | --- |
| 对话工作台（461） | ● | ● | ● |
| 智能体管理（462） | ● | ●（不可删他人正在引用的智能体时自控） | — |
| 知识库（463） | ● | ● | — |
| 工具中心（464） | ● | ◐（可自建 HTTP/Dify，管理动作受限） | — |
| 用量统计（465） | ● | ▲ | ▲（仅本人流水） |
| 模型管理（466） | ● | — | — |
| 开放能力（467） | ● | — | — |
| 用量统计-全局（468） | ●（或仅平台侧持有） | — | — |

设计要点：

- **建设与使用分离**：普通用户只拿 461（含 8009 `ai:chat:use`）+ 465 只读；模型 Key、API Key、MCP 等敏感配置收敛在 `ai_admin`。
- **画布编排随 462**：画布编辑器 / 试运行 / DSL 导入导出是智能体管理页的内部路由，不单独设菜单；试运行（`ai:agent:save`）与运行历史（`ai:agent:list`）分别挂在 8007 / 8006 上，授权 462 即随行。
- **知识库上传单列**：`ai:kb:upload`（8012）独立于 `ai:kb:save`（8011），如需「只能传文档不能改库配置」的资料员细分角色，按第四节明细裁剪即可（建议角色不单设）。
- **468 全局用量属平台视角**：租户侧一般不授（除非需要租户内跨部门用量治理角色）；平台账号天然可查。

## 五、数据权限（平台端 / 租户端双世界）

| 场景 | 规则 | 依据 |
| --- | --- | --- |
| 会话与消息 | 用户私有：会话按 `user_id` 归属，他人不可见（同租户管理员也不经列表互看） | `ai_chat_session.idx_tenant_user` |
| 租户世界资源 | 智能体 / 模型 / 工具 / MCP / API Key / 知识库 / 用量：租户内共享管理、跨租户绝对隔离 | 全部 ai_* 表带 tenant_id 行级隔离；独立库租户经 `@TenantDatasource` 路由专属库 |
| 平台世界（tenant_id=0） | 平台账号登录后的同组页面读写平台世界自有行：平台模型 / 平台智能体 / 系统工具平台行 / 全局用量——**平台端无独立 AI 菜单登记**，页面经 side=3 双端兜底访问 | 控制器对模型 / 开放能力 / 全局用量放行 `LOGIN_TYPE_PLATFORM` |
| 出厂种子副本 | 租户开通时播种 6 个智能体 + 平台模型行 + 平台工具行的自有副本（副本 id = 源 id + 租户号低 8 位 ×1000，kb_ids 置空）；**副本自治**：平台侧后续修改不回灌存量租户 | `V20261001_03_ai__tenant_seed.sql`（mse-per-tenant: true） |
| 向量数据 | Milvus 集合标量过滤 `tenantId/kbId` 收口，跨租户检索不可达 | `mse_ai_kb_<modelId>` schema |
| 开放 API 调用 | 第三方 Key 绑定租户归属：调用即建立该租户上下文，可见范围 / 用量记账均归该租户 | `ai_api_key.tenant_id` |
| 跨租户 | 一律由租户插件行级隔离，与角色无关 | 多租户基线 |

## 六、种子落库情况

1. **无角色种子**：`sys_role` / `sys_role_menu` / `sys_role_permission` 在本工程脚本中不存在——实施时按第二节清单在目标租户手工创建（或由基座侧统一模板另发版本脚本，需新增版本文件、不改已应用脚本）。
2. **菜单与权限点已落库**：`V20261001_01_ai__ai_base.sql`（mse-target: base）由 starter-bridge 推送 mse-system，经租户库车队重放落共享主库与各独立租户库，免手工执行。
3. **业务与种子已落库**：`V20261001_02_ai__ai_init.sql`（master）建 15 张 ai_* 表并种入平台公共智能体与 oa_flow / data_query 工具登记；`V20261001_03_ai__tenant_seed.sql`（mse-per-tenant: true）在租户开通 / 懒初始化时按租户播种副本并改写绑定引用。
4. **授权验证路径**：租户管理员登录 → 角色管理建角色 → 勾选「AI 服务」菜单组与第四节权限点 → 给用户授角色 → 用户登录确认侧边栏出现「AI 服务」分组且页面无 403。
