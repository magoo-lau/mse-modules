# 05 配置手册（零基础版）—— 从零把 AI 平台跑起来

> **这本手册是给谁的**：没接触过本系统、甚至没怎么接触过服务器软件的同事——实施工程师、现场 IT、接手部署的新人。你不需要看懂代码，照着做、每步核对「✅ 成功的标志」即可。
> 配套文档：跑起来之后怎么用，看 [04-操作说明书](04-操作说明书/README.md)；功能与架构细节，看工程 [README](../README.md) 与 [docs/01-功能规划](01-功能规划.md)。

## 一、先认识几个名词（2 分钟）

| 名词 | 是什么 | 打个比方 |
| --- | --- | --- |
| **Docker** | 容器软件，把 MySQL 等软件"打包"成一键安装 | 免安装的"绿色软件"运行器 |
| **MySQL** | 数据库，所有业务数据（含 AI 的智能体、会话记录）存在这里 | 大仓库的账本 |
| **Redis** | 缓存，存登录会话等临时数据 | 门卫的登记本 |
| **JDK 21** | Java 运行环境，后端 jar 包需要它 | 播放器（jar 是影碟） |
| **Nacos** | 微服务模式下的"配置中心 + 通讯录" | 公司前台（单体模式用不到） |
| **Milvus** | 向量数据库：把文档切成小段算出"语义指纹"存起来，AI 才能按意思检索（知识库 RAG 用，可选） | 图书馆的索引卡片柜 |
| **大模型 API Key** | 大模型服务商（DeepSeek / 智谱等）发给你的"充电卡"，AI 平台靠它调用模型 | 充值卡（有 Key 才能对话） |
| **单体 / 微服务** | 两种安装形态：单体=所有功能装在一个程序里；微服务=拆成多个程序各司其职 | 便利店 vs 购物中心 |
| **SSE 流式** | AI 回答逐字往外蹦的技术，像打字机 | 现场直播 vs 事后发稿 |

> **新人建议选「单体」**：一个程序 + MySQL + Redis 就能跑全部功能（含 AI 平台）。微服务是给有运维团队的正式生产环境用的（见第九节）。

## 二、你需要准备什么

| 项 | 要求 | 说明 |
| --- | --- | --- |
| 服务器/电脑 | 4 核 8G 起步，硬盘 ≥40G（开知识库 RAG 再加 10G） | Windows / Linux 均可 |
| 软件 | Docker（推荐）或：JDK 21 + MySQL 8 + Redis + Maven 3.9+ + Node.js 20+ | 路线 A 只需 Docker |
| 软件包 | 本仓库源码（git clone 或拿到压缩包） | jar 也可以直接找开发要成品 |
| **模型服务账号** | 任一大模型服务商账号并**充值拿 API Key**（DeepSeek / 智谱 / Kimi / 通义 / OpenAI / Claude / 本地 Ollama 均可） | 没有它 AI 无法对话——这是 AI 平台区别于其他模块的硬前置 |
| 知识库 RAG（可选） | Docker 起 Milvus（本工程自带部署文件） | 不开 RAG 可跳过，对话功能不受影响 |

## 三、路线 A：容器一键部署（推荐，约 30 分钟）

### 第 1 步：安装 Docker

- Windows：安装 Docker Desktop 并启动；Linux：安装 docker + docker compose 插件。
- ✅ 成功标志：命令行执行 `docker --version` 能输出版本号。

### 第 2 步：启动数据库和缓存

命令行进入仓库的 `mse-framework/docker` 目录，执行：

```bash
docker compose up -d mysql redis
```

- ✅ 成功标志：`docker ps` 里出现 `mse-mysql`、`mse-redis` 两个容器，状态 Up（首次要等 MySQL 初始化约 1 分钟）。
- 说明：自动创建 `mse_platform`（平台控制面）与 `mse_tenant`（租户业务库）两个空库，**不用手工建表**。

### 第 3 步：启动应用（单体，含 AI 平台全部功能）

单体聚合工程 mse-monolith 已内置 AI 业务积木，仍在同一目录执行（首次构建镜像 10~20 分钟属正常）：

```bash
docker compose --profile apps up -d --build mse-monolith
```

- ✅ 成功标志：浏览器打开 `http://localhost:8080` 有服务应答；`docker logs -f mse-monolith` 里出现 `Started ... in xx seconds`。
- AI 的业务表、6 个出厂智能体（通用助手等）、工具登记都会在启动时**自动写入数据库**，无需执行任何 SQL。
- 生产环境务必改加密密钥：在 compose 的 `mse-monolith.environment` 段（或 docker run -e）加一条 `MSE_AI_CRYPT_KEY: 你的随机长字符串`——它用于加密存储模型 API Key，**换了它旧 Key 将无法解密**，定了就不要再改。

### 第 4 步：启动网页前端

```bash
cd mse-framework/mse-ui      # 基座门户（含 AI 服务页面）
npm install
npm run dev
```

- ✅ 成功标志：浏览器打开 `http://localhost:3000` 看到登录页。

### 第 5 步：登录平台，开通租户

1. `http://localhost:3000` 用**平台超管**登录：账号 `platform`，密码 `admin123`（正式环境务必改密码）。
2. 「租户管理」→ 新建租户 → 按向导填写，自动生成该租户管理员账号。
3. 租户开通时 AI 平台会**自动播种**该租户的出厂资产副本：6 个智能体（通用助手、OA 审批助手、OA 流程生成器、OA 智能填单、OA 流程机器人、数据智能分析师）+ 平台模型行副本 + 系统工具副本——租户拿到即可编辑使用。

### 第 6 步：给租户"点亮"AI 服务（关键！不勾菜单看不到系统）

用平台账号进「**套餐管理**」→ 编辑租户所用套餐 → 勾选「**AI 服务**」分组下的页面菜单（对话工作台 / 智能体管理 / 知识库 / 用量统计 / 模型管理 / 工具中心 / 开放能力）→ 保存。

- ✅ 成功标志：用**租户管理员**重新登录后，左侧出现「AI 服务」菜单组。
- 原理：菜单默认"封存"，套餐勾选是租户可见的总开关；权限点随菜单一并圈定。

### 第 7 步：创建 AI 角色并授权（可选但推荐）

本工程**没有预置角色**，按以下建议在租户侧「角色管理」创建：

| 角色编码 | 角色名称 | 授权 |
| --- | --- | --- |
| `ai_admin` | AI 平台管理员 | 「AI 服务」全部菜单 + 全部权限点 |
| `ai_builder` | AI 应用建设者 | 对话工作台 / 智能体管理 / 知识库 / 工具中心 / 用量统计（不给模型管理、开放能力） |
| `ai_user` | AI 普通用户 | 对话工作台（+ 用量统计只读，可选） |

给用户勾上对应角色即可。明细对照表见 [03-角色规划](03-角色规划.md) 第四节。

### 第 8 步：配模型通道（第一个人工配置步骤，必做）

用租户（或平台）管理员登录 → 「AI 服务 → **模型管理**」→ 新增模型：

1. 选**模型类型**：对话模型（智能体用）/ 向量模型（知识库用）/ 重排模型（知识库精排用）——一行只表达一种能力。
2. 选**供应商**：端点自动带出（如 DeepSeek `https://api.deepseek.com`）；填模型名（如 `deepseek-chat`）与你的 **API Key**。
3. 点「**测试**」——✅ 成功标志：提示连通成功（向量模型会回显维度）。
4. 需要知识库时：另建一行「向量模型」（DeepSeek 无向量端点，可配智谱 `embedding-3` 或本地 Ollama `nomic-embed-text`）并点「**设默认**」。

### 第 9 步：验收

租户管理员或普通用户登录 → 「AI 服务 → 对话工作台」→ 选「通用助手」问一句话 → ✅ 成功标志：流式回答正常输出。再按 [04-操作说明书](04-操作说明书/README.md) 走一遍智能体编排。

## 四、开启知识库 RAG（可选）

1. 启动向量库（本工程自带部署文件，Milvus 2.6 系列，含 etcd / MinIO）：

   ```bash
   docker compose -f mse-modules/mse-ai/docker/milvus/compose.yaml up -d
   ```

   ✅ 成功标志：`docker ps` 出现 `mse-milvus`、`mse-milvus-etcd`、`mse-milvus-minio`。
2. 给应用加环境变量 `MSE_AI_MILVUS_ENABLED=true`（容器改 compose 的 environment 段；jar 直启用 `-e` 或启动参数），地址默认 `localhost:19530`（可用 `MSE_MILVUS_HOST / MSE_MILVUS_PORT` 覆盖），重启应用。
3. 页面验证：「知识库」页顶部向量库状态提示正常 → 建库 → 传文档 → 状态变「完成」→ 检索测试有结果。
4. （可选）精排：模型中心建「重排模型」行（OpenAI 兼容 /rerank 协议，如硅基流动 bge-reranker），在知识库里绑定。
5. （可选）原文件归档走文件服务：部署 mse-fs 即自动启用（默认 auto，未部署自动落本地目录，无需配置）。

## 五、常用配置项速查

> 单体：`mse-sample/mse-monolith/src/main/resources/application.yaml` 或环境变量；微服务：Nacos 的 `mse-ai.yaml`（留档在 `mse-modules/mse-ai/docker/nacos/config/`）。

| 想改什么 | 环境变量 / 配置 | 默认值 | 说明 |
| --- | --- | --- | --- |
| 数据库 / 缓存地址 | `MSE_MYSQL_HOST` / `MSE_REDIS_HOST` | localhost | 与基座共用 |
| **AI 密钥加密Key** | `MSE_AI_CRYPT_KEY` | 出厂默认串 | **生产必改且不再变更** |
| 服务端口（微服务） | `mse-ai.yaml` 的 `server.port` | 8094 | 单体不占独立端口 |
| 知识库向量库开关 | `MSE_AI_MILVUS_ENABLED` | false | true 时知识库可向量化检索 |
| Milvus 地址 | `MSE_MILVUS_HOST` / `MSE_MILVUS_PORT` | localhost / 19530 | |
| 对话失败自动重试 | `mse.ai.chat-retry-times` | 2 | 瞬态错误退避重试次数，0=不重试 |
| 会话记忆窗口 | `mse.ai.memory-window` | 40 | 最近 N 条消息送入模型 |
| 单体前端代理 | `ai-ui/vite.config.ts` 的 target | http://localhost:8080 | 微服务改网关 48080 |

> 全部建表、种子、升级**随启动自动执行**（版本化脚本，重复启动不重复执行）；升级 = 换新 jar 重启。

## 六、对接第三方系统（开放 API，可选）

1. 管理员登录 → 「AI 服务 → **开放能力**」→ 签发密钥：App ID、归属租户、每分钟限流、智能体白名单 → **当场保存弹窗里的 App ID 与 API Key**（仅显示一次）。
2. 把接口文档给对方：`POST {网关}/openapi/ai/chat`，请求头 `X-App-Id` 与 `X-Api-Key`，报文 `{"agentCode":"...","message":"..."}`；另有智能体列表与流式接口。
3. 若集团已部署开放平台（mse-open），AI 对话能力已自动注册进其「API 目录」，凭证 / 授权 / 限流在开放平台侧统一管理，二选一即可。
4. 对外暴露 MCP 协议（供外部 AI 客户端接入）：配置 `MSE_AI_MCP_SERVER_ENABLED=true` 后重启。

## 七、微服务形态（进阶，正式环境）

1. 启动 Nacos（基座 compose 已含）：`docker compose up -d nacos`，控制台 `http://localhost:18080`。
2. 导入 AI 服务专属配置：
   ```bash
   CONFIG_DIR=<仓库根>/mse-modules/mse-ai/docker/nacos/config sh mse-framework/docker/nacos/init-configs.sh
   ```
   数据源 / Redis / Dubbo 等公共项在共享 Data ID（`mse-micro-common.yaml`、`mse-micro-db-biz.yaml`、`mse-micro-dubbo.yaml`）里管理；端口 8094 与 `mse.ai.*` 专属项在 `mse-ai.yaml`。
3. 构建：先仓库根 `mvn install -DskipTests`（框架），再 `mvn install -DskipTests -f mse-modules/mse-ai/pom.xml`；启动 `java -jar mse-modules/mse-ai/ai-boot/target/ai-boot-1.0.0-SNAPSHOT.jar`（自动注册 Nacos）。
4. 网关路由：确认 `mse-gateway.yaml` 留档有 `/ai/**` 与 `/openapi/ai/**`（白名单 `/openapi/ai/**`）→ `lb://mse-ai`，修改后重导 Nacos；前端开发代理 target 改网关 48080。
5. 消费方（其他微服务）无需配置 AI——依赖 `ai-api` 契约即可；业务工具由各服务自动推送登记。
6. 高可用注意：编排「停止」的跨实例广播依赖 Redis（已有）；知识库解析为单机异步线程池，重启后「处理中」文档需手动重新解析。

## 八、常见问题排查（按现象查）

| 现象 | 先检查什么 |
| --- | --- |
| 应用启动失败报数据库 / Redis 连接错误 | 容器没起或地址密码错——`docker ps` 看容器，改环境变量重启 |
| 启动日志报"脚本执行失败"并退出 | 迁移是启动强校验：按日志提示修复后重启，不要跳过 |
| 登录后左侧没有「AI 服务」菜单 | 套餐没勾选（第 6 步），或该用户角色没授权菜单 |
| 对话报「模型不可用 / 鉴权失败」 | 模型 Key 错 / 欠费 / 端点不通——「模型管理」点「测试」看失败原因 |
| 对话报「智能体不存在或未发布」 | 智能体没发布或被下线；业务系统 / 开放 API 引用的编码写错也会报此错 |
| 知识库文档一直「待处理 / 处理中」 | 未开 `MSE_AI_MILVUS_ENABLED` 或 Milvus 没起；重启后积压文档需手动重新解析 |
| 知识库检索无结果 | 向量模型没配 / 未设默认，或文档解析失败——先看文档状态与模型测试结果 |
| 工具列表出现重复 / 删不掉的行 | 系统自动登记行为正常：以提供方为权威，用「停用」控制 |
| 第三方调用开放接口 401/403 | Key 填错 / 已停用 / 智能体不在白名单；限流超了会提示稍后再试 |
| 对话里工具调用一直重试 | 工具参数说明不清导致模型传错参——完善工具的功能与参数说明 |
| 微服务下接口 404 | ai-boot 没注册 Nacos，或网关缺 `/ai/**` 路由 |
| 界面中文乱码 | 建库连接须 utf8mb4（脚本已内置；自建库确认字符集） |
| 换了 `MSE_AI_CRYPT_KEY` 后模型全报错 | 旧密文无法解密——回改回原 Key，或到模型管理重录各 Key |

## 九、上线前检查清单

- [ ] 修改所有默认密码（platform/admin123、数据库 root、Redis 密码）
- [ ] **`MSE_AI_CRYPT_KEY` 已改为随机长串并纳入密码台账**（此后不再变更）
- [ ] 模型「测试」全部通过；关键对话模型已配备用模型
- [ ] 开知识库：Milvus 数据目录已纳入备份；文档解析链路验证过一轮
- [ ] 套餐勾选「AI 服务」菜单组；三个建议角色已建并试登录验证
- [ ] 开放 API：仅签发必要的 Key，逐条记录 App ID 用途与限流值
- [ ] 数据库开启每日备份；数据库 / Redis 走内网，端口不暴露公网
- [ ] 前端走 HTTPS 与正式域名；子应用登记改为生产地址 `/sub-apps/ai/`
- [ ] 记录本次部署的版本号与日期，便于后续升级追查
