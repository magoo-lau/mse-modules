# 01 功能规划 —— 功能模块与功能点

> mse-ai 功能总纲。配套文档：[02-权限规划](02-权限规划.md)（每个页面的权限码）、[03-角色规划](03-角色规划.md)（谁能用）。
> 功能以工程 README 与实际 Controller / 页面为准；菜单号 = `sys_menu.id`（见 02 第二节）。

## 一、模块总览与核心业务闭环

| # | 模块 | 页面菜单（menu_id） | 一句话定位 |
| --- | --- | --- | --- |
| 1 | 模型管理 | 模型管理（466） | 各世界自管的大模型通道台账：对话 / 向量 / 重排三类模型分行建档、连通性测试、备用模型 |
| 2 | 对话服务 | 对话工作台（461） | SSE 流式对话、多轮会话记忆、随时停止、工具调用与数据结果可视化、引用溯源 |
| 3 | 智能体 | 智能体管理（462） | 可发布的 AI 应用：模型 + 提示词 + 工具 + 知识库五要素编排，发布 / 下线 / 运行历史 |
| 4 | 画布编排 | 智能体管理内画布（/agent/flow/:id） | 对标 Dify Chatflow 的可视化工作流：15 类节点、变量引用、试运行调试、DSL 导入导出 |
| 5 | 知识库 RAG | 知识库（463） | 文档上传解析、五种切片模板、混合检索（向量+BM25+RRF）、重排、分块管理、检索测试 |
| 6 | 工具中心 | 工具中心（464） | 双向集成枢纽：内置/本地/RPC 自动登记 + HTTP/Dify 手工登记 + MCP 外部工具，测试与调用审计 |
| 7 | 用量统计 | 用量统计（465）/ 用量统计（468） | 本租户用量流水与汇总（465）；全局用量（468，平台 / 授权角色可见） |
| 8 | 开放能力 | 开放能力（467） | 对外窗口：API Key 签发与限流（`/openapi/ai/**`）+ MCP Server 登记（外部 AI 客户端接入） |

**核心业务闭环**（建设 → 消费 → 度量）：

```
模型中心建模型（对话/向量/重排分行建档，供应商预设带出端点，连通性测试）
  → （可选 RAG）Milvus 起库 → 知识库建库 → 上传文档 → 异步解析/切片/向量化 → 检索测试
  → 工具中心核对工具（启动扫描/RPC 推送自动登记；HTTP/Dify/MCP 手工登记）
  → 智能体编排（simple：模型+提示词+工具+知识库 ／ flow：画布工作流）→ 发布
  → 消费：① 对话工作台（SSE 流式）② 业务服务 @RpcReference（单体本地/微服务远程）
          ③ 第三方开放 API（/openapi/ai/**，appId+Key+限流）④ MCP 外部客户端
  → 度量：用量流水（gateway/rpc/openapi 三通道统一记录）+ 工具调用审计 + 工作流运行历史
```

## 二、模型管理（菜单 466）

各会话世界单边读写本世界自有模型行（租户配自己的 Key 计费；平台世界行为出厂播种模板源）。

| 功能点 | 说明 | 主要角色 |
| --- | --- | --- |
| 模型台账 | 模型类型三选一：`chat` 对话模型（智能体/工作流绑定）、`embedding` 向量模型（知识库绑定）、`rerank` 重排模型（知识库精排绑定），一行只表达一种能力，选择点按类型过滤 | AI 管理员 |
| 供应商预设 | DeepSeek / 智谱 GLM / Kimi / 通义千问 / OpenAI / Anthropic Claude / Ollama / 讯飞星火 / 自定义兼容，选中自动带出内置端点 | AI 管理员 |
| 接口类型 | `openai-chat`（OpenAI 兼容 chat/completions）与 `anthropic-messages`（Claude 原生 /v1/messages，兼容 DeepSeek/GLM/Kimi 的 Anthropic 兼容端点）；向量模型行固定 openai-chat | AI 管理员 |
| API Key 加密落库 | apiKey AES-GCM 密文存储（密钥 `mse.ai.crypt-key`，生产必须改） | AI 管理员 |
| 连通性测试 | 对话模型真实调用一次；向量模型真实 embed 一次并回显维度；结果（时间/成败/原因）留档 | AI 管理员 |
| 默认向量模型 | 向量模型行可「设默认」（本世界唯一 `is_default`）；新建知识库默认选中，可改绑 | AI 管理员 |
| 备用模型 | 对话模型可配 `failover_model_id`（必须对话模型且非自身）：主模型瞬态错误重试耗尽后整体切换备用再来一轮，全链路生效 | AI 管理员 |
| 瞬态重试 | 对话调用遇 5xx/429/网络中断自动退避重试（`mse.ai.chat-retry-times` 默认 2）；4xx 参数/鉴权错误快速失败 | —（平台行为） |

## 三、对话服务（菜单 461）

| 功能点 | 说明 | 主要角色 |
| --- | --- | --- |
| SSE 流式对话 | `POST /ai/chat/stream`（网关 `/api/ai/chat/stream`），事件 message/sources/tool/usage/done/error（编排智能体另有 node） | 普通用户 |
| 同步对话 | `POST /ai/chat`（非流式，一次性返回） | 普通用户 |
| 随时停止 | 「停止」按钮断流并调 `POST /ai/chat/stream/stop`；编排智能体节点级取消（Redis 频道跨实例广播，节点间隙/流式 delta 处协作中断） | 普通用户 |
| 会话管理 | 会话列表 / 重命名 / 删除；会话与消息落库（ChatMemory 的 MySQL 实现），刷新 / 回放不丢；上下文窗口 `mse.ai.memory-window`（默认 40 条） | 普通用户 |
| 智能体选择 | 对话页下拉选当前世界已发布智能体（出厂含「通用助手」等 6 个种子副本） | 普通用户 |
| 工具调用可视化 | SSE `tool` 事件实时显示「正在调用…」与结果；结果含数据集（columns+rows）时渲染「表格 / 图表」双视图卡片（echarts，随消息落库回放） | 普通用户 |
| 引用溯源 | 绑定知识库的智能体回答附 `sources` 事件（文件名/得分/摘要），随消息 ext 落库，历史回放恢复引用面板 | 普通用户 |
| 提示词变量 | 智能体系统提示词支持 `{{var}}` 占位，会话变量注入 | 普通用户 |

## 四、智能体（菜单 462）

智能体 = 一个可发布的 AI 应用，以世界内唯一 `agent_code` 编码被引用。

| 功能点 | 说明 | 主要角色 |
| --- | --- | --- |
| 五要素编排（simple） | 绑定对话模型（不绑=默认解析）+ 系统提示词 + 工具集多选 + 知识库多选（RAG）+ 温度 / 开场白 | AI 管理员 |
| 归属与发布 | 全面租户自管：列表即本世界全部自有智能体（含种子副本），可直接编辑 / 发布 / 下线 / 删除；仅「已发布」进入对话 / RPC / 开放通道 | AI 管理员 |
| 运行历史 | 每次编排执行收口落 `ai_workflow_run`（通道 gateway/debug/rpc/openapi，结果 success/failed/cancelled），列表「运行」弹窗分页查看 + 节点轨迹时间线回放 | AI 管理员 |
| 试运行调试 | 画布底部试运行抽屉（入参表单→节点时间线→回答流式区），不建会话不落消息 | AI 管理员 |
| DSL 导入导出 | 自有 mse-flow/v1 YAML 导入导出；**Dify DSL 尽力映射导入**（不可映射项生成待人工配置警告清单） | AI 管理员 |
| 数据分析模板 | 新建 flow 智能体一键套用「数据分析助手」：参数提取 → 数据中台取数（data_query）→ 条件分支 → LLM 趋势/异常分析 → 回复 | AI 管理员 |
| 数据源下拉 | 画布数据查询节点的数据源经 `GET /ai/agent/datasource-options` 取「中台库 + 本租户已启用数据源」，运行期双重校验归属，不能跨租户取数 | AI 管理员 |
| 工具跑飞保护 | 单回合单工具调用上限 10、合计 30（可配），超限以「已达上限」回传让模型自行收尾 | —（平台行为） |

## 五、智能体画布编排（462 内，orchestration_type=flow）

对标 Dify Chatflow：`flow` 模式智能体由画布 DSL（`graph_json`，mse-flow/v1）驱动，前端 vue-flow 编辑器。

| 功能点 | 说明 |
| --- | --- |
| 15 类节点 | 开始 / LLM / 知识检索 / 工具 / 数据查询 / 条件分支 / 问题分类 / 参数提取 / 代码执行（JavaScript GraalJS 沙箱）/ HTTP 请求（禁内网 SSRF 防护+白名单）/ 模板转换 / 变量赋值 / 变量聚合 / 迭代 / 直接回复+结束 |
| 全局参数 | 画布级 `env.<name>`（文本/数值/布尔/集合/对象），变量赋值节点可执行期改写（set/reset/append/add/subtract/merge） |
| 变量引用 | `{{nodeId.var}}` 引用任意上游祖先输出；系统变量 `sys.query/conversation/...`；HTTP 响应 JSON 深层取值 |
| 并行执行 | 多活跃路径并行（OR-join 先到先跑；`mse.ai.flow.parallel` 可回退串行）；节点级 errorStrategy；全局超时默认 120s |
| 草稿/发布双版本 | 「保存草稿」写 `draft_graph_json`（试运行/导出按草稿），「发布」校验后拷贝为运行版 `graph_json`——编辑不影响线上 |
| 对话集成 | SSE 新增 `node` 事件，消息内嵌「执行过程」时间线；有会话时运行成功自动落会话记忆 |

## 六、知识库 RAG（菜单 463，可选，需 Milvus 2.5+）

| 功能点 | 说明 | 主要角色 |
| --- | --- | --- |
| 切片方法模板 | `general` 通用（分隔符感知+overlap）/ `qa` 问答对 / `table` 表格（一行一片）/ `book` 书籍（章节标题层级）/ `one` 整篇；切片大小与重叠按库配置 | AI 管理员 |
| 异步解析管线 | 上传即返回，后台解析 → 切片 → 向量化（状态机 0 待处理/1 处理中/2 完成/3 失败，前端轮询）；失败重试 / 重新解析 / 知识库级重建索引 / 轻量重嵌入 | AI 管理员 |

| 分块管理 | 分块分页浏览（含增强展开）/ 手工新增 / 编辑 / 删除，保存即时重嵌入 | AI 管理员 |
| 检索测试 | `POST /ai/kb/search` 命中测试（统一走 KbRetrievalService 管线，与智能体 RAG / 引用同口径） | AI 管理员 |
| 向量模型绑定 | 知识库绑定向量模型（`embedding_model_id`）与重排模型（`rerank_model_id`）；按模型分集合 `mse_ai_kb_<modelId>`，改绑后「重嵌入」 | AI 管理员 |
| 原文归档 | 统一走 mse-fs（`storage-mode=auto`，可降级本地目录），原文可回下载 | —（平台行为） |
| 引用消费 | 智能体绑定知识库即启用 RAG，回答附引用来源（文件名/得分/摘要） | 普通用户 |

双向集成核心：智能体经工具调用业务能力，业务服务经工具把能力暴露给 AI。

| 功能点 | 说明 | 主要角色 |
| --- | --- | --- |
| 自动登记（双模式） | 内置/本地 Bean 工具启动扫描自动登记；RPC 远程工具由业务服务自动推送登记（`AiToolRegistrationPusher` 幂等 upsert + 周期重推自愈，默认 5 分钟）——免手工维护，单体/微服务行为一致 | —（自动） |

| 工具测试 | 按 Schema 展示全部参数，表单填写 / JSON 源码双模式，调用结果就地展示 | AI 管理员 |

## 十、AI 平台对外开放 / 被消费方式（专节）

### 10.1 正向通道（业务调 AI）

| 通道 | 场景 | 用法 |
| --- | --- | --- |
| RPC 契约（服务间同步） | 日报生成 / 智能填单 / 审批摘要等一次性生成 | 业务服务依赖 `ai-api` → `@RpcReference RemoteAiChatService` → `chat(AiChatRequest{agentCode, message, conversationId, variables})`；单体 local 本地直调、微服务 dubbo 远调，消费方零改动；租户上下文经 RPC 透传 |
| 智能体选项只读 | 业务工程「场景 → 智能体」映射下拉 | `RemoteAiAgentService.listOptions(keyword)` 返回当前世界已发布智能体（agentCode/name/description/scope）——参考 mse-oa「AI 智能体设置」 |
| HTTP SSE（前端流式） | 页面内流式问答 | 租户登录态 `POST /api/ai/chat/stream`（网关前缀 `/ai`），事件 message/sources/tool/node/usage/done/error |

### 10.2 反向通道（AI 调业务，工具门面）

- 业务服务实现 `RemoteAiTool`（`describe()` 声明 toolCode + 名称/说明/JSON Schema；`invoke(argumentsJson)` 返回 JSON 文本），微服务形态以 **group=服务名** 编程式导出——mse-ai 泛化调用按 group 定向，**无需编译期依赖提供方**；单体聚合形态平台直接收集容器内 Bean。
- 登记全自动：`AiToolRegistrationPusher` 应用就绪即推送、周期重推自愈；描述以提供方为权威（启停与备注保留）；`ai_tool` 唯一键 `(tenant_id, tool_code, deleted)` 兜底并发。
- 现有种子：`oa_flow`（8101，mse-oa：待办/实例/模板/统计/催办 + 组织供数）、`data_query`（8102，mse-data：元数据检索 / 受控只读 SQL / 数据源列表）。
- **红线**：工具内写死数据语义（如 data_query 的 jsqlparser 只读校验 + 租户谓词注入 + 限行），绝不让模型自由拼库。

### 10.3 第三方开放与生态

| 方式 | 说明 |
| --- | --- |
| 开放 API 直调 | `/openapi/ai/**`（appId + Key + 每分钟限流 + 智能体白名单），本页「开放能力」签发 |
| mse-open 开放平台 | `AiOpenApiContributor` 把 `POST /open/api/ai/chat`（授权码 `open:ai:chat`）自注册进 mse-open 目录——凭证 / 授权 / 限流 / 审计复用开放平台，本工程零开放平台代码 |
| MCP 双向 | 对外：MCP Client 动态接入外部 MCP Server（页面上登记+测试）；对内：MCP Server 开关把平台能力暴露给外部 AI 客户端 |
