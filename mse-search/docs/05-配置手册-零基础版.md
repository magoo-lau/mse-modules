# 05 配置手册（零基础版）—— 从零把搜索引擎跑起来

> **这本手册是给谁的**：没接触过本系统、甚至没怎么接触过服务器软件的同事——实施工程师、现场 IT、接手部署的新人。你不需要看懂代码，照着做、每步核对「✅ 成功的标志」即可。
> 配套文档：跑起来之后怎么用，看 [04-操作说明书](04-操作说明书/README.md)；技术细节与架构，看工程 [README](../README.md) 与 [docs/01-功能规划](01-功能规划.md)。

## 一、先认识几个名词（2 分钟）

| 名词 | 是什么 | 打个比方 |
| --- | --- | --- |
| **Docker** | 容器软件，把 MySQL 等软件"打包"成一键安装 | 免安装的"绿色软件"运行器 |
| **MySQL** | 数据库，业务数据存这里 | 大仓库的账本 |
| **Redis** | 缓存，存登录会话等临时数据 | 门卫的登记本 |
| **Elasticsearch（ES）** | 全文搜索引擎，本系统的"引擎"，数据在其索引里可秒级检索 | 图书馆的卡片目录（9.x 版本，本系统专用） |
| **中文分析器（smartcn）** | ES 把中文句子切成词的插件，切词方式决定"搜得到搜不准" | 图书管理员断句的习惯 |
| **可搜索源** | 一类可被检索的业务数据（如"OA 审批单"），业务系统"自报家门"登记进来 | 图书馆里登记在册的书架 |
| **索引** | 一类源在一个租户里的检索目录（每租户 × 每源一个，物理隔离） | 每个分馆自己的卡片目录 |
| **闲时窗口** | 每天凌晨的低峰时段（默认 00:00-07:00），重建索引这类重活默认这时干 | 商场打烊后盘点 |
| **JDK 21 / Maven / Node.js** | Java 运行环境 / Java 打包工具 / 前端构建运行环境 | 播放器 / 印刷厂 / 网页发动机 |
| **Nacos** | 微服务模式下的"配置中心 + 通讯录" | 公司前台（单体模式用不到） |
| **单体 / 微服务** | 两种安装形态：单体=所有功能装在一个程序里；微服务=拆成多个程序各司其职 | 便利店 vs 购物中心 |

> **新人建议选「单体」**：一个程序 + MySQL + Redis + Elasticsearch 就能跑全部功能（含搜索）。微服务是给有运维团队的正式生产环境用的（见第七节）。

## 二、你需要准备什么

| 项 | 要求 | 说明 |
| --- | --- | --- |
| 服务器/电脑 | 4 核 8G 起步，硬盘 ≥40G | ES 是内存大户，8G 内存是底线（见下） |
| 软件 | Docker（推荐）或：JDK 21 + MySQL 8 + Redis + Elasticsearch 9 + Maven 3.9+ + Node.js 20+ | 路线 A 只需 Docker |
| 软件包 | 本仓库源码（git clone 或拿到压缩包） | jar 也可以直接找开发要成品 |

**Elasticsearch 与内存（重要）**：ES 默认堆内存 512m（部署基线已配好）；数据量大或频繁重建索引时建议调到 1g-2g，且堆内存不超过物理内存一半（另一半留给系统缓存，检索性能靠它）。机器内存紧张时 ES 会启动失败或频繁假死——先加内存再排障。

## 三、路线 A：容器一键部署（推荐，约 30 分钟）

### 第 1 步：安装 Docker

- Windows：安装 Docker Desktop 并启动；Linux：安装 docker + docker compose 插件。
- ✅ 成功标志：命令行执行 `docker --version` 能输出版本号。

### 第 2 步：启动数据库、缓存和搜索引擎

命令行进入仓库的 `mse-framework/docker` 目录，执行：

```bash
docker compose up -d mysql redis elasticsearch
```

- ✅ 成功标志：`docker ps` 里出现 `mse-mysql`、`mse-redis`、`mse-elasticsearch` 三个容器，状态 Up（首次要等 MySQL 初始化约 1 分钟）。
- 验证引擎：浏览器或 curl 打开 `http://localhost:9200`，能看到一段带 `"cluster_name"` 的 JSON 即正常（ES 版本 9.2.8，镜像已内置 smartcn 中文分析插件，单节点免鉴权，无需任何配置）。

### 第 3 步：启动应用（单体，含搜索引擎全部功能）

仍在同一目录执行（首次会构建镜像，10~20 分钟属正常）：

```bash
docker compose --profile apps up -d --build mse-monolith
```

- ✅ 成功标志：`docker logs -f mse-monolith` 里出现 `Started ... in xx seconds`。
- 搜索引擎的业务表、菜单与权限点都会在启动时**自动写入数据库**，无需执行任何 SQL；ES 没起来也不影响单体启动，只是搜索暂时不可用。

### 第 4 步：启动网页前端

前端是独立的网页工程，需要 Node.js：

```bash
cd mse-framework/mse-ui      # 基座门户（含搜索引擎页面与顶栏搜索）
npm install
npm run dev
```

- ✅ 成功标志：浏览器打开 `http://localhost:3000` 看到登录页。

### 第 5 步：登录平台，开通租户

1. `http://localhost:3000` 用**平台超管**登录：账号 `platform`，密码 `admin123`（正式环境务必改密码）。
2. 「租户管理」→ 新建租户 → 按向导填写，系统会自动生成该租户的管理员账号。
3. （可选）想要现成演示数据：执行 `mse-framework/docker/mysql/demo/` 下的演示租户脚本，得到示例租户（详见仓库 README）。

### 第 6 步：给租户"点亮"搜索引擎（关键！不勾菜单看不到页面）

用平台账号进「**套餐管理**」→ 编辑租户所用套餐 → 勾选「**搜索引擎**」分组下的页面菜单（源管理 / 任务中心 / 热词统计 / 搜索测试 / 索引管理 / 搜索配置，建议六页一次配齐）→ 保存。

- ✅ 成功标志：用**租户管理员**重新登录后，左侧出现「搜索引擎」菜单组。
- 原理：搜索引擎的管理页面默认是"封存"的，套餐勾选是租户可见的总开关。**注意：这步只管管理页面——顶栏搜索框对所有登录用户始终可用，不需要勾套餐。**

### 第 7 步：给管理员配置搜索角色

1. 用**租户管理员**登录 → 「组织管理」→「角色管理」。
2. 本系统**不预置角色**——按 [03-角色规划](03-角色规划.md) 的建议矩阵新建角色（如「搜索引擎管理员」全量授权、「搜索运维员」任务/索引运维、「搜索查看员」只读），或在给用户勾权限时直接勾选搜索引擎相关权限。
3. 给管理员账号勾上对应角色。

### 第 8 步：验收搜索主流程

1. 登录租户管理员 → 搜索引擎 → **搜索测试**：选一个源（无业务接入时可先「手工登记源」），填标题"测试文档"推入 → 搜索"测试"看到高亮命中 → 验收通过。
2. 有业务接入（如 OA）时：在业务里产生一条数据 → 等扫描周期（默认每 10 分钟）或到任务中心对该源「立即扫描」→ 基座**顶栏搜索**输入关键词，命中并点击跳转业务详情页。
3. 走通即部署成功。

## 四、源接入与首扫触发（让搜索"有东西可搜"）

搜索页面部署好只是"架子"，真正可搜的数据来自业务工程接入。两条路：

### 路线一：业务自注册（正式，只动业务工程）

1. 业务工程引入 `search-api` 契约并声明可搜索源（开发侧动作，三步接入详见 [01-功能规划](01-功能规划.md) 第十一节；仓库内参考实现是 OA 协同办公的「OA 审批单」「OA 表单数据」两源）。
2. 业务应用启动后源**自动推送登记**进各租户目录（含平台域），无需任何界面操作或 SQL。
3. **首扫即全量**：每个"租户 × 源"的游标从水位 0 起步——首次定时扫描自然完成该租户该源的全量索引；等不及就到「任务中心」建「立即扫描」。
4. 删除数据要即时清理的话，业务侧需启用实时事件通道（RocketMQ，见第六节配置要点）。

### 路线二：手工登记（调试/验收）

无业务接入时：源管理「手工登记源」（提供者分组填 `manual`）→ 搜索测试手工推文档 → 搜索验证。适合给领导演示与实施前自检。

> 升级注意（存量部署）：目录租户化版本升级后，各租户游标为空、首扫自动全量重建租户索引，无需数据迁移；旧的共享索引成为孤儿数据，可在索引管理手工清理。

## 五、常用配置项速查

> 单体的配置文件：`mse-sample/mse-monolith/src/main/resources/application.yaml`（ES 连接键 `spring.elasticsearch.uris`，环境变量 `MSE_ES_HOST` 可覆盖，默认 localhost:9200）。微服务形态在 Nacos 的 `mse-search.yaml`（下表同样适用）。

| 想改什么 | 配置键 | 默认值 | 说明 |
| --- | --- | --- | --- |
| ES 地址 | `spring.elasticsearch.uris` | `http://localhost:9200` | ES 在别的机器时改；开了安全再补 username/password |
| 索引名前缀 | `mse.search.index-prefix` | `mse-search` | 索引 = 前缀-源编码-租户号 |
| 中文分析器 | `mse.search.analyzer` | `smartcn` | 换 IK 改 `ik_max_word`（需重建全部索引） |
| 闲时窗口 | `mse.search.idle-window` | `00:00-07:00` | 支持逗号分段与跨天（如 `22:00-06:00`） |
| 扫描总开关 | `mse.search.scan.enabled` | `true` | 关闭后只靠实时事件 |
| 默认扫描周期 | `mse.search.scan.default-cron` | 每 10 分钟 | 新源未单独调参时的扫描频率 |
| 忙时限流 | `mse.search.scan.batch-interval-ms` | 500 | 拉取批次间隔毫秒；闲时窗口内自动不限 |
| 任务轮询 | `mse.search.task.poll-interval-ms` | 30000 | 重建/优化任务的拾取间隔 |
| 源推送周期 | `mse.search.registry.interval-minutes` | 5 | 业务源目录推送自愈周期 |
| 单源字段上限 | `mse.search.field.max-per-source` | 100 | 参与检索/高亮的字段数上限 |
| 租户新增字段上限 | `mse.search.field.tenant-max-added` | 50 | 租户「搜索配置」单源可新增字段数 |

## 六、微服务形态（进阶，多服务正式环境）

> 什么时候需要：用户量大、需要独立扩缩容、有多团队维护。门外汉/试点环境用第三节的单体即可。

1. **Nacos 配置**：把服务专属配置写入 Nacos：
   ```bash
   CONFIG_DIR=<仓库根>/mse-modules/mse-search/docker/nacos/config sh mse-framework/docker/nacos/init-configs.sh
   ```
   服务端口 8096、ES 地址、扫描/任务/闲时窗口参数都在 `mse-search.yaml`（留档于工程 `docker/nacos/config/`）；数据源/Redis 等公共项在共享 Data ID 管理。
2. **构建启动**：先仓库根 `mvn install -DskipTests`（框架），再 `mvn install -DskipTests -f mse-modules/mse-search/pom.xml`，最后启动 `search-boot`（注册 Nacos 即被网关发现）。
3. **实时事件通道（可选）**：业务与搜索引擎两侧配 `rocketmq.name-server` 后，数据写入/删除即时进索引；不配也不影响定时扫描兜底。
4. **网关路由**：确认 `mse-gateway.yaml` 里有 `/search/** → lb://mse-search`（已登记，需登录、无白名单）；前端代理 target 改网关地址（默认 48080）。
5. **信创**：数据库可切达梦/金仓（启动加 `--spring.profiles.active=dm|kingbase`）；**但本工程版本化脚本当前仅提供 MySQL 方言**，且 ES 为独立中间件不受影响——混布前先评估。

## 七、租户/套餐/角色初始化（微服务形态同样适用）

与第三节第 5-7 步一致：租户管理建租户 → 套餐管理勾选「搜索引擎」页面菜单 → 角色管理按建议矩阵配角色。补充口径：

- **管理页面**（源管理/任务中心/索引管理等）按套餐+角色授权；
- **搜索入口**（顶栏/首页卡片）登录即用，无需套餐与角色；
- **各业务数据能否被搜到**由业务侧权限码与数据归属决定（如 OA 审批单需 `oa:process:mine`）——给用户开通搜索 = 给他在业务系统里本来就该有的权限，搜索不会"越权放大"。

## 八、常见问题排查（按现象查）

| 现象 | 先检查什么 |
| --- | --- |
| 搜索引擎页面打不开/接口报错，日志有 ES 连接异常 | **ES 连不上**：`docker ps` 看 `mse-elasticsearch` 是否 Up；`curl localhost:9200` 是否应答；内存不足会启动失败（看 `docker logs mse-elasticsearch`，加内存或调 `ES_JAVA_OPTS`）；地址不对改 `spring.elasticsearch.uris` |
| 源管理有源、热词/索引里文档数是 0 | **索引无数据**：① ES 是否正常（同上）；② 该源是否停用；③ 到任务中心建「立即扫描」手动触发，看任务状态与失败原因；④ 供数业务是否在运行（提供者分组对应的服务没起，扫描拉不到数据） |
| 用户反馈"明明有这条数据就是搜不到" | **权限过滤**（按序核对）：① 用户没登录/租户不对；② 用户没有该源的结果可见权限码（如 `oa:process:mine`）；③ 源配置了「可见角色」而用户不在其中；④ 数据归属人/部门/共享范围不含该用户——管理员可用「搜索测试」的过滤对比验证，一切"搜不到"先怀疑过滤而非故障 |
| 数据改了/删了，搜索结果没跟上 | 增量有扫描周期（默认 10 分钟）；删除依赖业务实时事件——未配 RocketMQ 的环境删除要等下轮扫描兜底。急迫用「立即扫描」；持续残留查业务侧实时通道与任务中心失败记录 |
| 业务系统启动日志出现源目录推送失败告警 | 搜索服务未启动/不可达：业务不受影响，推送会周期自愈；确认 mse-search 已部署即可，无需处理业务侧 |
| 新建租户的源管理是空的 | 套餐没勾选「搜索引擎」页面菜单（见第三节第 6 步）；或租户刚建、目录播种未到推送周期（默认最迟 5 分钟，等一轮即可） |
| 搜索结果点不开 | 该源「跳转模板」配置错误或业务详情页无权限；管理员到源管理核对该源跳转模板 |
| 中文搜索不准/搜不全 | 分析器问题：默认 smartcn；确需更细切词换 IK（改配置 + 全部索引全量重建，分析器建索引时固化，属变更管理动作） |
| 任务一直"待执行" | 默认仅闲时（00:00-07:00）执行，工作时间提交会挂起等待；急迫点行内「立即执行」改为立即 |
| 界面/数据库中文乱码 | 建库与连接必须 utf8mb4（脚本已内置；自建库时确认字符集） |
| 启动日志报"脚本执行失败"并退出 | 数据库迁移是启动强校验：按日志提示修复后重启，不要跳过 |

## 九、上线前检查清单

- [ ] 修改所有默认密码（platform/admin123、数据库 root、Redis 密码；生产建议开启 ES xpack 安全并补服务侧账号口令）
- [ ] ES 堆内存按数据量核定（512m 基线 → 建议生产 1g-2g，不超过物理内存一半），服务器磁盘余量充足
- [ ] MySQL/Redis 开启每日备份；ES 数据卷纳入快照策略（索引可重建，目录/游标/任务在 MySQL）
- [ ] 前端走 HTTPS 与正式域名；子应用登记改为生产地址 `/sub-apps/search/`
- [ ] 微服务形态：Nacos 开鉴权、网关白名单按需最小化（`/search` 本身需登录，无白名单）
- [ ] 套餐勾选搜索引擎页面菜单；按建议矩阵配置角色并试登录核对菜单与按钮
- [ ] 完成一轮验收：手工源 + 搜索测试推文档 → 搜索高亮；业务源「立即扫描」→ 顶栏搜索命中并跳转
- [ ] 记录本次部署的版本号与日期，便于后续升级追查（搜索服务与业务供数端需同批升级）
