# 01 搜索引擎管理员操作手册（租户端）

> 岗位：租户管理员，或按 03 分册建议配置的搜索引擎管理员（`search_admin`）/ 搜索运维员（`search_operator`）｜菜单：「搜索引擎」分组下全部（或部分）页面。
> 定位：本租户搜索域的管理员——负责**可搜索源目录**（哪些业务数据进搜索、什么参数扫）、**索引运维任务**（重建/优化/扫描）、**索引与字段治理**，并用**搜索测试**验证三层过滤。**不负责**基座侧用户/角色/套餐管理（那是租户管理员在「组织管理」的事）。

## 一、职责与页面清单

| 职责 | 页面 |
| --- | --- |
| 源目录：启停、调参（扫描周期/分片/可见性）、字段配置、手工登记调试源 | 源管理 |
| 索引运维：全量重建、索引优化、立即扫描、任务进度跟踪 | 任务中心 |
| 搜索健康巡检：热词榜、按源索引水位 | 热词统计 |
| 验收与排障：推测试文档、验证高亮与权限过滤 | 搜索测试 |
| 引擎实况：索引清单、数据浏览、清空/删除索引 | 索引管理 |
| 租户检索字段定制：覆盖已声明字段、从业务目录新增字段 | 搜索配置 |

## 二、源管理（搜索域的"总闸"）

> 路径：搜索引擎 → **源管理**。列表展示本租户目录内的全部可搜索源（业务自动推送 + 手工登记），按源标识/名称检索。

### 2.1 看懂一行源

| 列 | 含义 |
| --- | --- |
| 源标识 / 源名称 | 源的唯一编码（如 `search:oa:instance`）与显示名 |
| 业务域 | 搜索端「按域过滤」的分组名（空 = 仅参与「全部域」） |
| 提供者分组 | 增量数据来自哪个业务服务（微服务名） |
| 状态 | 启用 / 停用（停用即从本租户搜索中移除该源） |
| 个人过滤 | 开 = 按数据归属人/部门过滤结果；关 = 该源文档一律公开 |
| 可见角色 | 配置后仅持有所选角色的用户可见该源（空 = 不限制） |

### 2.2 调参（点行内「调参」）

- **扫描 cron**：图形化选择（秒/分/时/日/月/周/年七页签，日与周二选其一），下方实时预览最近 10 次执行时间——预览与实际触发同一套解析，所见即所得。
- **增量水位列 / 每批条数 / 分片数**：一般保持默认（update_time / 500 / 1）；数据量大时可加分片并行拉取。
- **跳转模板**：点击搜索结果跳转的业务详情页地址（支持取文档附加字段拼地址），改错会导致结果点不开。
- **结果可见权限码 / 可见角色**：双层来源可见性，任一不满足该源对用户整体不可见。
- **个人数据过滤**：公告类无归属的数据源可关闭，关闭后该源文档对全员可见。
- 保存即生效（仅作用于本租户，各租户互不影响）。

### 2.3 字段配置（点行内「字段」，权限：源字段配置）

1. 三种加字段方式：**手工添加**（已知字段名）、**从数据采样**（从存量文档抓取）、**从业务目录导入**（实时拉业务方最新字段清单，同类型同名字段自动合并，类型冲突的会列在排除清单里提示业务侧统一）。
2. 每个字段可设：类型（关键词=精确匹配 / 文本=全文分词 / 数字 / 日期）、可检索、权重（文本字段排序加权）、高亮（仅文本有效）、展示。
3. **改完字段不是立即全量生效**：新写入的文档立即可搜；**存量文档要建「全量重建」任务**（保存时系统会提示一键创建）。
4. 系统保留字段（标题/正文/租户/权限/共享用户等过滤字段）不可占用，界面已屏蔽。

### 2.4 启停 / 手工登记 / 删除

- 「启停」即时切换该源是否参与本租户检索。
- 「手工登记源」为调试通道（无业务接入时配手工源用），提供者分组可填 `manual`。
- 删除仅移除目录登记；已产生的索引到「索引管理」清理。

## 三、任务中心（索引运维）

> 路径：搜索引擎 → **任务中心**。「新建任务」选类型与目标源；列表跟踪执行。

| 任务 | 什么时候用 | 执行时机 |
| --- | --- | --- |
| 全量重建 | 字段集合/类型变更后；怀疑索引脏数据（删除索引重扫，保证无残留） | 默认仅闲时（00:00-07:00），工作时间提交则挂起排队 |
| 索引优化 | 大批量导入后合并索引段，降存储提查询 | 同上 |
| 立即扫描 | 想立刻同步最新增量（从当前水位继续，**不清理旧数据**） | 立即 |

- 挂起中的闲时任务可点行内「**立即执行**」改为立即跑（下一轮调度拾起）。
- 任务状态：待执行 → 执行中 → 成功 / 失败；失败原因在列表可见，处理后可再建同型任务。
- 重建/扫描按「租户 × 源」加锁，多实例部署不会重复执行。

## 四、索引管理（引擎实况）

> 路径：搜索引擎 → **索引管理**。展示本租户在引擎里的**真实索引**（含源已删除后遗留的索引——这是与热词统计页按源水位的区别）。

- 索引清单：索引名 / 健康（绿黄红）/ 状态 / 文档数 / 存储大小，点「刷新」更新。
- 「查看数据」：按关键词过滤文档列表，点「详情」看单条文档完整内容（排障利器：能看到这条文档的归属人、可见类型等过滤字段实际值）。
- 「清空数据」：保留索引结构，文档清零（之后靠重建/扫描回填）。
- 「删除」：整索引删除；要恢复检索请到任务中心对该源建「全量重建」。
- 护栏：只能看到/操作本租户自己的索引，其他租户与引擎外索引不可见。

## 五、搜索测试（验收与排障）

> 路径：搜索引擎 → **搜索测试**。三步验收法：

1. **推文档**：选一个已登记源，填业务主键、标题、正文（可再填归属人/部门/可见类型/共享用户），「推送/覆盖」写入本租户索引。
2. **搜索**：输入关键词「搜索」，核对命中、高亮与摘要。
3. **过滤对比**：同一关键词分别按「默认（范围过滤）」与「公开（all）」各搜一次——两次结果差异即个人数据范围过滤的实际效果；再用不同账号登录复核「搜不到」是否符合权限预期。
4. 辅助：「样本字段」从存量文档抓取附加字段清单，辅助字段配置。

## 六、搜索配置（租户字段定制）

> 路径：搜索引擎 → **搜索配置**（仅租户端）。与源管理字段配置的分工：源管理是**源的**字段登记（驱动索引结构），本页是**本租户的**检索偏好。

- 「配置」进入单源字段列表：可调整已声明字段的**可检索 / 权重 / 高亮 / 展示 / 显示名**（不能改类型）。
- 「从业务目录添加」：把业务方最新暴露、但尚未收录的字段加入本租户索引（单源新增上限 50；保存时实时对照业务目录校验，业务目录不可用或字段不存在会被拒绝）。
- 「恢复默认」：清除本租户覆盖，回退源级配置。
- 生效规则同 2.3 第 3 条：新文档立即可搜，存量文档需全量重建。

## 七、热词统计（健康巡检）

- 热词榜：本租户用户都在搜什么（关键词/命中次数/最近搜索时间）——冷门高频词可能提示检索质量或入口引导问题。
- 引擎水位：按源展示索引名与文档量，作为「数据有没有进来」的快速巡检视图（完整实况去索引管理）。

## 八、管理员注意事项

1. **字段变更必重建**：改了字段集合或类型，务必到任务中心建「全量重建」，否则存量文档检索行为不一致。
2. **删除靠实时事件**：业务数据的删除依赖业务侧实时事件即时清理；未接实时通道的业务由扫描周期兜底——发现"已删还能搜到"先核对业务的实时通道，再用索引管理核实。
3. **停用优于删除**：暂时不想让某源参与检索用「停用」，目录与索引都保留，随时可恢复。
4. **闲时重活**：全量重建默认深夜执行是刻意设计（避免影响白天检索）；确需白天跑用「立即执行」翻转，跑完记得观察任务状态。
5. **排障顺序**：搜不到 → 搜索测试推文档验证链路 → 索引管理看文档实际内容与过滤字段 → 源管理核对该用户是否满足权限码/可见角色。
