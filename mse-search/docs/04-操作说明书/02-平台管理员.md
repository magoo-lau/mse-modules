# 02 平台管理员操作手册（平台域 + 引擎运维）

> 岗位：平台超管（平台端登录）｜入口：平台门户左侧「搜索引擎」分组（子应用为双端注册，平台端以单菜单项进入）。
> 定位：两层职责——① **平台自有搜索域**（平台世界 tenant 0 也有独立的一份源目录与索引，业务源由系统自动播种到平台目录）；② **Elasticsearch 引擎运维**（搜索服务的底层中间件，页面之外的服务器侧操作）。普通平台账号默认无搜索管理权限（搜索权限点属租户域），引擎运维由平台超管承担。

## 一、职责与页面清单

| 职责 | 入口 |
| --- | --- |
| 平台域源目录：启停、调参、字段配置、手工登记 | 平台门户 → 搜索引擎 → 源管理 |
| 平台域任务：全量重建 / 索引优化 / 立即扫描 | 任务中心 |
| 平台域索引实况与清理 | 索引管理 |
| 平台域搜索验证与过滤对比 | 搜索测试 |
| 平台域热词与水位巡检 | 热词统计 |
| Elasticsearch 中间件运维（启动/健康/内存/分析器） | 服务器（docker） |

> 页面操作与租户端完全一致（详见 [01-搜索引擎管理员](01-搜索引擎管理员.md)），本手册不重复——差异只有两点：**作用域是平台世界（tenant 0）自己的目录与索引**；平台端**没有「搜索配置」页**（租户字段定制是租户端专属能力）。

## 二、平台域与租户域的关系（先建立正确认知）

1. **一租户一世界，平台也是**：源目录、扫描游标、任务、索引、热词全部按归属隔离——平台操作只影响平台世界（tenant 0），看不见也动不了任何租户的目录与索引。
2. **平台目录自动播种**：业务工程声明的可搜索源由系统扇出播种到「平台 + 全部租户」各一份目录——平台域目录无需手工创建，业务上线后最迟一个推送周期（默认 5 分钟）自动就绪；单次播种失败等下一轮推送自愈。
3. **平台数据进平台索引**：业务在平台世界产生的数据由扫描写入平台自己的索引（`{前缀}-{源}-{0}`）；各租户数据进各自索引，互不混写。
4. **普通用户搜什么看租户**：租户用户只搜租户域数据，平台域数据不参与租户检索——平台侧登记的源仅供平台自己的使用场景。

## 三、平台域日常运维（按 01 号手册操作）

1. **巡检**：热词统计看平台域水位；索引管理看平台索引健康与文档量。
2. **平台域数据变更后**：任务中心建「立即扫描」快速同步，或「全量重建」彻底重刷。
3. **验证**：搜索测试推平台域测试文档 → 查询高亮 → 过滤对比。
4. **清理**：源下线后遗留索引在索引管理删除（只显示 `mse-search-*` 且归属平台后缀的索引，误删其他世界不可能）。

## 四、Elasticsearch 引擎运维（服务器侧）

> 搜索引擎的底层是 Elasticsearch 9.x（部署镜像已预装 smartcn 中文分析插件，单节点、默认免鉴权）。这一节是页面之外的运维动作，需服务器 docker 权限；具体命令与参数速查见 [05-配置手册-零基础版](../05-配置手册-零基础版.md)。

- **启动与健康检查**：用仓库 docker 编排一键启动 ES 容器（端口 9200）；打开引擎健康地址，状态为绿/黄即正常，红色表示有分片未分配需处理。
- **内存**：部署基线 JVM 堆为 512m；数据量上万文档或重建任务频繁时建议调到 1g-2g（改编排配置后重建容器生效）。堆内存只给 ES 一半物理内存以内，余量留给操作系统文件缓存（检索性能主要靠它）。
- **分析器（中文分词）**：默认 smartcn（镜像内置，离线可用）；如需更细粒度的 IK 分词：把版本匹配的插件放入镜像构建目录、把搜索服务的分析器配置改为 `ik_max_word` 并重建镜像——**分析器在建索引时固化，已有索引必须全量重建后才生效**；平台与各租户索引共用同一配置，切换需统筹安排闲时重建。
- **开启安全（生产建议）**：基线为免鉴权（内网单节点）；开启 ES 的 xpack 安全后，在搜索服务配置里补访问账号口令（Nacos `mse-search.yaml`），重启搜索服务即可。

## 五、平台管理员注意事项

1. **不越界**：平台侧一切页面操作只作用于平台域；租户的数据问题（目录/索引/可见性）由该租户管理员在自己世界处理，平台无需也无法代劳。
2. **租户目录就绪保障**：新租户开通后其目录由系统自动播种（最迟一个推送周期）；若某租户报告"源管理是空的"，先核对该租户套餐是否勾选搜索引擎页面菜单，再查推送日志，不要手工替租户登记（登记到平台域没用）。
3. **引擎是唯一共享资源**：目录/索引/任务全租户隔离，但 Elasticsearch 进程共享——大租户全量重建集中爆发会抬高引擎负载，重大重建安排错峰（系统闲时窗口机制已内置，勿随意大面积"立即执行"翻转）。
4. **磁盘水位**：索引存储见索引管理页"存储大小"列；服务器磁盘使用率超 85% 时 ES 会把索引置为只读，先清理遗留索引再扩容。
5. **升级纪律**：搜索服务与业务供数端需同批升级（契约新增了按租户供数要求）；旧版供数器混跑期系统有防串写护栏，但旧供数器只能供出平台域数据——升级窗口安排在闲时并尽快对齐。

## 六、平台管理员常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 平台门户点了「搜索引擎」进去页面是空的/报无权限 | 搜索管理权限点属租户域，平台侧只有平台超管（`*`）可操作；确认用平台超管账号登录。 |
| 租户说他们搜到了平台的数据（或反之） | 不可能跨世界检索——目录与索引双重租户隔离；核实双方看到的是否为同名源在不同世界的各自索引。 |
| 索引管理里索引健康显示红色 | 有分片未分配：多为磁盘水位超限（超 85% ES 置只读）或节点内存不足；先清理遗留/废弃索引，再扩资源。 |
| 全量重建任务白天提交一直不跑 | 默认仅闲时窗口（00:00-07:00）执行属预期；确需白天执行由管理员在任务行内「立即执行」翻转，重大重建请错峰。 |
| 业务方问"我们接搜索要平台审批吗" | 不需要——业务工程引 `search-api` 契约自注册即接入，平台与租户目录自动播种，mse-search 侧零改动。 |
