# 02 权限规划 —— 子应用注册、页面菜单与权限点（实录）

> mse-search 的菜单与权限点设计。功能点含义见 [01-功能规划](01-功能规划.md)，角色授权见 [03-角色规划](03-角色规划.md)。
> **与 mse-mes 等规划文档不同：本工程已落地，本文所有 id / 号段均为种子脚本实际值**（`search-service/src/main/resources/db/mysql/V20261001_01_search__search_base.sql`），与 `alloc-tables.md` 登记一致。

## 一、规划原则（基座 RBAC 模型）

1. **三张全局表，一条链路**：`sys_micro_app`（子应用注册）→ `sys_menu`（导航菜单）→ `sys_permission`（权限点）；授权链 `sys_user → sys_user_role → sys_role → sys_role_menu / sys_role_permission`。
2. **sys_menu.type / menu_scope**：480 为 type=1 分组目录（`menu_scope=3` 双端可见）；六个页面均为 type=3 子应用页面菜单（`menu_scope=2` 租户端——搜索目录/索引每租户一份，管理页面归租户自管）；可见域语义：1=平台端、2=租户端、3=双端（门户按 `menu_scope IN (本端, 3)` 过滤）。
3. **权限点全部挂靠页面菜单**：11 个权限点的 `menu_id` 均指向本工程 type=3 页面菜单，参与角色授权分组与**租户套餐裁剪**；本工程**无 `menu_id=NULL` 通用权限**。
4. **搜索开放 API 不设权限码**：`/search/api/*`（query/domains/suggest/display-fields）登录即可调用，普通用户无需任何 search 权限即可使用基座搜索入口；能搜到什么由**源级三层过滤**控制（见 03 分册第六节）。
5. **前端按钮控制**：子应用内用 `v-permission` 指令按权限码显隐按钮（如「调参」「手工登记源」挂 `search:source:save`）。
6. **落库方式**：随 jar 的幂等版本化脚本 `V20261001_01_search__search_base.sql`（头指令 `-- mse-target: base`，按 id 判重），由 starter-bridge 自动推送 mse-system 应用——免手工执行；已应用脚本不再修改，变更一律新增版本文件。

## 六、编码规范

1. **权限码格式**：`search:<模块>:<动作>`，模块取值 `source` / `task` / `stats` / `debug` / `index` / `tenantconfig`，动作小写动词（list/save/use/delete/field），唯一键 `uk_code`。
2. **源标识（sourceCode）格式**：`search:<biz>:<对象>`（如 `search:oa:instance`），与权限码同风格但**分属两套命名**——源标识由业务 Contributor 声明并进 ES 索引名（`:` 替换为 `_`），权限码是基座 RBAC 资产。
3. **前端按钮**：`v-permission="'search:source:save'"` 按权限码显隐。
4. **双端注解惯例**：管理端点用「租户 + 平台」双 `@SaCheckPermission` 变体，保证平台超管（`*`）可运维平台自有目录。

## 七、套餐裁剪与登记纪律

1. **租户套餐**：本工程页面菜单（481-487）需在平台端「套餐管理」勾选后才对租户可见（480 分组目录随子页面祖先链自动闭合）；未配置任何页面菜单的中间状态会退化为单菜单项渲染，建议六页一次配齐。租户管理员拿到的是「套餐域内全量权限码」，裁剪对管理员同样生效。
2. **平台端口径**：4201-4211 挂靠租户端页面，属**租户域权限**；平台域权限集（menu_scope=1/3 菜单所挂权限点）不含它们——平台侧仅平台超管（权限 `*` 放行）可运维平台自有目录，普通平台角色默认无 search 权限点（如需开放须把页面菜单调整为双端并重新规划，当前未做）。
3. **alloc-tables.md 登记**（已执行）：后端端口 8096、前端 dev 4000、micro_app id=9、菜单段 480-484、486-487、权限段 4201-4211（基点 4200）、网关前缀 `/search`。
4. **脚本纪律**：全部幂等写法（micro_app 按 name 判重、菜单/权限点按 id 判重）；已应用脚本不再修改，新增权限点一律新增版本文件（2026-09-20 追加的 486/487 与 4207-4211 已并入 V20261001_01 基线，历史安装经推送重放补齐）。
