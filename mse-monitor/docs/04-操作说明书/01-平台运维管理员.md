# 01 平台运维管理员操作手册

> 使用者：平台运维岗（平台端）｜数据范围：平台世界（网关/基座微服务/中间件/monitor 所在主机）｜菜单：「监控中心」全部页面。
> 定位：监控中心的运营者——负责**监控目标接入**、**指标查看**、**告警与通知配置**。不负责基座侧的用户/角色/套餐管理（那是平台管理员的事）。

## 一、职责与页面清单

| 职责 | 页面 |
| --- | --- |
| 接入/维护监控目标（8 类）、启停、立即检测、告警规则 | 监控目标 |
| 指标查看与趋势分析、JVM/慢SQL/中间件/OS 健康研判 | 监控目标 → 目标详情 |
| 全局健康巡视 | 监控总览 |
| 告警查看、手动处理、通知通道配置 | 告警中心 |
| Redis 缓存浏览与删键、慢命令排查 | 缓存监控 / 目标详情 |

## 二、监控目标接入（上线第一步）

> 路径：监控中心 → **监控目标** → 「新增目标」。表单按目标类型差异化呈现，按类型填对应字段即可。

### 2.1 八类目标的填写要点

| 类型 | 填什么 | 说明 |
| --- | --- | --- |
| Java 微服务（service） | 地址 `http://主机:端口` | 系统只读其 `/actuator/health`，被监控服务零改动 |
| 任意 URL（http） | 完整 URL | Nacos 控制台、ES 集群健康（`…/_cluster/health`）等；按 JSON `status` 字段识别绿/黄/红 |
| JVM | 地址（同所属服务） | 需目标服务暴露 metrics 端点（实施配置）；种子默认停用 |
| 慢SQL | 地址（同所属服务） | 需目标服务开启慢SQL 开关并暴露 slowsql 端点（实施配置）；网关不支持 |
| MySQL | 主机 + 端口 + 用户名/密码 | 建议用只读账号；密码界面脱敏 |
| Redis | 主机 + 端口 + 密码（如有） | 凭据与「缓存监控」共用 |
| RocketMQ | 主机（namesrv 地址）+ 端口 | 只读集群信息 |
| 操作系统（OS） | 无需手工接入 | 系统自动登记 monitor 所在本机 |

### 2.2 建议的接入顺序

1. 部署完成后先巡视**监控总览**：系统已预置平台目标全家桶（网关/基座微服务/MySQL/Redis 等，其中 MySQL 与 Redis 默认启用，其余按部署实况启用）。
2. 对实际部署存在的服务，逐条打开「启用」开关；不存在的保持停用（停用目标不参与采集，不产生误报）。
3. 每启用一批，点行内「**检测**」立即验证连通性，确认状态点变绿。
4. 为关键目标配置**告警规则**（见第四节）。

### 2.3 地址填写的常见坑

- 容器/微服务部署时，目标地址要填**目标服务自己网络里可达的地址**（如容器名/内网 IP），不是浏览器地址。
- 目标服务若开启了 actuator 端点鉴权，监控侧令牌必须与之一致（环境变量对齐，由实施完成，见 [05-配置手册](../05-配置手册-零基础版.md) 第四节），否则目标显示异常。
- 中间件类目标可把采集间隔放宽到 60 秒，降低探测压力。

## 三、指标查看与趋势

> 路径：监控目标 → 点目标名称/行进入 **目标详情**。

- **基本信息**：地址、状态、最近耗时、最近采集时间、采集间隔、启停、说明。
- **当前指标**：按类型呈现（服务=存活/延迟；JVM=堆使用率/线程/GC；MySQL=连接数/QPS；Redis=内存/命中率/OPS；OS=CPU/内存/磁盘/网卡）。
- **趋势图**：近 1 小时 / 24 小时 / 7 天三档切换，用于容量研判与故障回溯。
- **差值口径提醒**：GC 次数/耗时、MySQL QPS、慢SQL 新增均为相邻两次采样的差值——目标服务或监控系统重启后首轮无增量属正常。

## 四、告警规则配置

在「新增/编辑目标」弹窗下半的**告警规则**区逐项填写，**0 或不填=不启用**该规则：

| 规则 | 适用目标 | 经验值 |
| --- | --- | --- |
| 宕机（down） | 全部类型 | 关键服务必开 |
| 响应耗时超过 N ms | service/http/jvm/slowsql | 3000 |
| CPU / 内存 / 磁盘使用率超过 N% | OS（本机） | 80 / 85 / 85 |
| Redis 内存超过 N% | redis | 90 |
| MySQL 连接数超过 N | mysql | 按上限的 80% |
| JVM 堆使用率超过 N% | jvm | 85 |
| 慢SQL 每轮新增达到 N 条 | slowsql | 10 |
| Redis 慢命令达到 N 条 | redis | 仅慢命令抓取开启期间评估 |

规则命中后系统自动产生告警并通知；**触发即通知、持续触发不重复轰炸**（可配周期重发）、**恢复也会通知**。

## 五、告警中心与通知设置

> 路径：监控中心 → **告警中心**。

- **筛选**：状态（触发中/已恢复）+ 目标/内容关键字。
- **手动处理**：已人工修复但等不及自动恢复探测时，点行内「处理」转「已恢复」并发送恢复通知（二次确认）。
- **通知设置**（弹窗，保存即生效）：
  1. **站内消息**：开启后从基座用户检索选择收件人（可多个），告警经基座消息铃铛送达。
  2. **Webhook 群机器人**：开启后填机器人地址，报文格式按群类型选钉钉/企微/飞书；填完点「**发送测试**」验证，群里收到卡片即通。
  3. **重复通知间隔**：持续触发时每隔 N 分钟重发一次（0=不重复，防轰炸默认）。
- 每条告警行可查看**通知结果**（各通道成功/失败），通知失败先查机器人地址与网络。

## 六、缓存监控与慢命令抓取

> 缓存浏览路径：监控中心 → **缓存监控**（选择一个 Redis 类型目标）；慢命令路径：该目标详情页。

- **键树浏览**：输入匹配模式（如 `mse:session:*`）查询，键按冒号分层成树；点叶子查看值（字符串自动识别 JSON 美化，集合类型预览前 200 条）。
- **删键**：详情/行内「删除该键」，二次确认后立即生效且**不可恢复**——仅授权给明确需要的角色。
- **慢命令抓取**（排查「哪些 key/命令慢」）：目标详情页打开开关，选持续时长（30 分钟/1 小时/2 小时）或起止时间窗，到期自动停；抓取期间「最近慢命令」表格持续积累（时间/耗时/命令/Key/参数）。界面常驻警示：抓取有固定额外开销，**排查完请及时关闭**；关闭后数据即消失、相关告警规则自动静默。

## 七、管理员注意事项

1. **先启用再观察**：预置目标多数默认停用，按部署实况逐批启用并「检测」验证，避免一次性全开产生噪音告警。
2. **密码安全**：目标凭据在界面一律脱敏显示，编辑时留空即保持原值；为 MySQL 建议使用只读账号。
3. **多实例部署**：监控系统自身建议单实例部署（多实例会重复采集，数据无害但浪费）。
4. **告警规则宁缺毋滥**：先给关键服务开 down + 耗时，观察一周再逐步加资源类阈值，避免告警疲劳。
5. **OS 监控边界**：操作系统目标仅覆盖监控系统所在主机，远程主机暂不支持（后续规划）。
