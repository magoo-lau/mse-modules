# 03 角色规划 —— 角色定义、授权矩阵与数据权限

> mse-monitor 的角色与授权设计。权限点 id / code 见 [02-权限规划](02-权限规划.md)，功能点含义见 [01-功能规划](01-功能规划.md)。
> **本工程未内置角色种子**（版本化脚本只落菜单与权限点，不含 `sys_role`）——下列角色均为**建议角色**，由实施/管理员在基座「角色管理」界面按需创建并勾选权限点。

## 一、角色模型说明

1. **双端世界，两套角色**：监控中心是双端子应用——平台端（tenant_id=0）与租户端各用各的角色体系，互不相通。平台侧角色在平台端「角色管理」维护，租户侧角色在租户「角色管理」维护。
2. **平台超管天然全量**：平台内置超管账号（platform）无需角色即拥有平台端全部监控能力；建议角色面向平台运维岗分工。
3. **租户超管不依赖角色**：租户 `super_admin` 天然拥有「套餐域内」全量权限码——但**前提是套餐勾选了监控菜单**（默认不勾选，见第六节）。
4. **监控数据无部门/个人维度**：监控目标与告警不按部门归属，数据权限只有「世界」维度（平台世界 / 本租户世界 / 离线本地世界），角色 `data_scope` 建议一律取 **1 全部**。
5. **角色是授权容器不是隔离手段**：租户能看到的数据边界由租户世界决定，角色只决定「能看哪些页面、能按哪些按钮」。

## 二、建议角色清单

### 2.1 平台端（在线形态运营主体）

| 角色（建议） | 定位 | 建议勾选权限点 |
| --- | --- | --- |
| 平台超管（内置） | 全部能力兜底 | 天然全量，无需勾选 |
| 平台运维管理员（建议自建） | 监控目标接入、指标查看、告警与通知配置的日常运营 | 4301-4312 全量 |
| 平台监控值班（建议自建，可选） | 只读值守 + 告警处理，不动目标与通知配置 | 4301、4302、4305、4306、4307、4308、4310 |

### 2.2 租户端（离线私有部署自管形态；在线形态默认不授权）

| 建议角色编码 | 名称 | data_scope | 定位 |
| --- | --- | --- | --- |
| `monitor_admin`（建议） | 监控管理员 | 1 全部 | 本地监控目标全生命周期管理、告警与通知配置、缓存删键，全模块管理 |
| `monitor_viewer`（建议） | 监控只读 | 1 全部 | 总览/目标/趋势/告警/缓存只读查看，用于汇报与值守 |
| `cache_operator`（建议，可选） | 缓存运维 | 1 全部 | 仅缓存监控浏览 + 删键（4310 + 4312），面向掌握 Redis 但不监控全局的运维岗 |

> 建议编码仅为实施约定（便于多环境口令一致），非种子强约束；基座「角色管理」创建时自定义编码即可。

设计要点：

- **删键单独成权**（4312）：删键对 Redis 实例立即生效且不可恢复，只授予明确需要的角色；无权限者界面自动隐藏按钮，呈纯只读视图。
- **通知设置查看/维护分离**（4308/4309）：值班岗可查看收件人配置核对链路，改动收口在管理员。
- **慢命令抓取是排查工具**：抓取期间常驻占用采集开销与 Redis slowlog 内存，只授予管理员，不给只读岗。

## 四、数据权限（双端世界 + 离线退化）

| 场景 | 规则 | 依据 |
| --- | --- | --- |
| 平台会话（在线） | 全部 mon_* 读写落**平台库**（tenant_id=0 行）：平台目标全家桶、平台告警与通知设置 | 平台会话经路由拦截器推平台库 |
| 租户会话（在线，若被授权） | 行级过滤**本租户库**：只见本租户自建的目标/记录/告警，平台目标不可见 | 租户插件行级隔离 |
| 后台调度线程（在线） | 无上下文默认**平台语义**（落平台库）；各租户库的启用目标按归属分库扫描采集 | 调度器 runAsPlatform 兜底 |
| 离线模式（offline=true） | **本地单一监控世界**：mon_* 全部直连本地缺省库（不路由平台库、不按会话租户过滤），平台/租户会话看到同一个本地世界，本机 OS 目标同落本地 | `runIgnore` 收敛 |
| data_scope | 监控数据无部门/个人维度，建议全部角色取 1（全部）——隔离靠世界，不靠部门 | 见第一节第 4 条 |
| 凭据安全 | 目标凭据（MySQL/Redis 密码）查询统一返回 `******`，编辑不回显原值；仅探测器直连使用 | 与角色无关的硬边界 |

## 五、种子落库情况

1. **菜单与权限点**：随 `V20261001_01_monitor__monitor_base.sql`（`-- mse-target: base`）落基座库，starter-bridge 推送 + 周期重推自愈；租户侧经「租户库车队重放」在各租户库获得菜单/权限点副本。
2. **角色**：**无种子**。实施路径——平台端角色在平台端「角色管理」新建并勾选 4301-4312；租户侧角色（若启用离线自管）由租户管理员在「角色管理」新建（建议编码见第二节）并勾选对应权限点。
3. **通知收件人种子**：`mon_setting` 默认行（站内信 → admin，Webhook 关闭）随 init/platform 脚本落业务库与平台库；此后界面维护，不再动种子。
4. **后续新增角色/授权调整**：直接界面操作即可（角色保存授权集合语义：传 null 保持不变、非 null 全量替换）；如需固化为种子，新增版本文件（`-- mse-target: master`，角色按 code 判重），不改已应用脚本。

## 六、套餐可见性说明（默认不勾选）

1. **出厂封存**：监控菜单（490-494）**不在任何默认套餐内**——在线形态下租户端即使有菜单副本也不可见、不可授权，监控由平台运营（这是在线形态「人为控制不授权给租户」的收口手段）。
2. **开通流程**：平台端「套餐管理」→ 编辑租户所用套餐 → 勾选「监控中心」分组（490-494 同树勾选）→ 保存；租户管理员重新登录后左侧出现「监控中心」，再按第二节建议角色授权到人。
3. **离线交付**：tenant-starter 离线交付导出对话框手动勾选基座菜单时，监控 490-494 同树勾选（与任务调度菜单同批处理的既有约定）。
4. **裁剪语义**：套餐勾选是租户可见的总开关——未勾选时，租户超管也无监控权限；勾选后，租户超管天然全量，普通员工按角色授权。
