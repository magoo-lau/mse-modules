# 02 权限规划 —— 子应用注册、页面菜单与权限点

> mse-monitor 的菜单与权限点设计。功能点含义见 [01-功能规划](01-功能规划.md)，角色授权见 [03-角色规划](03-角色规划.md)。
> **本工程已落地**：本文所有 id / 号段与版本化脚本 `monitor-service/src/main/resources/db/mysql/V20261001_01_monitor__monitor_base.sql` 逐条对应，并已登记 `alloc-tables.md`。

## 一、设计原则（基座 RBAC 模型）

1. **三张全局表，一条链路**：`sys_micro_app`（子应用注册）→ `sys_menu`（导航菜单）→ `sys_permission`（权限点）；授权链 `sys_user → sys_user_role → sys_role → sys_role_menu / sys_role_permission`。
2. **双端子应用**：本工程 side=3 / menu_scope=3（平台+租户双端共享同一套菜单与权限点）——平台端看平台自身监控（tenant_id=0 行），租户端看本租户监控（数据按会话租户路由/过滤）。后端六个控制器全部 `@SaCheckOr` 双登录类型校验（TENANT / PLATFORM 各检一次同码权限）。
3. **权限点必须挂靠页面菜单**：`sys_permission.menu_id` 指向本工程 type=3 页面菜单，参与角色授权分组与**租户套餐裁剪**；本工程无 `menu_id=NULL` 的通用权限。
4. **权限码格式**：`monitor:<模块>:<动作>`，动作小写动词，与仓库 `oa:form:list` 等风格一致；唯一键 `uk_code`。
5. **前端按钮控制**：删键、新增/编辑/删除/检测等按钮用 `v-permission` 按权限码显隐（如无删键权限者看到纯只读缓存视图）。
6. **落库方式**：随 jar 的幂等版本化脚本（头指令 `-- mse-target: base`），由 starter-bridge 就绪即推 mse-system 按分册账本应用——免手工执行；已应用脚本不再修改，变更一律新增版本文件。

## 五、编码规范

1. **前缀**：统一 `monitor:`；模块段 `dashboard / target / alert / notify / redis / cache`；动作段 `query / save / delete / probe / handle`。
2. **编辑即增改**：目标的新增与编辑共用 `monitor:target:save`（含启停、慢命令抓取开关），不再细分 insert/update。
3. **跨页复用从紧**：详情类数据（采样记录、慢命令抓取状态）跟随目标查询码；确需独立按钮粒度（删键）才单设权限码。
4. **新增权限点**：在 43xx 段顺延取号（4313 起），用后登记 `alloc-tables.md`；不得复用已释放的 4311。

## 六、套餐裁剪与登记纪律

1. **默认不勾选**：监控页面（490-494）**不在任何默认套餐内**——在线形态监控由平台运营，租户端靠「套餐管理」不勾选收口；租户确需使用（离线私有部署自管形态）由平台端在「套餐管理」勾选「监控中心」分组后保存。
2. **离线交付导出**：tenant-starter 离线交付导出对话框手动勾选基座菜单时，监控 490-494 需**同树勾选**（与任务调度 195 同批处理的既有约定）。
3. **网关白名单**：`/monitor` 路由无白名单（监控需登录）；被监控服务的 actuator 端点白名单由基座统一放行，与本工程无关。
4. **alloc-tables.md 登记**（已执行）：后端端口 8097、前端 dev 4010、micro_app id=10、菜单段 490-499（现用 490-494）、权限段 43xx（基点 4300，现用 4301-4312）、网关前缀 `/monitor`。
5. **脚本纪律**：base 脚本全段 `NOT EXISTS` 幂等（子应用按 name 判重、菜单/权限点按 id 判重）；历史挂靠修正用条件 UPDATE 幂等补挂；已应用脚本不再修改。
