# 05 配置手册（零基础版）—— 从零把监控中心跑起来

> **这本手册是给谁的**：没接触过本系统、甚至没怎么接触过服务器软件的同事——实施工程师、现场 IT、接手部署的新人。你不需要看懂代码，照着做、每步核对「✅ 成功的标志」即可。
> 配套文档：跑起来之后怎么用，看 [04-操作说明书](04-操作说明书/README.md)；功能全景看 [01-功能规划](01-功能规划.md)。

## 一、先认识几个名词（2 分钟）

| 名词 | 是什么 | 打个比方 |
| --- | --- | --- |
| **Docker** | 容器软件，把 MySQL 等软件"打包"成一键安装 | 免安装的"绿色软件"运行器 |
| **MySQL / Redis** | 数据库 / 缓存，监控中心的采样与配置存这里 | 账本 + 门卫登记本 |
| **JDK 21 / Maven** | Java 运行环境 / 打包工具 | 播放器 + 印刷厂 |
| **Node.js** | 前端页面的构建运行环境 | 网页的发动机 |
| **Nacos** | 微服务模式下的"配置中心 + 通讯录" | 公司前台（单体模式用不到） |
| **单体 / 微服务** | 两种安装形态：单体=一个程序全包；微服务=拆成多个程序 | 便利店 vs 购物中心 |
| **actuator** | Spring 服务自带的"体检端点"，监控系统靠读它采数据 | 服务自带的体检报告窗口 |
| **拉模式 / 零侵入** | 监控中心主动去读各服务的体检端点，服务不用改一行代码 | 上门抄表，不用户装表 |

## 二、你需要准备什么

| 项 | 要求 | 说明 |
| --- | --- | --- |
| 服务器/电脑 | 4 核 8G 起步，硬盘 ≥40G | Windows / Linux 均可 |
| 软件 | Docker（推荐）或：JDK 21 + MySQL 8 + Redis + Maven 3.9+ + Node.js 20+ | 路线 A 只需 Docker |
| 软件包 | 本仓库源码（git clone 或压缩包） | jar 也可以直接找开发要成品 |

## 三、路线 A：容器一键部署（推荐，单体形态，约 30 分钟）

### 第 1 步：安装 Docker

Windows 装 Docker Desktop 并启动；Linux 装 docker + docker compose 插件。
✅ 成功标志：`docker --version` 能输出版本号。

### 第 2 步：启动数据库和缓存

命令行进入仓库的 `mse-framework/docker` 目录执行：

```bash
docker compose up -d mysql redis
```

✅ 成功标志：`docker ps` 里 `mse-mysql`、`mse-redis` 状态 Up（首次要等 MySQL 初始化约 1 分钟）。

### 第 3 步：启动应用（单体，已含监控中心）

单体的聚合工程 `mse-sample/mse-monolith` 已引入监控业务模块，无需额外配置：

```bash
docker compose --profile apps up -d --build mse-monolith
```

✅ 成功标志：浏览器打开 `http://localhost:8080` 有应答；`docker logs -f mse-monolith` 出现 `Started ... in xx seconds`。

监控的 4 张业务表、菜单与权限点、预置目标**都会在启动时自动写入数据库**，无需执行任何 SQL。预置目标里 MySQL 与 Redis 默认启用，其余（网关/基座服务/Nacos/ES/RocketMQ/JVM/慢SQL）默认停用——按你的部署实况在界面逐批启用。

### 第 4 步：启动网页前端

```bash
cd mse-framework/mse-ui      # 基座门户（含监控中心入口）
npm install
npm run dev
```

✅ 成功标志：`http://localhost:3000` 看到登录页。

### 第 5 步：登录并验收监控中心

1. 用**平台超管**登录（账号 `platform`，密码 `admin123`；正式环境务必改密码）。
2. 左侧出现「**监控中心**」→ 监控总览：应看到预置目标卡片与本机 OS 目标。
3. 到「监控目标」逐批启用实际存在的目标，点行内「**检测**」验证变绿。
4. 「告警中心 → 通知设置」配好站内信/Webhook 并「发送测试」。

> 租户侧是否开放监控：默认**不开放**（见第七节），在线共享部署保持默认即可。

## 四、被监控服务：零侵入说明与令牌对齐（关键）

### 4.1 零侵入能采到什么

被监控的 Java 服务**不需要任何代码改动**——监控中心只读它的三个体检端点：`/actuator/health`（存活）、`/actuator/metrics/*`（JVM 指标）、`/actuator/slowsql`（慢SQL）。本仓库各服务的 Nacos 配置留档已统一暴露这四个端点（health,info,metrics,slowsql），开箱即采；自建工程照此对齐即可。

### 4.2 actuator 端点鉴权令牌对齐（开了鉴权的服务必做）

若被监控服务开启了端点鉴权（参数 `mse.actuator.auth.token`），监控侧必须配**同一个值**，否则拉取一律被拒、目标显示异常：

- 两侧都读同一个环境变量 **`MSE_ACTUATOR_TOKEN`**——给被监控服务和监控服务（单体即同一个进程）注入同一个变量值即可自动对齐，无需分别改配置。
- 令牌为空（默认）= 目标未开启鉴权，匿名拉取，兼容存量部署。

### 4.3 慢SQL 监控的显式开关（唯一需要"动配置"的项）

慢SQL 默认关闭、零开销；要对某个服务做慢SQL 监控，在该服务的配置里显式开启：

```yaml
mse:
  mybatis:
    slow-sql:
      enabled: true        # 默认 false
      threshold-ms: 3000   # 超过 3 秒记为慢 SQL
      capacity: 32         # 内存保留条数
```

同时确认该服务暴露 slowsql 端点（见 4.1）。开关没开时监控目标显示正常且「慢SQL采集=否」，**不会误报**。网关（WebFlux 无数据库）不支持慢SQL 目标。JVM 目标只要求 exposure 含 metrics，无需其他开关。

## 五、在线 / 离线模式选择与配置

| 模式 | 什么时候选 | 行为 |
| --- | --- | --- |
| **在线**（默认，`mse.monitor.offline: false`） | 共享 SaaS 部署：监控由平台统一运营 | 平台端看平台目标全家桶（采集按目标归属分库）；租户端菜单存在但默认不授权 |
| **离线**（`mse.monitor.offline: true`） | 租户**离线私有部署**：环境与平台断开，监控自管 | 监控整体退化为「本地单一监控世界」——全部数据直连本地库、不再区分平台/租户，租户授权后在租户端维护本地监控 |

配置方式（单体/微服务通用）：在应用的 yaml 或 Nacos `mse-monitor.yaml` 里设 `mse.monitor.offline: true`。**在线共享部署请保持 false**。

## 六、常用配置项速查

> 单体：`mse-sample/mse-monolith/src/main/resources/application.yaml`（或环境变量覆盖）；微服务：Nacos Data ID `mse-monitor.yaml`（留档在 `mse-modules/mse-monitor/docker/nacos/config/`）。

| 想改什么 | 参数（mse.monitor.*） | 默认值 | 说明 |
| --- | --- | --- | --- |
| 离线模式 | `offline` | false | 见第五节 |
| 调度轮询间隔 | `scan-interval-ms` | 10000 | 毫秒 |
| 新目标默认采集间隔 | `default-collect-interval` | 30 | 秒 |
| 采样保留天数 | `retention-days` | 7 | 每日 04:30 自动清理 |
| 采集线程池并行度 | `executor-parallelism` | 4 | — |
| 单次探测超时 | `probe.timeout-ms` | 5000 | 毫秒 |
| 缓存键浏览扫描上限 | `redis.scan-limit` | 5000 | 超出提示缩小匹配模式 |
| 慢命令抓取单轮条数上限 | `redis.slowlog-max-entries` | 10 | 只读命令 |
| 采样清理时刻 | `cleanup-cron` | `0 30 4 * * ?` | cron |
| actuator 令牌 | `actuator-token` | 空 | 经 `MSE_ACTUATOR_TOKEN` 环境变量对齐（见第四节） |

> 告警收件人/Webhook **不在配置文件**——界面「告警中心 → 通知设置」维护，存数据库。

## 七、租户开通与角色初始化

1. **默认封存**：监控菜单不在任何默认套餐内——在线共享部署到此为止（监控由平台运营）。
2. **离线私有部署要给租户开通**：平台账号 →「**套餐管理**」→ 编辑租户所用套餐 → 勾选「**监控中心**」分组（总览/目标/告警/缓存四个页面同树勾选）→ 保存。tenant-starter 离线交付导出时同样记得勾选监控菜单。
3. **角色**：本系统**不预置角色**——租户管理员在「角色管理」按 [03-角色规划](03-角色规划.md) 建议自建（如监控管理员=全部权限点，监控只读=仅查询类权限点，删键权限单独授予），再在「用户管理」把角色授予运维同事；租户超管在套餐勾选后天然全量。
4. ✅ 成功标志：租户管理员重新登录后左侧出现「监控中心」，能新建目标并收到测试通知。

## 八、微服务形态（进阶）

1. 前置：仓库根 `mvn install -DskipTests`（框架）→ `mvn install -DskipTests -f mse-modules/mse-monitor/pom.xml`。
2. 启动 Nacos（compose 已含，控制台 `http://localhost:18080`），导入服务专属配置：
   ```bash
   CONFIG_DIR=<仓库根>/mse-modules/mse-monitor/docker/nacos/config sh mse-framework/docker/nacos/init-configs.sh
   ```
3. 启动服务：`java -jar monitor-boot/target/monitor-boot-1.0.0-SNAPSHOT.jar`（端口 8097，注册 Nacos 应用名 `mse-monitor`）。
4. 网关路由 `/monitor/** → lb://mse-monitor` 已在 `mse-gateway.yaml` 留档（运行期热更新或重新导入）。
5. 前端：开发 `cd monitor-ui && npm install && npm run dev`（端口 4010，代理指向 8080 单体/48080 网关）；正式 `npm run build` 部署到 `/sub-apps/monitor/`（子应用地址已随脚本自动登记）。
6. **单实例部署**：调度在内存里跑，多实例会重复采集（数据无害但浪费）——生产请单实例或外置调度。
7. 信创数据库：启动加 `--spring.profiles.active=dm` 或 `kingbase`（数据源由共享配置提供）。

## 九、常见问题排查（按现象查）

| 现象 | 先检查什么 |
| --- | --- |
| 启动失败报数据库连接错误 | MySQL 没起/地址密码错——`docker ps` 看容器，改环境变量后重启 |
| 登录后左侧没有「监控中心」 | 平台端：角色未授权；租户端：套餐未勾选（第七节）或角色未授权 |
| 目标一直「未知」或「异常」 | ① 地址/端口填错（容器里 localhost 不是宿主机）② 目标没起 ③ 目标开了 actuator 鉴权而 `MSE_ACTUATOR_TOKEN` 未对齐（第四节）——点「检测」逐项排除 |
| 监控页面打开但接口 401/403 | 未登录或角色缺对应权限点；微服务形态检查网关路由与 Nacos 注册 |
| 接口 404（微服务） | monitor-boot 没注册到 Nacos，或网关缺 `/monitor/**` 路由 |
| JVM 目标启用后没数据 | 目标服务 exposure 未含 `metrics`（第四节）；重启后首轮无 GC 增量属正常 |
| 慢SQL 目标显示「慢SQL采集=否」 | 目标服务未开启 `mse.mybatis.slow-sql.enabled`（第四节）；开启后自动变「是」 |
| 告警不发通知 | 「通知设置」未启用/收件人空/机器人地址错；点「发送测试」看返回；离线环境查到群机器人的外网连通性 |
| 告警重复轰炸 | 「重复通知间隔」被配成了大于 0 的分钟数；不需要周期重发就归零 |
| 缓存监控打不开/无实例 | 先到「监控目标」建好 redis 类型目标并启用（凭据正确），缓存页才可选实例 |
| 键树提示已达扫描上限 | 匹配模式太宽（`*`），改前缀匹配（`mse:*`） |
| 新建租户独立库时日志刷 Unknown database / 表不存在（DEBUG） | 初始化窗口期的正常中间态，建库完成后自动纳入，无需处理 |
| 启动日志报"脚本执行失败"并退出 | 数据库迁移是启动强校验：按日志提示修复后重启，不要跳过 |
| 界面/数据库中文乱码 | 建库与连接必须 utf8mb4（脚本已内置；自建库时确认字符集） |

## 十、上线前检查清单

- [ ] 修改所有默认密码（platform/admin123、数据库 root、Redis 密码、MySQL 监控目标改只读账号）
- [ ] `MSE_ACTUATOR_TOKEN` 已设置且被监控服务与监控服务一致（如启用端点鉴权）
- [ ] 慢SQL 监控只在确有需要的服务上开启（有固定采集开销）
- [ ] 在线/离线模式确认：共享部署 `offline: false`；私有部署按第五节切换
- [ ] 预置目标按部署实况启停（不存在的目标保持停用），逐个「检测」验证
- [ ] 告警通知通道已配并「发送测试」通过；重复通知间隔按值守策略设定
- [ ] 微服务形态：monitor-boot 单实例部署；Nacos 开鉴权；网关 `/monitor` 无白名单（需登录）
- [ ] 租户侧：在线共享部署确认套餐**未**勾选监控；离线自管部署已完成套餐勾选与角色初始化
- [ ] 记录本次部署的版本号与日期，便于后续升级追查
